# AGENTS.md — account-research 项目契约

> 本文件是 **account-research 产品项目**的操作契约。仓库级铁律见仓库根 [`AGENTS.md`](../AGENTS.md)（唯一真相源，冲突时以仓库契约为准）；本文件只写**项目特有纪律**，不重复仓库级四条铁律。

## 1. 这个项目是什么

账号调研产品：人保存网页 HTML（约 2 分钟/账号）→ AI 全自动处理（解析 → 四层拆解 → 封闭判决 → 双镜）→ 报告交付。方法论在 `skill/`，工程在 `src/`，副端在 `web/`。

## 2. 项目特有纪律（违反即交付作废）

1. **采集端只能是人，处理端可以全自动，分界线 = 数据进表**。脚本只允许处理用户已贴入 / 已保存到 `account/` 的数据；**禁止访问任何平台域名、模拟点击、接管浏览器会话、批量存档**。「慢速拟人化脚本」同样是禁止项——速率不改变 ToS 性质（playbook §4）。
2. **双输出同源**：markdown 报告与 HTML 可视化的数字必须同源，HTML 里禁止出现报告中没有的数字。
3. **台账只追加**：`skill/账号库台账.md` 不改写历史行；状态变更追加新行并备注「替代 YYYY-MM-DD 行」。
4. **⬜ 不得被填充**：拿不到的数据写 ⬜ 未取证并计入统计；禁止估算值、行业经验值、第三方横评填充。
5. **相关 ≠ 因果**：对标拆解模式不下病因判决；病因诊断是 v0.3 诊断模式的事。
6. **图片不得进模型上下文**（R7，2026-10-29 起）：图文笔记的内容走「本地图 → 本地 OCR → `account/notes-text/<note_id>.images.txt`」这条路，**任何情况下不把图片字节送给模型**。账：一张 1440×2400 的笔记图约 4.3k tokens，一篇 24 图 ≈ 10 万，不可压缩、重试再花一次——这是本项目唯一一次真的把请求撑爆成 `Input exceeds the context limit`。人要看图就双击原图；OCR 文本上万字时也不整篇读，按需读某几张图的段落。见 [`docs/图片内容通道.md`](docs/图片内容通道.md)。

## 3. 代码纪律（src/ 与 web/ 共用）

- ✅ 允许：解析已存档 HTML、合并表格、算指标、台账更新、异动告警、报告渲染
- ❌ 禁止：访问平台域名、模拟点击、接管浏览器会话、批量存档、验证码绕过
- 解析器验收标准 = **对 `account/` 真实存档跑通，产出与报告 1.2 节数据一致**；没有真实存档不写解析器（不纸面造）
- 测试代码入库，fixtures（含采集者会话数据的 HTML）绝不入库——`account/` 与 `data/` 均在 gitignore

## 4. 提交约定

沿用仓库约定：`<type>: <中文简述>`，type ∈ feat/fix/docs/chore/skill。每次实质修改 Skill 或解析器行为，往仓库 [`docs/lessons-learned.md`](../docs/lessons-learned.md) 追加一条实证（一本账）。

## 5. 版本纪律

- `skill/` 方法论按语义版本（v0.2.0 → …），版本史记在 SKILL.md「构建实证」节
- `src/` 工程按 semver，与 skill 版本解耦——方法论可以不改而工程迭代
