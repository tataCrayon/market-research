# src/parser —— P3 解析器（产品化第一个组件）

> overall-workflow.md 判定：「P3 解析器（HTML → 结构化表）是整条管线上唯一**纯工程、零合规风险、输入输出都明确**的环节——v0.2 真实 case 的存档格式就是它的需求文档。」

## 职责边界

- **输入**：`account/` 下用户保存的小红书主页 / 详情页 HTML 存档（本地文件）
- **输出**：结构化数据表（发布时间 / 标题 / 赞 / 藏 / 评 / 分享 / 链接），带口径标注（公开页）+ 来源文件名 + 查证日期
- **禁线**（AGENTS.md §3）：只读本地文件；零平台请求；不模拟任何浏览器行为

## 已知的真实存档特性（v0.2 case 实测，开发前必读）

1. 列表页 HTML 内嵌 `__INITIAL_STATE__`，32 篇五字段（标题 / 发布时间 / 赞 / 形式 / 置顶）完整可解析
2. `__INITIAL_STATE__` 是 JS 字面量非严格 JSON——`undefined` 值需清洗为 `null` 才能 `json.loads`
3. 存档混入**采集者本人会话数据**（登录态 / 浏览历史）——必须按 target userId/nickname 做归属校验，不匹配即丢弃（v0.2 曾把 viewer 简介误当目标简介）
4. 列表页 SSR 不含单篇收藏 / 评论 / 分享——仅详情页存档提供，解析器需分别处理两种页面类型
