# web/ —— 副端 PC Web 工具（占位，未启动）

> ⚠️ **放大方向待复核（2026-10-22）**：case-001 的过程账显示，采集摩擦占全程约 **80%**（7 轮动作中 3 轮失败），而 Web 工具**消除不了采集摩擦**——用户仍需先存文件、仍需自己判断存得对不对。浏览器插件形态（本地解析当前页、用户主动触发、不发额外请求）可以消除这一层且不触碰零爬虫红线。
> 本目录的定位与启动条件**不变**，但「插件 vs Web 谁先」的顺序待决策。证据见 [`../docs/case-001-卡兹克-执行过程复盘.md`](../docs/case-001-卡兹克-执行过程复盘.md) §4。

## 定位

产品立项调研（[`../../docs/product-research-account-research-2026-10-21.md`](../../docs/product-research-account-research-2026-10-21.md)）判决的**放大路径**：Skill 版验证「有人愿意为纪律付费」之后才建站。

## 技术架构（已定盘，来自立项调研 §4）

- **纯客户端解析**：HTML 在用户浏览器本地解析（File API + 解析逻辑），数据不出用户浏览器
- 静态托管；大模型 API（服务端代理或用户自带 key）
- 无数据库（台账即文件）
- 合规与隐私双赢：连「用户数据」都不经过我们服务器

## 启动触发条件（缺一不可）

1. Skill 版 ≥50 次自然安装
2. Skill 版 ≥3 次付费安装

> 触发前不写一行 web 代码——与「探针通过前不写解析器」同构：先验证前提，再投入工程。
> 启动前置办：ICP 备案（3-22 工作日）+ 公安备案 + 个体户 / 公司主体（微信支付接入需要），立项调研 §4 延误险合计约 4-8 周日历天。

## 延后项（明文不做）

微信小程序 / iOS / Android——采集动作（PC 浏览器保存 HTML）在移动端不成立；iOS 虚拟支付抽成对工具类是重税；小程序需重新备案 + 类目审核。硬做要么违反合规设计，要么重做一套完全不同的交互（= 第二个产品）。
