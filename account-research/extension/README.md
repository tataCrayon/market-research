# extension/ —— 详情页采集扩展 v7.2（Chrome / Edge，Manifest V3）

> **一句话**：点一下图标 → 面板打开 → 按「采集」→ **当前窗口里所有笔记页各存一份
> 单文件 MHTML（含图），直接入库**。不用开终端、不用下载目录、不用管文件。
>
> **它就是 Ctrl+S 的批量替身 + 自动入库**：图片、CSS、字体一起打包，不丢东西。

## ⚠️ 采集时**别关那个面板**

采集跑在面板里（不是后台），因为 `pageCapture` 返回的是**文件-backed 句柄**，
只有渲染进程（面板）能可靠读出它的字节。面板一关，这次采集就断了。
界面上会写着「别关这个面板」，进度也在那儿。

## 安装（一次性，两步）

### 第 1 步：注册本地宿主

```powershell
cd D:\Projects\MyProjects\market-research\account-research
python ar.py host --register
```

**注册一次就够**，之后不用再碰。它做两件事：写一个注册表项（HKCU，不需要管理员权限）、
生成一个 `.bat` 与一份清单 JSON。

想确认装好了：

```powershell
python ar.py host --doctor
```

全绿就可以用了。

### 第 2 步：在 Chrome 里加载扩展

1. 打开 `chrome://extensions`
2. 右上角打开 **开发者模式**
3. **加载已解压的扩展程序** → 选中 `account-research/extension`

> ⚠️ **改完代码必须点卡片上的 ⟳ 重新加载。** 开发者模式加载的扩展没有自动更新，
> 不重载跑的还是旧代码——这正是「点了没反应」的常见原因之一。

## 用

1. 中键连开 3–5 篇笔记（**别一次开 20 个**，见下面的上限说明）
2. 图片栏**从第一张滑到最后一张**（不滑的话那些图没下载过，存档里只剩链接）
3. 点图标 → 面板 → 「采集当前窗口的笔记」
4. 面板上会出现「已入库 N 篇」，下方是入库日志

采集完**不需要做任何事**——数据已经在库里了。`ar status` 能看到。

## 面板怎么看

```
今日已采   3        库里篇数  68       有正文  13
数据目录 … · 今日详情额度 3/30

采集当前窗口的笔记
──────────────────────────
已入库 1 篇，失败 1 篇（20480 KB）
✗ 从主页点开的弹层（不是整页打开）
2 篇有图没加载出来：保存前把图片栏从第一张滑到最后一张
```

- **今日已采**：今天进库的篇数（按 note_id 去重）
- **库里篇数 / 有正文**：累积值
- 失败原因会写明**在哪一层**（识别页面 / 存档页面 / 转换存档 / 入库）
- 红字是失败，黄字是「采到了但不完整」，灰字是宿主返回的原始日志

面板**只显示数字，不评价**。它不会说「你今天采得不够」——那不属于工具该说的话。

## 边界（这次改动没有放宽，反而更窄）

**不发任何网络请求、不导航、不开新标签。** 它只读你已经加载好的页面。

| 做 | 不做 |
|---|---|
| 读**已渲染 DOM** 判页面类型、统计图加载情况 | ❌ 发任何网络请求 |
| 用 `pageCapture` 把**内存里已有的字节**序列化 | ❌ 导航、开新标签、reload |
| 把字节交给**本地宿主** | ❌ 跳过休眠标签（会触发重新加载） |
| 点图标才动，一次最多 10 个标签 | ❌ 轮询、定时、页面加载时自动跑 |

### 为什么「扩展能调本地程序」没有让风险变大

`nativeMessaging` 听起来比 v6 的 `offscreen` 危险得多，但要让这一点变成真实风险，
还得有一个「会执行任意命令的宿主」。所以真正的约束在宿主：

1. 宿主**只做一件事**——把收到的字节交给 `ar ingest` 的同一条代码路径。
   没有通用执行入口、没有 shell、没有文件浏览；
2. 宿主里**没有任何网络调用**（连 `urllib` 都不 import）；
3. 消息里带 note_id 但**不带 URL**：宿主不需要知道页面在哪，也就不可能自己去取。

权限清单是 `scripting` / `pageCapture` / `nativeMessaging`——**净增 0**（删了 `offscreen`）。
**不留用不到的权限**：留着一个，等于为一个已经不存在的能力继续背书。

## v7.2 修了什么（2026-11-16，起因：第一次真机点击）

```
转换存档✗ The requested file could not be read, typically due to permission
problems that occur after a reference to a file has been acquired
```

`DOMException: NotReadableError`，来自 `blob.arrayBuffer()`。

**它不是说 blob 是空的**——`size` 读得出非零，只是**取不到背后的数据**。
`pageCapture.saveAsMHTML` 返回的不是内存里的一串字节，而是一个**句柄**
（Chrome 把 MHTML 写进了 profile 的 blob storage）。
这种跨进程句柄在 **MV3 的 service worker** 里读不稳。

修法不是「换个读法」，是**换个地方读**：采集搬到弹出面板（真渲染进程），
那里有 `FileReader`，对文件-backed blob 走的是已知可用的读路径。

拆成三个文件：

| 文件 | 跑在哪 | 干什么 |
|---|---|---|
| `capture.js` | 面板（渲染进程） | 找笔记页、存档、读字节、分块上传、问 status |
| `popup.js` | 面板 | 只负责显示与触发 |
| `background.js` | service worker | 只负责画 badge（面板关掉后那点记忆） |

**代价是诚实的**：面板一关，采集就断。这是有意换的——
一个会失败的重试成本，比一个「以为在跑其实没跑」的静默失败便宜得多。

## v7 删掉了什么（以及为什么每一样都可以删）

| 删掉 | 它原来为什么存在 | 现在为什么不需要 |
|---|---|---|
| `offscreen.js` / `offscreen.html` | service worker 里没有 `URL.createObjectURL`，要借一个文档生成 blob URL | 不写文件了，就没有 blob URL |
| `offscreen` 权限 | 同上 | 同上 |
| 下载目录 / 文件名 `ar-page-*.mhtml` | 靠「文件落到磁盘」交接给 Python | 字节直接过管道 |
| `ar watch` 必须开着 | 靠轮询目录发现新文件 | 没有文件了 |

**v6 的三个真实事故（Blob 过不了消息通道、blob URL 跨上下文失效、
offscreen 没有 `chrome.downloads`）全部来自「要让浏览器写文件」这一个需求。**
v7 不写文件，那三个坑连同它们的修法一起消失。这不是运气，是**换掉一个错误的需求**的结果。

## 出问题时

| 现象 | 原因 | 怎么办 |
|---|---|---|
| badge 显示 `!`，提示「本地宿主没注册」 | 第 1 步没做，或换了扩展 ID | `python ar.py host --register` |
| 同上但提示「宿主清单里没允许这个扩展 ID」 | 扩展 ID 变过（换了 `key`） | 重新 `--register` |
| 面板全空、写着「本地宿主没连上」 | 宿主 .bat 起不来 | `python ar.py host --doctor` |
| 「转换存档✗ …could not be read」 | 采集跑在了 background 里（v7.1 的 bug） | 确认 `manifest.json` 的 `default_popup` 是 `popup.html`，重新加载扩展 |
| 「失败 1 篇：从主页点开的弹层」 | 那篇是弹层不是整页 | 中键在新标签页打开那篇 |
| 「N 篇有图没加载出来」 | 懒加载的图没下载过 | 采集前把图片栏滑到底 |
| 「N 个标签未加载/已休眠」 | Chrome 把不用的标签丢弃了 | 点一下那个标签让它重新加载 |
| 什么都正常但库里没数据 | 数据目录不同 | 面板上会显示宿主用的 `数据目录` |

`python ar.py host --doctor` 会逐项报告：注册表、清单、启动脚本、`ar_host.py`、
扩展 manifest、以及**真的启一次宿主握个手**。检查不出问题才叫「能用了」。

## 拿不到什么（必须说清）

- **`__INITIAL_STATE__` 里的分享数与精确发布时刻**：`pageCapture` 只序列化渲染后的 DOM，
  把脚本剥掉了，所以 state 连带消失。这两项会写 ⬜（`分享 ⬜`）。
- **懒加载没滚到的图 → 拿不到图**：没下载过的图不在内存里，打包不到。
  这几张在 `_files/` 里没有字节，`ar images` 会报「本地 3 < 声明 16」。
  **这是数据事实，不是解析 bug。** 所以要存全图，按 Ctrl+S 之前得先把图片栏滑到底。
- **视频**：MHTML 里只有封面，视频本体不在。
- **评论**：`pageCapture` 存下来的是首屏已渲染的评论，不是全部（展开加载的那些要人手动点）。

## 为什么上限是 10 个标签

不是技术限制，是**行为限制**：一次开 10 个标签页本身就会形成请求突发，
比人逐篇点更不像正常用户。建议一次开 3–5 篇，读完再点一次保存。
