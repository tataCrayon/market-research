# extension/ —— 主页 + 详情页采集扩展 v8.0（Chrome / Edge，Manifest V3）

> **一句话**：点一下图标 → 面板打开 → 按「采集」→ **当前窗口里所有主页与笔记页各存一份
> 单文件 MHTML（含图），直接入库**。不用开终端、不用下载目录、不用管文件。
>
> **它就是 Ctrl+S 的批量替身 + 自动入库**：图片、CSS、字体一起打包，不丢东西；
> 主页还会把 `__INITIAL_STATE__` 一起带回来（见下面的 v8 一节）。

## ⚠️ 采集时**别关那个面板**

采集跑在面板里（不是后台），因为 `pageCapture` 返回的是**文件-backed 句柄**，
只有渲染进程（面板）能可靠读出它的字节。面板一关，这次采集就断了。
界面上会写着「别关这个面板」，进度也在那儿。

## 安装（一次性，两步）

### 第 1 步：注册本地宿主

```powershell
cd D:\Projects\MyProjects\market-research\account-research
python ar.py host --register
```

**注册一次就够**，之后不用再碰。它做两件事：写一个注册表项（HKCU，不需要管理员权限）、
生成一个 `.bat` 与一份清单 JSON。

想确认装好了：

```powershell
python ar.py host --doctor
```

全绿就可以用了。

### 第 2 步：在 Chrome 里加载扩展

1. 打开 `chrome://extensions`
2. 右上角打开 **开发者模式**
3. **加载已解压的扩展程序** → 选中 `account-research/extension`

> ⚠️ **改完代码必须点卡片上的 ⟳ 重新加载。** 开发者模式加载的扩展没有自动更新，
> 不重载跑的还是旧代码——这正是「点了没反应」的常见原因之一。

## 用

1. **先开主页，再开笔记**：主页是账号的入口（粉丝/简介/笔记列表全从它来）。
   中键连开 3–5 页（**别一次开 20 个**，见下面的上限说明）
2. 笔记页的图片栏**从第一张滑到最后一张**（不滑的话那些图没下载过，存档里只剩链接）
3. 点图标 → 面板 → 「采集当前窗口的主页 / 笔记」
4. 面板上会出现「已入库 N 篇」，下方是入库日志

采集完**不需要做任何事**——数据已经在库里了。`ar status` 能看到。

**主页排在最前面处理**：这样详情页入库时作者账号已经在了，不会先建占位号再被替换。

## 面板怎么看

```
今日已采   3        库里篇数  68       有正文  13
数据目录 … · 今日详情额度 3/30

采集当前窗口的主页 / 笔记
──────────────────────────
已入库 2 篇，失败 1 篇（20480 KB）
其中主页 1 个（粉丝/简介靠它）
✗ 从主页点开的弹层（不是整页打开）
2 篇有图没加载出来：保存前把图片栏从第一张滑到最后一张
```

- **今日已采**：今天进库的篇数（按 note_id 去重）
- **库里篇数 / 有正文**：累积值
- 失败原因会写明**在哪一层**（识别页面 / 存档页面 / 转换存档 / 入库）
- 红字是失败，黄字是「采到了但不完整」，灰字是宿主返回的原始日志

面板**只显示数字，不评价**。它不会说「你今天采得不够」——那不属于工具该说的话。

## 边界（这次改动没有放宽，反而更窄）

**不发任何网络请求、不导航、不开新标签。** 它只读你已经加载好的页面。

| 做 | 不做 |
|---|---|
| 读**已渲染 DOM** 判页面类型、统计图加载情况 | ❌ 发任何网络请求 |
| 用 `pageCapture` 把**内存里已有的字节**序列化 | ❌ 导航、开新标签、reload |
| 把字节交给**本地宿主** | ❌ 跳过休眠标签（会触发重新加载） |
| 点图标才动，一次最多 10 个标签 | ❌ 轮询、定时、页面加载时自动跑 |

### 为什么「扩展能调本地程序」没有让风险变大

`nativeMessaging` 听起来比 v6 的 `offscreen` 危险得多，但要让这一点变成真实风险，
还得有一个「会执行任意命令的宿主」。所以真正的约束在宿主：

1. 宿主**只做一件事**——把收到的字节交给 `ar ingest` 的同一条代码路径。
   没有通用执行入口、没有 shell、没有文件浏览；
2. 宿主里**没有任何网络调用**（连 `urllib` 都不 import）；
3. 消息里带 note_id 但**不带 URL**：宿主不需要知道页面在哪，也就不可能自己去取。

权限清单是 `scripting` / `pageCapture` / `nativeMessaging`——**净增 0**（删了 `offscreen`）。
**不留用不到的权限**：留着一个，等于为一个已经不存在的能力继续背书。

## v8 修了什么（2026-11-18，起因：真机点下去得到「宿主没回结果」）

用户截图里的原话是 `已入库 0 篇，失败 1 篇` / `▼ 原因：入库✗ 宿主没回结果`。
复现之后发现是**三件事叠在一起**，而且每一件单独看都像是在正常工作：

| 层 | 真实发生了什么 | 屏幕上显示 |
|---|---|---|
| 归属校验 | 那篇笔记的作者不在 `accounts` 里 → 被当「外来作者」拒收 | 无 |
| `host.py` | `ingest` 非 0 退出，但响应里**没有 `error` 字段** | 扩展只能填一句兜底 |
| 扩展 | `reply.error` 为空 → 显示「宿主没回结果」 | 那句谎 |

而 `accounts` 里没有这个作者，是因为**扩展采不了主页**——`pageCapture` 会剥掉
`<script>`，主页的数据全在 `__INITIAL_STATE__` 里，于是必然抛「找不到 state」。
于是闭环成了死锁：**详情页要作者 → 作者要从主页来 → 主页采不了**。

三处一起改（少任何一处这条链仍然断）：

1. **归属校验默认收**。`accounts` 是目标清单，不是准入白名单；
   归属的真凭据是详情页里的作者链接。外来作者建**占位账号**（粉丝/简介 ⬜，
   备注「缺主页存档」），补一次主页就被整行替换。想回到旧行为用 `--no-new-authors`。
2. **失败必须带原因**。`host.ingest_payload` 从 `ar ingest` 的输出里挑出最后一条
   `❌ / ⏭ / ⚠️` 作为 `error` 回传。兜底那句从「宿主没回结果」改成
   「宿主回了 ok=false 但没给原因」——它确实回了。
3. **state 隧道**。`probePage` 把 `__INITIAL_STATE__` 的 `user` / `note` / `feed` /
   `search` 子树摘出来（实测主页 `user` 约 48 KB），随 `begin` 一起上传；
   宿主写成 `<stem>.state.json` 旁车；`initialstate.open_archive` 按
   **HTML 内 state → 旁车 → 无 state（仅详情页）** 三档降级，并记下 `state_source`。

协议因此升到 **v2**：v1 宿主会**忽略** `state` 字段，扩展却以为送达了，
失败点离原因很远。升版本让旧宿主直接说「版本不匹配」。

**顺带修掉一个更隐蔽的**：`_expand_mhtml` 拆包失败时文件从候选里消失，
而 `ingest` 仍然返回 0 —— 宿主于是回「成功」，面板显示「已入库 0 篇，失败 0 篇」。
**什么都没做却报成功**，比报错糟得多。现在拆包失败会计数并返回 1。

## v8.1 修了什么（2026-11-19，起因：主页明明加载好了却说没渲染）

```
已入库 0 篇，失败 1 篇
▼ 原因：主页还没渲染出账号信息（等它加载完，或往下滚一屏再试）
```

而截图里的页面**已经是完整的主页**：头像、昵称、小红书号、粉丝 1016、32 张卡片全都在。

两个错误叠在一起，都是「把必要条件当成了充分条件」：

### ① 判据取错了地方（扩展）

v8.0 用 `__INITIAL_STATE__.user.userPageData.basicInfo.nickname` 判断「主页渲染好了没」。
**但小红书是 CSR**：首屏的 state 里 `userPageData` 是**空的**，账号头部由挂载后的
接口请求填进 DOM。于是这个门槛在真机上**永远过不了**——屏幕上有东西，state 里没有。

改成看 `.user-name` 在不在 DOM 里（与 Python 侧 `profile_dom` 同一个选择器）。
state 缺席只是「发布日与置顶会缺」，不再是「不能采」。

### ② 解析器只有一条腿（Python）

`open_archive` 在没有 state 时直接抛「找不到 `__INITIAL_STATE__`」——
哪怕 DOM 里字段齐全。现在加了第三档 `profile_dom`：

| 腿 | 数据来源 | 能给的 | 缺 |
|---|---|---|---|
| `profile` | state（存档自带或旁车） | 全部 | —— |
| `profile_dom` | 渲染后的 HTML | 昵称/小红书号/简介/IP/粉丝/关注/获赞 + 全部卡片（id/标题/赞/形式） | **发布日、置顶** |

实测对照（卡兹克那份真实主页存档，剥掉 `<script>` 后）：

| 字段 | state 腿 | DOM 腿 |
|---|---|---|
| 昵称 / 小红书号 / IP / 简介 | 数字生命卡兹克 / wzglyay2023 / 北京 / ✅ | 同左 |
| 粉丝 / 关注 / 获赞 | 143884 / 94 / 846545 | 14.4万→144000 / 94 / 84.7万→847000（**近似值**） |
| 笔记数 | 32 | 32 |
| 发布日 | ✅ | ❌ 页面上是「3 天前」 |
| 置顶标记 | ✅ 2 篇 | ❌ 32 张卡片里 `pin`/`top`/`置顶`/`sticky` 一个都没有 |

**缺两列不等于整份存档不能用**，但这两列宁可写 ⬜ 也不猜：
把 `pinned` 写成 `"0"` 会让「置顶 2 / 样本 30」静默变成「置顶 0 / 样本 32」——
数字全对得上，结论全错。

> 想补齐这两列：Ctrl+S 存一份「网页，全部」，或让扩展在 state 非空时再采一次
> （旁车会被自动带上）。`ar validate` 会 WARN，`ar selftest` 的 AC1 会红——
> 那就是「该补旁车了」的信号。

## v7.2 修了什么（2026-11-16，起因：第一次真机点击）

```
转换存档✗ The requested file could not be read, typically due to permission
problems that occur after a reference to a file has been acquired
```

`DOMException: NotReadableError`，来自 `blob.arrayBuffer()`。

**它不是说 blob 是空的**——`size` 读得出非零，只是**取不到背后的数据**。
`pageCapture.saveAsMHTML` 返回的不是内存里的一串字节，而是一个**句柄**
（Chrome 把 MHTML 写进了 profile 的 blob storage）。
这种跨进程句柄在 **MV3 的 service worker** 里读不稳。

修法不是「换个读法」，是**换个地方读**：采集搬到弹出面板（真渲染进程），
那里有 `FileReader`，对文件-backed blob 走的是已知可用的读路径。

拆成三个文件：

| 文件 | 跑在哪 | 干什么 |
|---|---|---|
| `capture.js` | 面板（渲染进程） | 找主页/笔记页、存档、读字节、带 state 分块上传、问 status |
| `popup.js` | 面板 | 只负责显示与触发 |
| `background.js` | service worker | 只负责画 badge（面板关掉后那点记忆） |

**代价是诚实的**：面板一关，采集就断。这是有意换的——
一个会失败的重试成本，比一个「以为在跑其实没跑」的静默失败便宜得多。

## v7 删掉了什么（以及为什么每一样都可以删）

| 删掉 | 它原来为什么存在 | 现在为什么不需要 |
|---|---|---|
| `offscreen.js` / `offscreen.html` | service worker 里没有 `URL.createObjectURL`，要借一个文档生成 blob URL | 不写文件了，就没有 blob URL |
| `offscreen` 权限 | 同上 | 同上 |
| 下载目录 / 文件名 `ar-page-*.mhtml` | 靠「文件落到磁盘」交接给 Python | 字节直接过管道 |
| `ar watch` 必须开着 | 靠轮询目录发现新文件 | 没有文件了 |

**v6 的三个真实事故（Blob 过不了消息通道、blob URL 跨上下文失效、
offscreen 没有 `chrome.downloads`）全部来自「要让浏览器写文件」这一个需求。**
v7 不写文件，那三个坑连同它们的修法一起消失。这不是运气，是**换掉一个错误的需求**的结果。

## 出问题时

| 现象 | 原因 | 怎么办 |
|---|---|---|
| badge 显示 `!`，提示「本地宿主没注册」 | 第 1 步没做，或换了扩展 ID | `python ar.py host --register` |
| 同上但提示「宿主清单里没允许这个扩展 ID」 | 扩展 ID 变过（换了 `key`） | 重新 `--register` |
| 「协议版本不一致（扩展 2，宿主 1）」 | 宿主还是升级前的进程/脚本 | `python ar.py host --register` 后重开面板 |
| 面板全空、写着「本地宿主没连上」 | 宿主 .bat 起不来 | `python ar.py host --doctor` |
| 「转换存档✗ …could not be read」 | 采集跑在了 background 里（v7.1 的 bug） | 确认 `manifest.json` 的 `default_popup` 是 `popup.html`，重新加载扩展 |
| 「失败 1 篇：从主页点开的弹层」 | 那篇是弹层不是整页 | 中键在新标签页打开那篇 |
| 「主页还没渲染出账号信息」 | 页面真的还没画出头部（`.user-name` 不存在） | 等它加载完，或往下滚一屏再点采集 |
| 「主页读不到页面数据」 | state 缺席。**v8.1 起这不再是失败**：会照常入库，只是发布日与置顶为空 | 想补这两列就 Ctrl+S 存一份「网页，全部」 |
| 「N 篇有图没加载出来」 | 懒加载的图没下载过 | 采集前把图片栏滑到底 |
| 「N 个标签未加载/已休眠」 | Chrome 把不用的标签丢弃了 | 点一下那个标签让它重新加载 |
| 「页面数据 N KB，超过单次上限」 | 那个号笔记太多，子树过大 | 只采它的主页（关掉其它标签），必要时先往下滚到需要的屏 |
| 什么都正常但库里没数据 | 数据目录不同 | 面板上会显示宿主用的 `数据目录` |

`python ar.py host --doctor` 会逐项报告：注册表、清单、启动脚本、`ar_host.py`、
扩展 manifest、以及**真的启一次宿主握个手**。检查不出问题才叫「能用了」。

## 拿不到什么（必须说清）

- **详情页的 `__INITIAL_STATE__`**：v8 起它由 state 隧道补上（分享数 / 精确发布日从
  ⬜ 变成有值）。但**只有当扩展把子树摘到、且没超过 4 MB 上限时**才成立；
  超限会在面板上明说「这次没带」。
- **懒加载没滚到的图 → 拿不到图**：没下载过的图不在内存里，打包不到。
  这几张在 `_files/` 里没有字节，`ar images` 会报「本地 3 < 声明 16」。
  **这是数据事实，不是解析 bug。** 所以要存全图，按 Ctrl+S 之前得先把图片栏滑到底。
- **视频**：MHTML 里只有封面，视频本体不在。
- **评论**：`pageCapture` 存下来的是首屏已渲染的评论，不是全部（展开加载的那些要人手动点）。
- **主页的列表只到滚到的位置**：页面没滚下去的那几屏笔记不在 DOM 里，也不在 state 里。
  想采全，先往下滚到底再点采集。

## 为什么上限是 10 个标签

不是技术限制，是**行为限制**：一次开 10 个标签页本身就会形成请求突发，
比人逐篇点更不像正常用户。建议一次开 3–5 篇，读完再点一次保存。
