# extension/ —— 详情页采集扩展 v2（Chrome / Edge，Manifest V3）

> **v2 的变化**：从「一篇一存」升级为「**一次保存当前窗口里所有已打开的小红书笔记页**」。
> 采 10 篇的点击次数：v1 需要 10 次 → v2 只需 **1 次**。

## 装法（开发者模式，10 秒）

1. Chrome / Edge 地址栏输入 `chrome://extensions`（Edge 是 `edge://extensions`）
2. 打开右上角 **开发者模式**
3. 点 **加载已解压的扩展程序** → 选这个 `extension/` 目录
4. 工具栏出现 **AR 采集** 图标（若被折叠，点拼图图标固定它）

## 用法（一次采 5 篇，约 40 秒）

1. 在主页看板上**中键连开 3–5 篇**笔记（每篇是新标签页，各自加载完）
2. 切到任意一个笔记标签，**点一下 AR 采集图标**
3. 浏览器连续下载 `ar-note-<id>.txt` × N
4. 另一头 `ar watch` 在后台守着，文件落地**自动入库**——全程不用回终端

## 为什么「批量保存」这次可以、以前不行

这是本项目最关键的一条边界论证：

| 做法 | 请求由谁发起 | 是否新增请求 |
|---|---|---|
| 脚本/MCP 打开 10 个链接再保存 | **程序** | ✅ 新增 10 次 |
| 你中键连开 10 个标签，扩展一次保存 | **你**（页面加载时请求已发生） | ❌ **零新增** |

**被禁止的「批量存档」是「程序把页面拉回来」；不是「把已经在你眼前的页面存下来」。**
两者分界只有一个：**有没有产生新的请求**。这个扩展一次点击处理 N 个页面，
但**它一个请求都不发**——所以它不越过那条线。

### 一个必须知道的实现细节：跳过休眠标签

Chrome 会把长时间不用的标签「丢弃」（`discarded`），此时页面不在内存里。
**对丢弃的标签注入脚本，浏览器会先把页面重新加载回来**——那就是我们制造了一次请求，
论证立刻崩掉。所以代码显式跳过 `discarded` 与 `status === "loading"` 的标签，
并在提示里说明「N 个标签已休眠，已跳过」。

这不是防御性编程，是**这条能力的成立前提**。有单测钉着
（`test_skips_discarded_and_loading_tabs`）。

### 单次上限 10 篇

`MAX_TABS = 10`。不是技术限制，是**行为限制**：一次开 10 个标签页本身就会形成请求突发，
比人逐篇点更不像正常用户。**建议一次 3–5 篇。**

## 边界（设计约束，非建议）

| 它做 | 它不做 |
|---|---|
| 读**已加载**页面的正文与互动栏文字 | ❌ 不发任何网络请求（无 fetch / XHR / WebSocket） |
| 用 `data:` URL 触发本地下载 | ❌ 不导航、不开新标签、不 reload |
| 只处理**当前窗口**你自己打开的小红书笔记页 | ❌ 不读 Cookie / localStorage / 会话 |
| 跳过休眠与未加载的标签 | ❌ 不模拟平台控件、不接管浏览器会话 |

**权限**：`scripting`（注入只读脚本）+ `downloads`（存文件）
**host_permissions**：只有 `https://www.xiaohongshu.com/*`，不是 `<all_urls>`
——没有 `cookies`、没有 `webRequest`、没有 `history`。想加也加不上（有测试拦着）。

## 字段

自动拿到：`note_id`、标题、正文首 40 字、正文长度、时长（视频）、话题标签（随正文）。

**不自动填**：赞 / 藏 / 评——`bar_text` 会带出互动栏原文，照它填。
理由：`like-wrapper` 这类选择器平台一改就失效，自动填会变成**静默错数据**。

> 更好的办法：**详情页 HTML 通道**（右键新标签打开 → Ctrl+S 选「**网页，完整**」→ 丢进 inbox）
> 能自动拿到赞/藏/评，**还能拿到图上的正文**（`ar images --ocr`），
> 见 [../docs/详情页采集-结论.md](../docs/详情页采集-结论.md) 与 [../docs/图片内容通道.md](../docs/图片内容通道.md)。
> 扩展适合「数字不急、正文要先拿到」的场景；HTML 通道适合「数字也要准 + 内容在图上」的场景。
> ⚠️ 扩展**拿不到图**：它只读已渲染的文字层，而图文笔记的完整内容常常只排版在图上（实测正文层只占全文 1%–43%）。

## 与书签版的关系

`tools/capture-bookmarklet.js` 是同一套读取逻辑的书签版（单页）。

| | 书签 | 扩展 v2 |
|---|---|---|
| 安装 | 粘贴 `javascript:` | 开发者模式加载目录 |
| 一次处理 | 1 篇 | 当前窗口全部（≤10） |
| Chrome 是否拦 | 部分版本拦 | 不拦 |

**逻辑改动请同时改两份**；`tests/test_bookmarklet_redlines.py` 与
`tests/test_extension_redlines.py` 分别检查两者的红线。
