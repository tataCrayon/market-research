# S4 矩阵视图：三个问题，以及三个「不许装」的地方（2026-11-12）

> 一句话：`ar matrix` 把「跨账号能答什么」做成一张**离线 HTML**——
> 无脚本、无外链、无图片，断网双击可开。
> 它只回答 PRD §8 的三个预设问题，**答不出的地方明写答不出**。

## 1. 它回答什么

| # | 问题 | 区块 | 当前实测能不能答 |
|---|---|---|---|
| Q1 | 图文 vs 视频哪种形式的中位互动更高？ | §2 | 卡兹克**能**（28 图文 / 3 视频）；知新**不能**（只有图文一种形式达 3 篇） |
| Q2 | 有哪些打法在 ≥2 个账号上验证过？ | §4 | **不能，0/17** —— 两个号的打法没有交集 |
| Q3 | 想做「X 母题」，谁做过、我抄会死在哪？ | §3 + §5 | 知新**能**（7 个母题）；卡兹克**不能**（49 篇 topic 全空） |

**这张表本身比页面更有用**：三个预设问题里，现在只有一个半能答。
页面的价值不在于「答出来了」，而在于**把「答不出」也变成可见的结论**。

## 2. 三个「不许装」的地方

### ① 样本不足不许给中位数

一个母题只有 2 篇时算中位数没有意义——那不是「这个母题的水平」，是那 2 篇的平均运气。

所以定 `MIN_SAMPLES_FOR_MEDIAN = 3`，不够就显示 `⬜ <3 篇`，**不给数字**。

形式对照同理：知新 30 篇全是图文，视频 0 篇。报一个「图文比视频好」是编的，
页面写的是「只有 1 种形式达到 3 篇，不足以比较」。

### ② 空值不许写成 0

FuzzyPop 还没采到任何笔记。最初版本它在总览里显示 `样本 0 | 篇均 0.0 | 中位 0.0 | 最高 0`。

`0.0` 会被读成「这个号的中位赞就是 0」——那是**完全不同的结论**：一个是「数据没采」，
一个是「数据很差」。现在显示 `⬜ 0 篇 / 无笔记 / ⬜`。

**这条与项目纪律「⬜ 不得被填充」是同一条**：0 也是一个需要证据的数。

### ③ 未标注不许合并隐藏

`notes.topic` 是拆解时写入的标签。卡兹克那 49 行 `topic` **全为空**——
历史数据在 topic 列出现之前就入库了。

如果把空值静默归到「其他」或者干脆不显示，页面会呈现「卡兹克没有母题分布」这种假结论。

现在：空 topic 单独成一行、排在最前、用灰段 `--seg-na`，并显式写：

> ⚠️ **标注缺失** 数字生命卡兹克 的全部 33 篇都没有 topic 标签——
> 这不是「没有选题」，是**标注缺失**。

**排在最前的理由**：数据质量问题比任何母题都该先被看见。

## 3. 不评分（PRD §7 N5）

这一条最容易在实现时被违反，因为「综合评分」是页面的自然诱惑。

所以：
- 排序依据只有一条——**样本中位点赞**，且写在标题下面。
- 页面里**没有任何加权合成列**。
- 爆文率 K=3 每个号用自己的中位算，页面明写「跨账号不可直接比」。

单测检查的是**表头里没有「综合/评分/指数/总分」这些列**，而不是「页面不出现评分二字」——
后者会误杀「这里不做综合评分」这句说明本身。

## 4. 为什么直接拼 HTML，而不是复用 markdown

试过「复用 `report.py` 的 markdown 段 + 写个小渲染器」，理由是不重复。

但那个渲染器要认表头、分隔行、加粗、内联 span、转义边界——**等于重写一个 markdown 解析器**，
而它只服务这一个模块。

直接拼 HTML 代码更短、边界更少、可测（可以断言 `div` 平衡、无 `<script>`、无 `http://`）。

**markdown 与 HTML 的同源不靠共用字符串，靠共用 `ReportData`。**
这才是「双输出同源」（N3）的可执行含义：同一个数字对象，两种排版。

## 6. 已知边界

- **不做跨账号合并结论**。要合并需要 ≥3 个号同向，页面明说不做——
  样本不够时合并只会制造假规律。
- **不重新聚类母题**。`topic` 是拆解产物，本页只聚合。
  在这里聚类等于让页面自己产出结论。
- **没有筛选/排序交互**。那需要 JS，与「无脚本、断网可开」冲突。
  当前 3 个账号 17 条打法还不需要交互；超过 10 个账号时再考虑。
- **`data/` 在 gitignore**，所以矩阵页也是本地派生物，不随仓库分发。
