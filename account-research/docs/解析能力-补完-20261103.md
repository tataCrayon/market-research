> 这一轮做的是**解析能力**的补完，没有新增采集动作。所有结论都来自 `account/` 里已有的 7 篇详情页存档。
> 起因是一个会崩的边界（万级计数），查下去发现旁边还躺着一个更值钱的漏洞（分享数 / 发布日 / 视频时长）。

## 2. 三条可移植的教训

### E14. 「页面没显示」≠「数据不存在」——先看页面里还有没有第二份

- 旧结论（写在两份文档里）：「分享数：页面上只有图标没有数字 → 永远 ⬜」。
- 事实：DOM 里确实只有图标，但同一份 HTML 内嵌的 `__INITIAL_STATE__` 里，
  `interactInfo.shareCount` 明明白白写着 `1776` / `1351` / `181` / `958` / `58` / `29`。
- **渲染层是副本，不是唯一真相**。判「拿不到」之前，先问：这份存档里除了渲染结果，
  还有没有平台自己的结构数据？SPA 页面几乎总是有。
- 代价对比：这一处认知错误让我们把三列字段白白留空了两个多月，而数据一直躺在存档文件里
  ——**不是采不到，是没去读**。

### E15. 解析失败的根因往往在离现场最远的地方

- 症状：5 篇详情页「没有 state」。第一反应会去查正文、查页面类型、查采集姿势。
- 根因：`{"AiNoteDetailStore":{"noteDetailMap":new Map([])}}` —— 一个与内容完全无关的
  前端 store 字段，因为用了 JS 构造器而不是 JSON 字面量，让**整份** state 在 `new` 上报错。
- 一个字符的问题，废掉的是整份文件的全部结构数据。**解析器的失败是整份失败，不是局部失败**，
  所以「清洗」这一步的覆盖面，等于整条通道的可用率。
- 顺带定了条边界：只转**空**构造（`new Map([])` → `{}`）。`new Map([["k",1]])` 里有真实数据，
  转成 `{}` 就是静默丢数据——宁可让它报错让人来看。

### E16. 圆整值不是精确值，而它会同时制造「崩溃」和「静默」

- 平台上万后把计数渲染成 `1.2万`。同一个字符串在两条路径上表现完全不同：
  - `ar gaps` / `ar links`：`int("1.2万")` → **ValueError，命令直接不可用**；
  - `ar stats`：`_int_or_none` 返回 None → **整行被丢出样本**，`n_total` 少一篇、
    `excluded` 还是 0、没有一个字提示。
- 后面这种更坏：崩了你会去修，静默丢行你不会。而且丢的恰恰是**破万的那几篇**——
  也就是最该被分析的那几篇。
- 修法的关键不是「把万换算成数字」，是**保留不确定性**：`Count(value, approx, low, high)`。
  - 排序/分档/篇均 → 用 `value`，够用；
  - 报告里逐篇引用 → 必须 `≈12,000`，不许写 `12,000`；
  - 两条通道比对 → 比**区间是否重叠**，不比值是否相等（`1.2万` 与 `12345` 是同一件事）。
- **可移植教训**：把「精度」变成类型的一部分，而不是靠人记得。记不住的纪律等于没有纪律。
