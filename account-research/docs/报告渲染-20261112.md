# 报告渲染：把「手抄数字」这件事从流程里删掉（2026-11-12）

> 一句话：`ar debrief` 早就把「拆解」跑通了，但产物是四张 CSV。
> 前两份报告（卡兹克、知新）都是**手写的**——每拆一个新号就要重抄一遍数字、重排一遍版式。
> `ar report` 把这一步变成一条命令：**改表即改报告**。

## 1. 为什么必须做

三个理由，按代价从低到高：

**① 手抄会漂。** 实测把 `27/31` 写成 `29/31`——这种错读起来完全合理，
而且不会让任何校验报错（报告不是表，V1–V8 管不到它）。

**② 成本会重复付。** 每拆一个号都要重抄一遍。库里有 3 个账号、计划还要拆更多，
这笔账是线性增长的。

**③ 两处口径会分叉。** 报告里的分母是手写的，`stats` 里的分母是算出来的。
两边不一致时没人知道哪个对——这正是之前那个「§4 与 §5 报了两个不同样本量（30 vs 31）」
bug 的同一个病根，只是换到了报告层。

## 2. 设计：`ReportData` 算、`render_*` 排

```python
data = report.collect(data_dir, account_id, text_dir)   # 所有数字在这里算完
text = report.render(data)                              # 纯函数，只排版
```

**为什么分两层**：项目纪律要求「双输出同源」（markdown 与 HTML 的数字必须一致）。
把计算收进 `ReportData`、渲染拆成函数，后续加 HTML 视图时**复用同一个对象**——
结构上就不可能漂，而不是靠「两边都记得改」。

`render()` 是**纯函数**：同样的表永远渲染出逐字节相同的文本。有单测钉住（`test_same_data_same_text`），
因为不可复现的报告无法 diff、也无法判断「这次改动是不是只改了版式」。

## 3. 报告结构与它防的三类错

| 段 | 内容 | 防的是什么 |
|---|---|---|
| 头 | 判决 + 决定日 + 到期日 + 理由 | 挂着过期判决（表只追加，历史判决仍在） |
| §0.1 | 样本量与统计 | 分母手抄漂移 |
| §0.2 | 覆盖度（正文/图上/评论原文/藏评分享） | 拿「有评论数」当「读过评论」 |
| §0.3 | **永远拿不到的**（附理由） | 读者把「漏采」和「拿不到」混为一谈 |
| §1 | 逐篇数据（含 ✅ 文本层标记） | 无从核对某条结论对应哪篇 |
| §2 | 四层结论（未知 layer 归「其它」） | **报告「看起来完整」而实际吞了结论** |
| §3 | 可抄清单（**失效条件缺失标 ⚠️**） | 出现「建议全抄」式内容 |
| §4 | 假设 + 到期日 | 假设永远挂着「未验证」 |
| §5 | 三件套 + 双镜 + 历史判决 | 判决只有一句话、没有可执行下一步 |
| §6 | 本报告没做到的事 | 把部分结论当全量结论引用 |

### §2 那条最值得说：不吞结论

库里 `findings` 的 layer 分布是 `结构 13 / 定位 6 / 变现 6 / 选题 5 / **产能 1** / **数据 1**`。
后两个不是 SKILL.md 的四层之一。

初版实现按四层分组渲染，`产能` 与 `数据` 会**静默消失**——报告仍然完整、仍然好看，
但少了两条真结论，而且读者不知道少了什么。

改成：未知 layer 一律归到「其它（N 条）」。有单测
（`test_unknown_layer_goes_to_extra_not_dropped`）。

**这是本模块最该记的一条**：报告最坏的不是丑，是「看起来完整但是漏的」。

### §0.3 那条：⬜ 要带理由

读者会合理地问「粉丝增长呢？」「报价呢？」。如果报告里只有一堆 ⬜，
他分不清是**漏采**（该去补）还是**永远拿不到**（别浪费时间）。

所以把 `fans_growth / impressions / 报价` 这三类**固定**列成一张表，每条给一句「为什么拿不到」。
判据：**读者会合理地问「这个数呢？」——那就必须回答「拿不到，因为 X」。**

## 4. 一个必须小心的细节：表格转义 vs 原话

markdown 表格单元格里的 `|` 会把表撑坏，所以要转义成全角 `／`。

但**只有表格里的字段能转义**。`findings.statement` 是散文段落，
里面的 `|` 是原话的一部分——转义就是篡改证据。

单测拆成两条钉住这个边界：
- `test_no_pipe_inside_table_cells`：假设表（表格）里的 `|` 要变 `／`
- `test_prose_is_not_escaped`：finding statement（散文）里的 `|` 要原样保留

## 6. 已知边界

- **只渲染已有结论，不生产结论**。表里没有的东西不会自己长出来——
  没有 verdict 就写「还没有判决」，没有 findings 就写「还没有 findings」。
- **不做 HTML**（那是 S4）。`ReportData` 已经是共享层，加视图时不用重算。
- **`data/reports/` 在 gitignore 里**（`account-research/data/*`）。
  报告是派生物：给外人看的那一份要单独放，且放之前要确认没有采集者会话信息。
