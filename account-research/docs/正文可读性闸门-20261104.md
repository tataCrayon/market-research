# 「数据齐了」是一句会说谎的话（2026-11-04）

> 我上一轮提议：「知新那 33 篇的解析数据已经齐了，跑一次 debrief 就能验证方法论对第二个账号是否成立」。
> 动手前先盘了一遍 —— **这句话是错的**，33 篇里只有 1 篇能读到正文。
> 这轮做的是把「能不能读」变成闸门，顺便修掉一个同一个任务里两套分母的 bug。

## 1. 盘出来的实况

```
知新：33 篇（置顶 2 / 样本 31）
样本里能读到正文的：1 篇
样本里能读到图上文字的：1 篇（同一篇）
其余 30 篇：只有标题 + 发布时间 + 点赞
```

「齐」指的是**字段齐**（标题/时间/赞/形式），不是**能读**（正文/图上文字）。
结构层拆解——开头钩子 / 中段节奏 / 结尾引导 / 标题句式——**全靠正文**。
只有标题能做的只有选题层（母题归类、标题句式）。

## 2. 更要紧的是：代码一声不响

`ar debrief` 当时的提醒逻辑只有一条：「本次一篇图上文字都没有 → 必须写进 sample_basis」。
正文覆盖 1/30 这种情况它一个字都不说，首行照样欢快地报：

```
账号 知新的AI笔记（686011fb...）：样本 30 篇｜正文 3 篇｜图上文字 3 篇
```

（那 3 篇里 2 篇是置顶，不进样本——连这个「3」都比样本内的真数大。）

而一轮真跑要烧 **60–114 万 tokens、7–11 分钟**。

**不出声的代价不是「结果差」，是「结果看起来一样好」。**
模型会拿标题 + 点赞硬写出一份结构拆解，读起来完全合理，而正文根本没读过。
这和 E14（「页面没显示」当成「数据不存在」）、E17（纪律只在文档里）是同一类错误：
**规则写在 SKILL.md 的验证清单上，执行靠人记得。**

## 3. 修法：§3.1 正文可读性闸门

任务文本里新增一节，三档：

| 能读到 | 闸门输出 |
|---|---|
| ≥ 3 篇 | `- 可读正文 N/total 篇：满足「深拆 3 篇」的下限，结构结论可以基于实读文本。` |
| 1–2 篇 | `⚠️ 能读到的文本只有 N 篇：不足「深拆 3 篇」。结构层结论必须在 sample_basis 里写明样本量，并标注仅这几篇成立；不许把 N 篇的观察写成「这个号的通用结构」。` |
| 0 篇 | `⛔ 正文一篇都读不到：结构层必须整层留 ⬜，不许用标题 + 点赞反推结构——那不是拆解，是编。` |

并且**点名**可读的是哪几篇（`6addb1a6`（果然马斯克…））。只说「只有 2 篇」，
模型还得自己去翻目录找是哪 2 篇——那是真金白银的 token。

`required = 3` 这个数不是随手挑的，是 SKILL.md 验证清单里「深拆 3 篇（爆款 / 中位 / 近期）」定的下限。

## 4. 两个实现细节，都是踩出来的

**① 按篇取并集，不能把两层计数相加。**
正文层与图上文字层是**两批不同的篇目**，同一篇可能两层都有。相加会把它数两次。
第一版就是这么写的，单测立刻抓到：`bodies=1, images=2` 而且 n1 两层都有时，
相加得 3 → 判定「满足」→ 放行一个其实只有 2 篇的结构结论。

**② 同一个任务里两个分母。**
`ar debrief` 的 §4 统计块报「样本 30 篇」，§5 覆盖块报「样本 31 篇」。
根因：`stats.summarize` 排「置顶 + 无点赞」，`coverage_counts` 只排了置顶。
那个号有一行是详情页顺手建的占位行（点赞为空）。

危害不是差 1 本身，是**模型引用 `a/b` 时被迫二选一**，而闸门 `audit_ratios` 又按 §5 判——
两个口径互相打架，模型怎么写都可能被退回。

**错值会被质疑，两个值会被各取所需。** 现在统一到「能进统计的样本」，
并有单测钉住 `coverage_counts(...)["n_sample"] == summarize(...).n_sample`。

## 5. 所以第二个账号现在能拆吗？

**选题层能，结构层不能。**

| 层 | 现在能不能做 | 依据 |
|---|---|---|
| 选题层（母题、爆款集中度、形式分布） | ✅ 能 | 30 篇标题 + 时间 + 点赞齐 |
| 定位层 | ⚠️ 半能 | 主页存档有简介/粉丝/累计互动，但没有正文佐证 |
| 结构层 | ❌ 不能 | 样本内只有 1 篇正文。硬写就是编 |
| 变现层 | ❌ 不能 | 需要正文里的转化入口 |

要补齐结构层，最少还需要 **2 篇**详情页（凑够 3 篇）。我已经生成清单：

```bash
python account-research/ar.py links --account 686011fb000000001b023a74 --out account-research/data/todo-zhixin.md
```
