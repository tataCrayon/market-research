# 假设结案：把「该结案了」变成一条能执行的命令（2026-11-12）

> 一句话：`ar status` 连喊 10 天「证伪或证实都算结案，唯独不能继续挂着『未验证』」，
> 而**命令行里没有任何一条路能做到**。这次修的是执行面，不是措辞。

## 1. 三条路全是死路

```
$ ar add hypotheses --file h.json     # 想把 H-KZK-01 的 status 改成「已证伪」
hypotheses：新增 0 行（校验先于落盘 ✅）   ← 键已存在，append-only 静默跳过

$ ar --help | grep -i close
（20 个子命令里一个都没有）

$ # PRD §4.1 说「到期未验 → 自动降 已证伪（超期未验）」，照着写：
ERROR [V6] H-KZK-01: 状态「已证伪（超期未验）」不在 ('未验证','验证中','已证伪','已证实') 内
```

结果：守纪律的唯一方式是**手改 CSV**，而那被明令禁止（「写入口唯一」）。

**这是 E25/E26 同源的第四次复发**——纪律写在提示里，执行面缺一块。
前三次分别是「评论采不到」（其实是没解析）、「字段齐≠能读」（没闸门）、
「拿不到无法复核」（没记尝试历史）。这次是「该结案但没结案命令」。

## 2. 根因：表结构不允许结案

假设表的键原先是 `hypothesis_id`——**一条假设终生一行**。
在这个设计下，「结案」在物理上做不到：任何对同一 `hypothesis_id` 的写入都会被
`preview_append` 判成重复键并跳过。

所以修法不是加个命令壳，是**先改键**：

```python
HYPOTHESIS_COLUMNS = (..., "recorded_on", "close_note")
TABLE_KEYS["hypotheses"] = ("hypothesis_id", "recorded_on")
```

结案 = **追加一行新状态**。历史状态留在表里（那是证据：它确实在 11-02 之前一直是「未验证」）。

这与判决表（`account_id + decided_on`，二判靠追加）是同一个模式，不发明第二套。

## 3. 加了第五个状态，而不是复用「已证伪」

PRD 原来写的是「到期未验 → 自动降 `已证伪（超期未验）`」。这个词有两个问题：

1. 它不在枚举里，V6 会直接拒（见 §1 第三行）；
2. 更根本的：**没做实验 ≠ 被证伪**。

前者是「我不知道」，后者是「我知道它不对」。把两者写成同一个词，
等于在结案的同时**编了一个结论**——恰好是本项目最禁止的那件事。

所以新增 `超期未验`，并把闭合集合拆开：

```python
HYPOTHESIS_STATUS = ("未验证", "验证中", "已证伪", "已证实", "超期未验")
HYPOTHESIS_CLOSED = ("已证伪", "已证实", "超期未验")
```

## 4. 三个「不许静默」的地方

**① 用「未验证 / 验证中」结案要拒。** 那只是把告警重新点亮一次，等于什么都没做。

**② 同一天结案两次要拒。** 键是 `(hypothesis_id, recorded_on)`，同一天第二次会撞键 →
`preview_append` **静默跳过** → 而 `close` 打印的却是「新增 1 行」。
「看起来成功其实没写」正是这次要消灭的失败模式，所以在命令层就拦住：

```
❌ 「H-KZK-01」在 2026-11-12 已经有一条结案记录（状态「超期未验」）。
   同一天只能结案一次——表键是 (hypothesis_id, recorded_on)，再写会被静默跳过。
```

**③ `超期未验` 必须写 `--note`。** 不写原因的话，三个月后没人分得清这条假设
是被放弃了还是被忘了。校验器 V6 也有同样一条——不能只靠命令层自觉。

## 5. 告警必须只看最新一行

这是最容易漏的一半。结案后表里会同时有旧「未验证」行和新「超期未验」行。

如果 `overdue_hypotheses()` 照旧逐行判，**已结案的假设会因为旧行继续被报出来**——
结案了却还在响，比不结案更让人不信任告警（E12）。

所以加了 `store.latest_hypotheses()`（按 `recorded_on` 折叠，同日取最后写入的），
`alerts` 与 `report` 都改用它。

顺带：`ar debrief` 的 `DATE_DEFAULTS` 也给它加了 `recorded_on`——模型不知道今天几号，
和 `decided_on` 一样由代码无条件写，否则 V6 会因缺 `recorded_on` 拒收结案行。

## 6. 当前实测

```
$ ar close hypothesis H-KZK-01 --status 超期未验 --note "..."
结案 H-KZK-01：未验证 → 超期未验（recorded_on 2026-11-12）
hypotheses：新增 1 行（校验先于落盘 ✅）
```

三条到期假设全部结案：

| 编号 | 状态 | 为什么没做实验 |
|---|---|---|
| H-KZK-01 | 未验证 → **超期未验** | 要自号发 2 条对照稿，属用户侧发布动作 |
| H-KZK-05 | 未验证 → **超期未验** | 要自号发 5 篇并等 48h |
| H-KZK-06 | 未验证 → **超期未验** | 要自号 14 天日更 vs 隔日更对照 |

**告警从 5 条降到 2 条**（只剩 D1 判决到期）。

三条结案说明里都写了同一件事：**这些验证都要求「用户自己的账号发内容」，
调研侧永远做不到**。这不是拖延，是这类假设的结构性问题——
它们本该在提出时就标注「需自号实验」，而不是等到期才发现做不了。

## 7. 验证

```bash
python -m pytest account-research/tests -q    # 364 例（本轮 +20）
python account-research/ar.py validate        # 0 ERROR / 0 WARN
```

测试重点不是函数行为，而是**那条死路是否真的通了**：

- `test_overdue_unverified_is_a_legal_status`：PRD 写的那个词必须先能过 V6
- `test_after_close_the_alert_is_silent`：结案 → 写入 → D2 闭嘴（整条链路）
- `test_history_rows_do_not_keep_the_alert_alive`：旧「未验证」行不能让它继续报警
- `test_same_day_second_close_is_refused`：不许出现「打印成功但没写」
- `test_alert_tells_you_how_to_close`：告警必须给出可执行的下一步

## 8. 已知边界

- **只支持 hypothesis**。判决的「二判」走 `ar add verdicts`（键含 `decided_on`，
  追加新判决即可），不需要 `close`——两条通道语义不同，不合并。
- **不能撤销结案**。表是只追加的。同一天写错只能等第二天改判，或手工处理。
  这是 append-only 的固有代价，接受它比绕开它安全。
- **`超期未验` 不是终点**。有计划重启时，应当**提一条新的假设**
  （新 `hypothesis_id`），而不是把旧的改回「验证中」——旧的那条已经记录了
  「这段时间没做」这个事实，改回去等于抹掉它。
