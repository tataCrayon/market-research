# 关于「用 DSH 的浏览器能力替我们 Ctrl+S」

> 你提的这个方向**部分成立**，而且比我上一轮说的更接近可行。我上一轮有两处说得不准，先更正，再说清边界。

## 1. 先更正我上一轮的两处错

| 我说的 | 更正 |
|---|---|
| 「我的工具里没有任何能发出网络请求的接口」 | **不准确**。DSH 有 `web_fetch` / `web_search` 工具，也有 `dsh-mcp-client`（可挂外部 MCP 服务器，含浏览器自动化类 MCP）。我确实**能**通过 MCP 获得浏览器控制能力——这是 DSH 层的能力，不是我"没有" |
| 「我碰不到浏览器」 | 对**当前会话**成立（配置里没挂浏览器 MCP），但**不构成永久限制**。装一个 MCP server 就有了 |

但这个更正**不改变结论**，它只是把问题从「做不到」变成「做得到，但不该这么做」——理由要重新讲清。

## 2. DSH 能不能控浏览器：能，有两条正规路径

| 路径 | 是什么 | 是否触碰平台 |
|---|---|---|
| **MCP server（如 Playwright MCP / browser-use）** | DSH 通过 `dsh-mcp-client` 连外部 MCP，模型调用它的工具去开页面、点元素 | ✅ 会——它就是驱动浏览器访问平台 |
| **CDP 直连（`--remote-debugging-port`）** | 让脚本接管你已登录的 Chrome | ✅ 会，且复用你的登录态 |
| 浏览器扩展（本次交付） | 读**你已经打开**的页面，人点一下触发，零额外请求 | ❌ 不会 |

前两条能实现你要的"AI 帮按 Ctrl+S"，第三条不能自动化但要人点一下。

## 3. 为什么前两条依然不该用（这次给可执行的分界，不再只讲原则）

我上一轮说的是「程序发起 vs 人发起」。这个判据是对的，但太抽象，容易变成谁也说服不了谁。换成三条**可操作**的检查：

### 检查 1：这条请求，平台看到的是什么？

| 场景 | 平台侧日志 |
|---|---|
| 你打开浏览器、翻到某笔记 | 一个正常用户的一次页面访问 |
| MCP 让 Playwright 打开同一页 | 同样是一次页面访问，**但它来自 `navigator.webdriver=true` 的会话** |

**分界不是"有没有自动化"，是"对方能不能区分"**。MCP 驱动的浏览器在平台看来是自动化会话，这与「用 AI 还是用脚本」无关。

### 检查 2：数据还点得回去吗？

这是**产品逻辑**，不是道德问题：

| 来源 | 报告里能写什么 |
|---|---|
| 你 10-28 15:20 在这页看到的 | 「②级，来源：该笔记页，2026-10-28 15:20 查证」——可点回复核 |
| MCP 批量抓的 | 来源是"某个会话"，**具体到哪一次、哪一秒、页面是否一致，无法复核** |

你的报告卖点是「每个数字能点回去」。自动化不是"效率提升"，是**换掉这个卖点**。

### 检查 3：谁承担后果？

MCP 用的是**你的**登录态、**你的** IP、**你的**账号。封了是你。这一点不会因为"是 DSH 的能力"而改变——工具中立，账号不中立。

## 4. 那"利用 DSH 的能力"到底能用在哪

**能用，而且我建议用**——但不是用它去采，是用它做三件不碰平台的事：

| DSH 能力 | 用在哪 | 碰平台吗 |
|---|---|---|
| `dsh headless` | 拆解推理（已有规划，方向卡 S2） | ❌ |
| `ar` CLI + 子代理 | 解析、校验、统计、结论落库 | ❌ |
| MCP（可选） | 接你自己的数据源（如本地文件系统、笔记软件） | ❌ |
| **MCP 浏览器自动化** | **不接**——它会替我们访问平台 | ✅ 红线 |

**一句话**：DSH 的能力该用在你写的报告上，不该用在打开别人的页面上。

## 5. 我这次实际做了什么：把"人点一下"压到极限

既然不能自动化那一下，那就让它变成**一次点击、零复制粘贴**。交付了一个 Chrome/Edge 扩展（`account-research/extension/`）：

| 步骤 | 操作 |
|---|---|
| 1 | 打开笔记页（整页，不要弹层） |
| 2 | **点一下扩展图标** |
| 3 | 自动下载 `ar-note-<id>.txt` |
| 4 | 拖进 `account/inbox/` → `ar ingest` |

和书签版相比：**扩展不受 `javascript:` 限制**（Chrome 会拦书签里的脚本写法）、有图标、能常驻。
和之前的手工方式相比：**6 步 → 2 步**。

技术实现与书签一致：`chrome.scripting.executeScript` 读当前页**已渲染**的文字 → `data:` URL → `chrome.downloads`。
**没有一次网络请求**，权限只要 `activeTab` + `scripting` + `downloads`，不需要 `<all_urls>`、不需要 `cookies`。
