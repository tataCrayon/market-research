# 岗位不是你想的那样——真实 JD 才是证据，岗位名是会蒸发的东西

> **为什么存在**：通用的职业调研会给你一份"岗位职责 + 任职要求 + 发展前景"的三段式，读起来很专业，但**三段全部可能来自模型印象**。而职业决策里最贵的两个错误，恰好都出在这里：
> ① **岗位名 ≠ 岗位需求**——岗位名会通胀、会改名、会蒸发（"提示词工程师"这个独立岗位名在收缩，技能被折叠进别的岗位）；
> ② **门槛软硬不分**——把"3 年及以上**相关**工作经验""硕士及以上"当成可议的软性要求，结果连简历筛选都过不去。
>
> **心脏**：**JD 真取证 × 可迁移证据链对账**。
> - 心脏 A（Step 2 PROFILE）：职责与要求必须来自**真实招聘 JD + 官方职业标准**，不得来自通用模板或印象；
> - 心脏 B（Step 5 AUDIT）：把履历逐条对账成 **可迁移（有证据件）/ 需补（带时间预算）/ 硬门槛不可补** 三类。
>
> 找不到心脏就别建这个 Skill——那说明它只是通用调研的换皮。

## 何时用 / 何时不用

**用**（用用户会说的话写）：
- "AI / 大模型这个方向都有哪些岗位？"
- "AI 应用开发工程师到底要求什么？我能不能投？"
- "我做了 5 年前端，转 AI 应用开发差在哪？"
- "公司要招一个 XX 岗，岗位职责和任职要求该怎么定？"
- "这个方向还值得转过去吗，还是已经晚了？"
- "按 3 年经验、本科、在杭州，这个岗位还有得投吗？"

**不用**：
- 想知道某个 App / 小程序该不该做 → `app-market-research`
- 游戏立项与玩法验证 → `game-research`
- 已经定好了岗位，只想审「我这个决定对不对」 → `grill-me` / `doubt-driven-development`
- 要写简历、准备面试话术 → 不在本 Skill 范围内（本 Skill 产出调研与判决，不产出求职材料）
- **要对真实第三方自然人打分、排序、筛查、建档** → 红线 R1，直接拒绝执行

## 硬信念（7 条，违反即报告作废）

1. **判决必须落地**。判决集合封闭为五选一：`✅ 直接投 / 🔧 换岗 / 🧪 先补短板 / ⏸ 硬门槛不可逾越 / ❌ 放弃该方向`，每个判决附三件套（最值钱的一步 / 最便宜的验证 / 放弃信号）。
2. **证据分级**（③ 级在本领域细分为两个子类，见 [references/research-sources.md](references/research-sources.md)）：
   - **①权威** = 人社部新职业公告与国家职业标准、官方统计、原始法律文本
   - **②专业** = 企业官方招聘页、国聘/国企平台、高校就业中心 JD、行业报告、上市公司财报、**正规媒体的调查报道**（有记者调查 + 可追溯数据 + 交叉核实）
   - **③-a 媒体/机构二手** = 转行自媒体、内容农场、SEO 博客、转述的海外薪资数据 → 只能当线索
   - **③-b UGC / 匿名不可核验** = **脉脉职言与公司点评、小红书、知乎匿名答、贴吧** → **只能生成待核验主张与反向指标，不得当结论、不得单独支撑判决、不得进薪酬与门槛字段**
3. **未取证 ≠ 没问题**。查不到写 ⬜ 未取证并计入差距清单。默认「没问题」是职业调研里最贵的错误。
4. **反谄媚**。「⏸ 硬门槛」和「❌ 放弃」是常态判决之一。用户的热情不得影响结论。
5. **岗位名 ≠ 岗位需求**（本领域专属）。必须用真实 JD + 官方职业编码交叉验证岗位是否真实存在、是否在萎缩、职责是否被折叠进别的岗位。**用岗位名推断需求 = 报告作废**。
6. **门槛要分软硬**（本领域专属）。年限 / 学历 / 城市 / 资质 / 从业资格，必须逐条判「硬性（筛简历即淘汰）」还是「软性（加分项）」——**禁止默认"能力强可以放宽"**。混为一谈会让差距清单完全失去行动力。
7. **用工性质是必查维度**（本领域专属）。**同一个岗位名，自有 / 劳务派遣 / 岗位外包 / 项目外包·驻场 = 完全不同的选项**。不标用工性质会把外包岗当自有岗计入岗位供给，**虚增机会**；也会让用户在「能进」之后才发现履历含金量、福利、稳定性的差异。
   **判据只有两个法律事实**：**劳动合同甲方** 与 **社保公积金缴纳主体**。公司名、JD 用词、平台标签都只是线索——**禁止凭公司名一刀切**（识别指南见 [references/employment-nature.md](references/employment-nature.md)）。

## 三种模式

本 Skill 有三个入口，共享同一套证据纪律与红线。**默认模式 A**；用户只自查或只维护名单时走 B / C。

| 模式 | 何时用 | 产出 |
|---|---|---|
| **A 调研模式**（默认） | 想知道方向有哪些岗位、岗位要求什么、自己差多少、要不要转 | 职业调研报告 + 五选一判决 + 三件套 |
| **B 岗位能力自查模式** | 已有目标岗位，只想**对着岗位能力要求自查自己**（求职 / 晋升 / 转岗前的自我盘点） | 岗位能力自查表（能力差距矩阵 + 三档结论） |
| **C 名单维护模式** | 复核日到期 / 调研中发现新服务商 / 发现名单内公司更名被收购 | 更新后的 `references/outsourcing-suppliers.md` + 变更日志 |

**三者共享**：证据分级、四条非隐私红线、R1/R6 两条隐私与中立红线、双镜自审、未取证 ≠ 没问题。

### 模式 B：岗位能力自查（详见 [references/capability-model.md](references/capability-model.md)）

```
CHECK-1  圈定能力域与能力项   —— ①职业标准工作要求 × ②≥3 份 JD × ③失败侧线索，每项可追溯原文
CHECK-2  设目标等级           —— 按硬性(3)/软性(2)/加分(1) 分档，来自真实要求，禁止按理想拉满
CHECK-3  自评 + 绑证据件       —— 行为锚定五级(L0–L4) + 证据强度(强/弱/无)
CHECK-4  应用降级规则         —— 证据弱 → 等级降 1；证据无 → 记 L0–L1 并标「待补证据」
CHECK-5  差距矩阵 + 排序      —— 优先级 = 等级差 × 岗位权重；必须含「假差距」一栏
```

**心脏是证据件**：**无证据的等级不作数**。自查最容易被偷工成「凭感觉自评」，降级规则就是用来把「我觉得我会」逼成「我能拿出来」。

> **R1 限制**：自查对象**只能是本人或明示的虚构/聚合画像**。**禁止**用它评估真实第三方候选人——那是对真实自然人评分，触碰红线 R1。

### 模式 C：外包名单维护（详见 [references/outsourcing-suppliers.md](references/outsourcing-suppliers.md) §7）

**真实 case**：[`examples/模式C-外包名单维护运行记录.md`](examples/模式C-外包名单维护运行记录.md)（首次全量复核，暴露并修复 5 个 schema 缺陷）。

三条触发（**复核日到期 + 调研发现新服务商 + 发现更名/被收购**）→ 全量复核流程 / 单条追加流程 / 变更流程。

**批量发现本地服务商**（这一步产出远大于通用名单）：`<城市>/<区> 劳务派遣单位 名单 公示 核验`（人社局年度核验公示，**覆盖到区县**）+ `<城市> 人力社保局 行政许可决定清单 劳务派遣`（**动态**，含新办/变更/延续/**注销**）。

**硬纪律**：新增条目必须填满 schema（含必填字段「**是否同时是甲方雇主**」——这是防一刀切的最后一道闸）；**禁止收录无来源的公司名**；**禁止收录平台吐槽与匿名「避雷名单」**（③-b）；**禁止删条目，只改状态**（名单的可信度依赖可追溯的历史）；更名时**保留旧名做检索别名**（旧名仍会出现在历史 JD 里）。

**跑真实数据后补的四条（缺一就会误判）**：

| # | 纪律 | 为什么要写下来 |
|---|---|---|
| 6 | **许可 ≠ 实际开展业务** | 临平区样本：通过年检的 147 家里**仅 61 家实际开展**派遣业务（86 家持证未开展，占 59%）。把持牌名录整体当外包公司名单会一次性误伤过半 |
| 7 | **判定精确到法人全称，不精确到品牌名** | 同一个「信雅达」：母公司经营范围**明文排除**劳务派遣，全资子公司经营范围**明文含**「承接人力资源服务外包业务」且持派遣许可。**合同盖哪个法人的章，决定它是自有岗还是外包/派遣岗** |
| 8 | **「服务人次 / 在册外包员工数」≠ 自有员工数** | 人力资源公司宣传的「服务 30 万人次」与「自有管理人员 2700 余人」能差两个数量级，用作性质判据会得出相反结论 |
| 9 | **①权威来源给不了「业务特征」时，允许 ⬜ + 转「待复核」** | 人社公示只回答「有没有许可」，不回答「做什么业务」。**禁止凭公司名脑补业务描述**；但 ⬜ 不是免查——跨两个复核周期仍为 ⬜ 应降为失效 |

## 流程（8 步）

> 以下为**模式 A（调研）** 的完整 8 步。

```
STEP 0 SCOPE    — 调研委托书（输入参数规范化 + 用途合规闸门）
STEP 1 MAP      — 岗位图谱（岗位清单 + 别名 + 上下游 + 岗位健康度）
STEP 2 PROFILE  — 岗位职责 × 任职要求取证【心脏 A】
STEP 3 DRILL    — 单岗深钻（focus_post 的详细任职要求三级拆分）
STEP 4 FILTER   — 条件筛选与组合（年限 / 城市 / 学历 / 履历）→ 命中矩阵
STEP 5 AUDIT    — 差距审计【心脏 B】→ 可迁移 / 需补 / 硬门槛
STEP 6 PRICE    — 薪酬带宽与转型成本（含机会成本）
STEP 7 VERDICT  — 五选一判决 + 三件套
```

检索预算：**≤20 次**，其中至少 **1/2 必须投给 Step 2 PROFILE**（最容易偷工的一步——AI 最爱凭印象写「产品经理要会写 PRD」，顺手且看起来专业）。

数据源分级、UGC 源纪律与检索语句见 [references/research-sources.md](references/research-sources.md)。**UGC 源（脉脉 / 小红书）单列 3–5 次预算**——它需要平台内检索、成本更高，**不得挤占心脏 A 的 ≥1/2 配额**。

### Step 0: SCOPE —— 调研委托书

**产出物**：一份《调研委托书》，含：调研方向、别名清单、深钻岗位（或标记「由 Skill 按证据推荐」）、过滤条件（年限/城市/学历/履历）、检索预算、time-box（默认 8 周）、**用途声明**（个人职业规划 / 团队编制规划 / 岗位设计）。

**合规闸门（先于一切检索）**：若用途是「对真实第三方自然人建档、评分、排序、筛查」→ 立即停止并拒绝，说明理由（红线 R1）。

### Step 1: MAP —— 岗位图谱

**产出物**：《岗位清单表》（见输出格式 表1），列 **≥6 个** 核心岗 / 邻近岗 / 支撑岗即停——岗位图谱会无限膨胀，不在穷举上烧预算。

**做法**：先取**官方锚点**（人社部《国家职业分类大典》、新职业公告、国家职业标准），再用招聘平台 JD 取**市场用法**。两者不一致必须显式记录——**那正是「岗位名蒸发」的直接证据**。

每条标两个属性：
- **岗位健康度**：扩张 / 稳定 / 萎缩 / ⬜未取证
- **用工性质**：`自有` / `劳务派遣` / `岗位外包` / `项目外包·驻场` / `子公司关联直签` / `⚠️ 疑似未取证` —— 附判定依据 + 置信度（高/中/低）

用工性质的识别信号（强/中/弱三级 + 反例）、法定杠杆与核验入口见 [references/employment-nature.md](references/employment-nature.md)。**这一步最容易整体漏掉**——岗位名、薪资、门槛都查了，却没人问「合同跟谁签」。

官方锚点与市场用法的具体查证入口、健康度四档判据、岗位清单表字段规范见 [references/position-taxonomy.md](references/position-taxonomy.md)（**停止条件：≥6 个即停，穷举是检索预算的黑洞**）。

### Step 2: PROFILE —— 职责 × 任职要求取证【心脏 A】

**产出物**：逐岗《岗位说明书卡》（见输出格式 表2）。

字段：职责（4–8 条，动词开头）/ 任职要求三级拆分（硬性 / 软性 / 加分）/ 工具栈 / 交付物 / 考核指标 / 年限带 / 城市分布 / 学历门槛 / 薪酬带宽 / **用工性质 + 判定依据 + 置信度** / 来源 + 查证日期 + 证据等级。

**用工性质取证的三条路**（调研阶段就能做完前两条）：
1. **工商核验**（①权威）：招聘方经营范围是否含「劳务派遣」「人力资源服务」——国家企业信用信息公示系统 / 爱企查 / 企查查
2. **JD 信号**（②专业）：见 [references/employment-nature.md](references/employment-nature.md) 强/中/弱三级信号 + 反例
3. **面试核验**（用户后续动作，写入「最值钱的验证」）：必问三句——「劳动合同的甲方是哪家公司？」「社保公积金由哪家缴纳？」「是否有长期驻场要求？」

> 📋 **常见外包 / 人力资源服务供应商名单见 [references/outsourcing-suppliers.md](references/outsourcing-suppliers.md)**（含官方核验入口与检索语句）。
> ⚠️ **该名单只是「核验触发器」，不是判定依据**——在名单上 ≠ 该岗位是外包（这些公司自己也招自有员工），不在名单上 ≠ 是自有岗。**唯一判据仍是「劳动合同甲方 + 社保缴纳主体」两个法律事实**（红线 R6）。

**铁律**：每条字段必须有**真实来源链接 + 查证日期**；拿不到就写 ⬜ 未取证。**禁止用「行业通用要求」「众所周知」填空**——那是记忆冒充检索。

**交叉纪律**：职责要求至少 3 份 JD 交叉，并区分「这家公司特有」与「行业通用」。

字段级取证规范（每个字段的常见偷工方式）、软硬三级拆分判定规则、Step 3 深钻的额外五块、检索语句模板见 [references/jd-requirements.md](references/jd-requirements.md)。

### Step 3: DRILL —— 单岗深钻

**产出物**：《详细任职要求卡》（见输出格式 表3），针对 `focus_post`。

在表2 基础上补：典型一天 / 一个迭代在做什么、常见淘汰原因（**搜失败报告比搜成功案例值钱**）、晋升路径、可迁移入口（从哪些邻近岗能切进来）、以及**入职后 6–12 个月的存活要求**（试用期考核、前半年交付压力、学徒期绩效）。

> **只写到「拿到 offer」的报告，会在真实职业生涯里失效**——拿到 offer ≠ 站稳。

### Step 4: FILTER —— 条件筛选与组合 → 命中矩阵

**产出物**：《命中矩阵》（见输出格式 表4）。

**五类**过滤条件：**工作年限**（注意 `relevant_only` 开关——「3 年相关经验」≠「3 年工龄」）/ **城市** / **学历**（含**应届身份**）/ **履历背景**（过往经历、项目经验、技能、证书）/ **用工性质**（自有 / 派遣 / 外包 / 驻场 —— 对很多人是**独立开关**而非加分项）。

每格判定：✅命中 / ⚠️部分命中 / ❌未命中 / ⬜未取证，每格附证据。

**组合逻辑**：默认 **AND**（全部满足才保留）；用户显式指定时才用 OR 或加权。

**三条实证纪律（来自判决复审，见 `examples/评估测试-数据源扩展与判决复审.md`）**：

1. **城市必须单独检索，禁止外推**。用 A 城市的 JD 结论去判 B 城市是错的——实测中「杭州无岗位」的误判正是这样产生的。目标城市必须单独取证。
2. **同一岗位要按「薪资档位」分行判定**。实测：高薪档（1.5–3 万 ×14 薪）卡**硕士或应届身份**，低门槛档（0.8–1.4 万）**本科且经验不限**。**门槛与薪资强相关**，混在一行会同时误判「能投」和「不能投」。
3. **「应届身份」是一等硬门槛维度**。校招 JD 的「2026 届应届毕业生」对在职转岗者是死线，且它常被误读为「年限要求低 = 门槛松」——恰恰相反。

> **城市这一格最容易未取证**——必须显式标注，禁止默认「一线城市都有」，也禁止用其他城市的结论外推。

命中矩阵的四值判定规范、组合逻辑（AND/OR/加权）、差距审计的三类判定与排序、**JSON schema**、以及七种常见失败模式见 [references/candidate-matching.md](references/candidate-matching.md)。

### Step 5: AUDIT —— 差距审计【心脏 B】

**产出物**：《差距清单》（见输出格式 表5）。逐条对账「岗位要求 × 候选人履历」，每条标类型：

- **可迁移**——必须给出**证据件**（哪个项目 / 哪段经历 / 什么可核验指标能证明）。"我觉得能"不算。
- **需补**——可补齐，给**时间预算**（默认 ≤8 周）与最便宜的验证。超过 time-box 即视为换路径。
- **硬门槛不可补**——学历（含应届身份）、资质、从业资格、年限、城市等，当前路径不可达，需换路径而非硬填。
  **反外推纪律**：判一条为硬门槛前，必须确认**目标城市的 JD 也卡这一条**——单份/少数 JD 的门槛**不得外推为全市场门槛**。实测教训：用 1 份外地国企 JD 的「3 年相关经验」判了硬门槛，而目标城市实际存在「经验不限」的入口，导致判决偏严。

### Step 6: PRICE —— 薪酬与转型成本

**产出物**：薪酬带宽（带来源 + 日期，**禁写死**）+ 转型成本（学习 / 证书 / 空窗 / 降薪 / 职级回退 / 搬迁）+ 机会成本 + **回本周期**。

**薪酬必须分档记录**——因为**门槛与薪资强相关**：

| 档 | 记什么 |
|---|---|
| 低门槛档 | 门槛最松那批的薪资 + 门槛条件（常是转型者的唯一入口） |
| 中位档 | 与目标画像最匹配那批 |
| 高端档 | 门槛最严那批（常被学历 / 应届身份卡死） |

> 实测：高薪档（1.5–3 万 ×14 薪）卡硕士或应届身份，低门槛档（0.8–1.4 万）本科且经验不限。**混成一个带宽会同时误判「能投」与「不能投」**。
> **单城市口径必须注明「不得外推全国」**。

**三条硬要求**（来自落地镜 A/F 轴实证）：
1. 转型成本必须量化到**回本周期** = 转型总成本 ÷ 薪酬增量。只给「目标岗薪酬 − 现薪酬」会系统性低估回本时间。
2. **必须与「不转 / 深耕原岗位」比机会成本**。只评估「转」是方法论缺陷。
3. 未设 `salary_floor` 时，必须**显式声明「无法判断回本周期」**，不得跳过。

**薪酬数字一律现场取证**；只有 ③二手来源（尤其是转述的海外薪资）→ 标 ⬜ 未取证，**不得进判决理由**。

### Step 7: VERDICT —— 判决

| 判决 | 含义 | 触发条件 |
|---|---|---|
| ✅ **直接投** | 方向对、岗位对、硬门槛全过、仅剩加分项差距 | 命中矩阵无 ❌、无 ⬜ 阻塞项；差距清单无「硬门槛」项 |
| 🔧 **换岗** | 方向对但目标岗位选错（岗位萎缩 / 名实不符 / 需求被折叠进别的岗），应换到邻近岗 | 目标岗健康度 = 萎缩，或岗位名与真实需求严重脱节 |
| 🧪 **先补短板** | 有 ≥1 项「需补」差距，且全部可在 time-box 内补齐 | 无硬门槛阻塞，需补项均有时间预算 |
| ⏸ **硬门槛不可逾越** | 存在「硬门槛不可补」（学历 / 应届身份 / 资质 / 年限 / 城市 / 从业资格），当前路径不可达 | 差距清单含硬门槛项，**且经目标城市 JD 复检确认无低门槛入口**（否则判 🧪） |
| ❌ **放弃该方向** | 市场不为此付钱 / 岗位持续萎缩 / 薪酬低于底线且无上升 | 岗位健康度萎缩 + 薪酬不达标 + 换岗也无更好落点 |

**冲突时从严**：硬门槛 > 岗位萎缩 > 需补 > 直接投。

**三件套（缺一不可）**：
1. **最值钱的一步**——现在就该做的单个具体动作（优先选能一次消除最大不确定性的）
2. **最便宜的验证**——带时间预算（补齐类默认 ≤8 周；核验类 ≤1 天），明确验证哪条主张
3. **放弃信号**——观察到什么就停手（可证伪：如「投 20 份 0 面试」「目标城市在招岗位 <5 个」）

## 红线

- **判决必须落地**——不许「值得考虑」「看个人兴趣」收尾
- **外部结论必须带真实出处 + 查证日期**——只引用实际检索到的链接；没搜到就写「未取证」
- **未取证 ≠ 没问题**——写 ⬜ 未取证并计入差距清单
- **禁止用记忆冒充检索**——没有链接的薪酬/门槛数字一律删掉或标未取证
- **反谄媚**——「⏸ 硬门槛」「❌ 放弃」是合法且常常正确的判决
- **R1 隐私红线（本领域首要红线）**：不产出、不存储**可识别到具体自然人**的档案。禁止收集/输出第三方真实个人的姓名、联系方式、证件号、雇主可识别信息、简历原文。用途仅限个人职业规划、团队编制规划、岗位设计；**不得用于**对真实第三方自然人做评分、排序、筛查、画像归档。
- **R2 岗位名 ≠ 需求**：禁止用岗位名推断职责与任职要求，必须有真实 JD 或官方职业标准来源
- **R3 门槛软硬不得默认**：学历 / 年限 / 城市 / 资质是硬是软必须现场取证，禁止默认「可放宽」
- **R4 薪酬不得写死**：薪酬、在招量、通过率等变动数字一律现场取证，无①/②来源即标未取证
- **R5 UGC 源（脉脉 / 小红书 / 匿名社区）不得当证据**：它们是 ③-b——**信号早、可核验性低、有被伪造与营销污染的公开实证**。只能用来生成待核验主张、反向指标、岗位名真实使用观察；每条主张必须回到 ①/② 取证才能进判决。单帖不算（≥3 帖交叉且跨 ≥1 个月）；匿名爆料须标「未见官方确认」；**不得用搜索引擎的零星结果冒充「已检索该平台」**；私信/引流内容视为营销并反向计入岗位名通胀分。**例外**：UGC 平台作为**作品发布渠道**是正当用法——它不产生结论，但产出可出示的证据件。
- **R6 不得把外包岗当自有岗统计**：**同一个岗位名，用工性质不同 = 完全不同的选项**。不标用工性质会把外包岗计入岗位供给，**虚增机会**。判定必须落到**劳动合同甲方**与**社保公积金缴纳主体**两个法律事实，且**两个法律事实都要精确到法人全称**（同一集团内母公司可明文排除劳务派遣、子公司可同时持派遣许可并承接人力资源外包——判据是**合同盖章的那个法人**，不是品牌名）；**禁止凭公司名、JD 用词、平台标签一刀切**（「猎头/代招」≠ 外包；「子公司关联直签」既不是自有也不是外包，须单列）；**持牌 ≠ 实际开展业务**（临平区样本：通过年检者中仅 41% 实际开展派遣业务，政府许可名录不得整体等同于外包公司名单）；中信号须 **≥2 条叠加**才判「疑似」。**表述必须中立**——只陈述性质与客观影响（合同主体、福利口径、履历可核验性），**不得贬损、不得对人群排序**（与 R1 一致）。识别指南见 [references/employment-nature.md](references/employment-nature.md)。

## 常见合理化借口

| 借口 | 现实 |
|---|---|
| "这个岗位的职责大家都很清楚，不用查 JD" | 岗位名会蒸发。2026 年"提示词工程师"作为独立岗位名在收缩，而同一批技能被折叠进 AI 应用开发、AI 产品经理、解决方案架构师。凭印象写的职责，大概率是两年前的版本。 |
| "抄一份同行业 JD 就够了" | 单份 JD 只是**单一雇主的写法**。职责要 3–5 份交叉，且必须区分「这家公司特有」与「行业通用」。 |
| "年限和学历都是软性要求，能力强可以放宽" | 软硬必须取证。国企与校招 JD 白纸黑字写「3 年及以上**相关**工作经验」「硕士及以上」，筛简历阶段即淘汰——你连展示能力的机会都没有。 |
| "过往项目经验都能迁移" | 可迁移必须有**证据件**（具体项目 + 交付物 + 可核验指标）。转岗落选最常见的原因就是拿不出对应交付物，不是能力不够。 |
| "薪酬网上有个大概区间" | 二手转述的海外薪资不能用于国内判断。无 ①/② 来源即标 ⬜ 未取证，不得进判决理由。 |
| "先把所有岗位都列全再筛" | 岗位图谱会无限膨胀。列 ≥6 个即停，用命中矩阵筛，不在穷举上烧检索预算。 |
| "他符合大部分要求就够了" | 硬门槛是 **AND** 不是加权平均。一条 ❌ 压过九条 ✅——这正是命中矩阵必须单列硬门槛的原因。 |
| "城市随便挑个一线就有机会" | 城市分布必须逐岗取证。实测里 AI 应用开发岗分布在北上广深 + 无锡/重庆/安庆/昆明/西安，**杭州是否密集属于未取证**，不得默认。 |
| "先转过去再说，进去再学" | 转岗成本被低估：降薪、空窗、职级回退、学徒期。必须进 Step 6 计量，不能当免费选项。 |
| "脉脉上都说在裁员，肯定是真的" | 脉脉匿名区 2018 年因侵权被责令关停整改，且有伪造信息、水军刷评的公开实证。它是**最早**的信号源，也是**最不可核验**的源——正确用法是转成取证任务（查官方回应 / 查在招量变化），不是写进结论。 |
| "小红书上好多人都转行成功了" | 小红书的职业内容有**公开的机构引流方法论**，「假避雷真推广」已被媒体实证，且运营方法论明确教人用「避雷」「真实体验」增强可信度。**越像真实分享越要怀疑**——它是反向指标，不是成功率证据。 |
| "网上查不到这个岗位在杭州的情况" | 通用搜索引擎对脉脉/小红书索引很差。查不到要如实标 ⬜未取证并转成**平台内检索**任务，不得用零星搜索结果冒充已检索，也不得据此判「没有」。 |
| "岗位名、薪资、门槛都查了，应该够了" | 漏了**用工性质**。「AI 应用开发工程师」这个岗位名在自有、派遣、岗位外包、驻场外包下都存在——**不标性质，等于把外包岗当自有岗计入机会**。这是最容易整体漏掉的一格。 |
| "招聘方是 XX 科技/信息公司，肯定是外包" | **禁止凭公司名一刀切**。大型 IT 实施/集成商本身就是甲方雇主；「猎头/代招」只是渠道，合同仍可能与用人企业直签。判据只有两个法律事实：**劳动合同甲方**与**社保公积金缴纳主体**。 |
| "JD 里没写外包，那就是自有岗" | JD 不写是常态而非例外（有真实案例：标「大厂自研直签」、面试在大厂办公区，入职才发现用工主体是人力外包公司）。要靠**工商经营范围 + 面试必问三句 + 合同主体**三条路核验，不能只读 JD。 |

- v1.0.2（2026-09-21）：**评估测试 + 数据源扩展**（见 `examples/评估测试-数据源扩展与判决复审.md`）。
  - 静态验证 13/13 通过，但**动态重跑后判决由 ⏸ 改判为 🧪**——原判决偏严，根因是把单份外地 JD 的门槛外推为全市场门槛。
  - 修法（D1–D5）：① 硬门槛反外推纪律（须经目标城市 JD 复检）；② 城市须单独检索不得外推；③「应届身份」列为一等硬门槛维度；④ 薪酬**分档记录**（门槛与薪资强相关）+ 单城市口径不得外推；⑤ 新增 R5 UGC 源纪律 + `references/research-sources.md`（脉脉 / 小红书）。

- v1.0.3（2026-09-22）：**新增「用工性质」为必查维度**（硬信念 7 + 红线 R6 + 岗位清单表必填列 + 命中矩阵第五类过滤条件 + JSON `employment_nature`）。
  - 触发原因是一次**真实自省**：v1.0.2 的样例报告把「**科锐国际**」当成一家雇主写进了杭州岗位列表，而它是**人力资源服务公司**，发布的岗位很可能是代招或外包派遣——**这正是「岗位名相同、用工性质不同」的典型漏检**。
  - 法定杠杆（①权威）：《劳动合同法》与《劳务派遣暂行规定》规定派遣只能用于**临时性/辅助性/替代性**三性岗位、比例 **≤10%**、部分岗位**禁止派遣**；「假外包、真派遣」被列入 2025 年人社部等五部门专项行动重点。
  - 核验只有两个法律事实：**劳动合同甲方** 与 **社保公积金缴纳主体**；工商经营范围（国家企业信用信息公示系统/爱企查）可作为调研阶段的 ①权威 预判。

- v1.0.4（2026-09-22）：新增 [references/outsourcing-suppliers.md](references/outsourcing-suppliers.md)——常见外包 / 人力资源服务供应商名单（A 类人力服务与派遣：中智/上海外服/FESCO/科锐国际/万宝盛华/外企德科/任仕达/人瑞人才/易才/英格玛等；B 类 IT 人才外包：业内「八大外包」中软国际/软通动力/文思海辉(现中电金信)/东软/博彦/法本/京北方/佰钧成等；C 类区域中小服务商不给名单给识别特征）。
  - **定位是「核验触发器」而非「判定依据」**——这是与红线 R6 的一致性要求：在名单上 ≠ 该岗位是外包（这些公司自己也招自有员工），不在名单上 ≠ 是自有岗。
  - 附**①权威核验入口**：各地人社局官网依《劳务派遣行政许可实施办法》（人社部令第 19 号）第二十二、二十三条**年度核验公示的「劳务派遣单位名单 / 人力资源服务机构名单」**——政府行政许可产物、逐地覆盖到区县、不营销包装，比任何网络名单可靠。
  - 附**维护纪律**（季度复核 / 新增须附来源 / 禁止收录匿名爆料类「避雷名单」/ 更名 30 天内更新）与**中立表述纪律**（不评价优劣、不贬损、不排序）。
- v1.1.0（2026-09-22）：**从单一流程升级为三模式 Skill**，新增两项一等能力。
  - **模式 B · 岗位能力自查**：新增 [references/capability-model.md](references/capability-model.md)。心脏 = **能力项 × 行为锚定等级(BARS L0–L4) × 证据件** 三联锁，核心机制是**证据强度降级规则**（证据弱 → 降 1 级；证据无 → 记 L0–L1 并标「待补证据」）——用来把「我觉得我会」逼成「我能拿出来」。目标等级按硬性(3)/软性(2)/加分(1) 分档，**禁止按理想拉满**（那会生成一堆假差距）；输出必须含「**假差距**」一栏，把时间预算还给真差距。等级禁止用「了解/熟悉/精通」（无法被旁观者验证）。
  - **模式 C · 外包名单维护**：`outsourcing-suppliers.md` 升级为**货架式活文档**——状态总览（取证日/下次复核/条目数/状态）、**三条触发条件**、全量复核流程（含批量发现本地服务商的官方入口）、**单条追加 schema（10 个必填字段，含「是否同时是甲方雇主」这道防一刀切闸门）**、变更流程（保留旧名做别名、不删条目只改状态）、**变更日志（只追加）**。
  - **架构决策（值得记录）**：能力自查**没有**做成独立 Skill。理由：① 它**不产出「做不做」的判决**，不符合本仓库"调研 Skill"的定义（调研 Skill 的成功标准是「用户敢照着它花钱或停手」）；② 它是心脏 B（可迁移证据链对账）的**上游输入**，独立建会让 AUDIT 失去能力模型支撑，或造成两份重复；③ 它与模式 A 共享同一套 R1 隐私边界（自查对象只能是本人或明示虚构画像）。**保留独立可用性**：用户可只跑模式 B，不跑市场调研。
  - **什么情况下才该抽出去做独立 Skill**：当它需要被用于**团队能力盘点 / 编制规划**这类与「岗位调研」无关的场景，且届时能提出与现有 Skill 不同的心脏时。现在抽出来是过早抽象。
