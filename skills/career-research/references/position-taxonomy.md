# 岗位图谱构建与取证入口（Position Taxonomy）

> **用途**：`career-research` Step 1 MAP 的深度资料。
> **铁律**：**只给查证入口 + 要求现场取证，禁止写死任何数字**（岗位数量、在招量、增长率、薪酬一律会变）。
> 写死的岗位列表会在下一次调研时变成假证据。

---

## 一、为什么岗位图谱要「官方锚点 + 市场用法」双取

单取任何一侧都会失真：

| 只取官方 | 只取招聘平台 |
|---|---|
| 有权威定义与职业编码，但**滞后于市场**——新岗位往往先在企业 JD 出现，几年后才入大典 | 反映实时需求，但**岗位名极度不稳定**：同一批技能在不同公司叫 5 个名字，且带大量营销通胀 |

**两者不一致的地方，就是最有价值的证据**——它直接说明「岗位名在蒸发 / 通胀 / 被折叠」。

> 实测案例（2026-09-21）：「生成式人工智能系统应用员」在 2024-07 由人社部作为新职业发布（职业编码 4-04-05-13，有官方定义与 7 条主要工作任务）；而市场上同一批技能散落在「AI 应用开发工程师」「AI 产品经理」「AI 解决方案架构师」等十几个岗位名里，且独立岗位名「提示词工程师」在收缩（③二手线索，需现场核验）。

## 二、官方锚点：查证入口

| 来源 | 拿什么 | 入口 | 证据等级 |
|---|---|---|---|
| **人社部新职业公告** | 新职业名单、职业编码、职业定义、主要工作任务 | 人社部官网 / 中国政府网 `gov.cn` 政策文件库；搜「新职业 公示」「职业分类大典」 | ①权威 |
| **国家职业标准**（职业技能标准） | 职业编码、职业技能等级（五级/四级/三级/二级/一级）、**普通受教育程度**、培训参考时长、**申报条件（工作年限）**、工作要求 | `osta.org.cn`（技能人才评价工作网）职业标准栏目 | ①权威 |
| **《国家职业分类大典》** | 职业编码、所属大类/中类/小类、上下游职业关系 | 人社部发布版本 + 大典查询入口 | ①权威 |
| 地方人社 / 技师学院认定公告 | 申报条件的地方执行口径、报名材料清单 | 各地人社局官网、技师学院官网 | ②专业（口径互有差异，需注明） |

**检索语句模板**：
```
"<职业名>" 新职业 人社部 职业编码 定义
"<职业名>" 国家职业标准 职业技能等级 申报条件
site:osta.org.cn "<职业名>" 国家职业标准
"<职业名>" 国家职业分类大典 编码
```

**从国家职业标准里必取的四个字段**（这四个是别处拿不到的权威口径）：

| 字段 | 为什么值钱 |
|---|---|
| **普通受教育程度** | 官方口径的最低学历门槛。它通常**远低于**企业 JD 要求——两者之差就是「法定门槛 vs 市场门槛」的真实落差 |
| **职业技能等级** | 五级制（初级工→高级技师），对应职业发展的官方阶梯 |
| **申报条件（累计从事本职业或相关职业工作满 N 年）** | 官方口径的**年限门槛**，且明确写「本职业**或相关职业**」——这正是 `relevant_only` 开关的现实依据 |
| **职业定义 + 主要工作任务** | 官方版「岗位职责」。写职责卡时以它为骨架，再用 JD 补市场化的具体工具与交付物 |

## 三、市场用法：查证入口

| 来源 | 拿什么 | 证据等级 |
|---|---|---|
| **企业官方招聘页 / 校园招聘官网** | 岗位职责、任职资格、学历、工作年限、工作地点、招聘人数、发布时间 | ②专业 |
| **国聘 / 国企招聘平台**（如 `iguopin.com`） | 国企口径的硬门槛（学历、年限、专业限制、报名截止） | ②专业 |
| **高校就业指导中心发布的 JD**（如 `job.tiangong.edu.cn`、`jyzx.scut.edu.cn`） | 校招口径：学历、专业、薪资区间、城市 | ②专业 |
| 主流招聘平台的岗位聚合 | 城市分布、岗位名变体、在招量趋势 | ②专业（聚合口径需注明平台） |
| 行业报告 / 上市公司财报 | 行业用人趋势、薪酬带宽 | ②专业 |
| 转行自媒体 / SEO 博客 / 转述的海外薪资数据 | **只能当线索** | ③二手 |

**检索语句模板**（英文短关键词命中率更高，中英文都要试）：
```
"<岗位名>" 岗位职责 任职要求 招聘 <当前年份>
"<岗位名>" 任职资格 学历 工作经验 工作地点
"<岗位名>" job description requirements <year>
"<岗位名>" 裁员 缩招 岗位消失 劝退          # 搜失败比搜成功值钱
"<方向>" 新职业 人社部                      # 找官方锚点
```

## 四、岗位健康度：四档判据

岗位清单表里每一行的「健康度」必须给出判定依据，不许凭感觉：

| 健康度 | 判据（满足其一即可，须附来源） |
|---|---|
| **扩张** | 近 1–2 年被列入官方新职业 / 新工种；或多个独立雇主的 JD 数量明显增加；或行业报告点名增长 |
| **稳定** | 长期存在于职业分类大典，JD 数量无明显方向变化 |
| **萎缩** | 独立岗位名的 JD 数量下降；或岗位职能被明确折叠进别的岗位（原岗位名在头部公司招聘页消失）；或行业报告列入「at-risk」 |
| **⬜ 未取证** | 搜不到任何 ①/② 来源。**不得因此判稳定** —— 未取证必须计入差距清单 |

> **反通胀纪律**：岗位名的热度 ≠ 岗位需求。媒体热炒的岗位名（常伴随夸张薪资传闻）往往是通胀最严重、也最先蒸发的那一批。判健康度时，**优先看雇主侧的 JD 数量与岗位名变化，而不是媒体声量**。

## 五、岗位清单表的字段规范

| 字段 | 填法 |
|---|---|
| `post_id` | P01、P02 … 稳定不变，供 JSON 与后续引用 |
| `岗位名` | 取**市场上最通用**的叫法；若与官方职业名不同，两者都写 |
| `别名/曾用名` | 必填，可空但需显式写「无」。别名是「岗位名蒸发」的直接证据 |
| `层级` | 核心岗（方向的主战场）/ 邻近岗（技能可迁移的落点）/ 支撑岗（配套职能） |
| `一句话定位` | **动词开头**，说清这个岗产生什么交付物，不写「负责相关工作」这种空话 |
| `上游 / 下游` | 谁给它输入、它交付给谁。用来判断可迁移入口 |
| `健康度` | 扩张 / 稳定 / 萎缩 / ⬜未取证 + 依据 |
| `证据等级 + 来源 + 查证日期` | 每行必填 |

**停止条件**：列满 **≥6 个**（核心 + 邻近 + 支撑）即停手。岗位图谱会无限膨胀，穷举是检索预算的黑洞。

## 六、常见失败模式

| 失败模式 | 症状 | 修法 |
|---|---|---|
| 只写岗位名不写别名 | 看起来很全，实则漏掉正在改名的那批 | 别名列为必填字段 |
| 官方名 = 市场名 假设 | 用大典里的职业名去搜 JD，什么都搜不到 | 双取，不一致处显式记录 |
| 健康度凭印象 | 写「热门」但无来源 | 健康度必须附来源，无来源即 ⬜未取证 |
| 岗位越列越多 | 15 个岗位，检索预算烧光 | ≥6 个即停，用命中矩阵筛 |
| 把培训广告当权威 | 引用机构招生页的「月薪 X 万」「人才缺口 X 万」 | 招生/培训机构页是 ③二手，只能当线索 |
