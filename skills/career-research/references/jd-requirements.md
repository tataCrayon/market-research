# 岗位职责与任职要求取证清单（JD Requirements）

> **用途**：`career-research` Step 2 PROFILE（心脏 A）与 Step 3 DRILL 的深度资料。
> **铁律**：每条字段必须来自**真实来源 + 查证日期**。禁止用「行业通用要求」「众所周知」填空——那是记忆冒充检索。
> **禁止写死**：薪酬、通过率、在招量、具体年限要求一律现场取证。

---

## 一、岗位说明书卡：字段字典

| 字段 | 规范 | 常见偷工方式（禁止） |
|---|---|---|
| **职责**（4–8 条） | **动词开头** + 宾语 + 可核验的交付物。例：「负责基于大模型 API 的业务应用系统设计与开发交付」 | 「负责相关工作」「协助完成其他任务」 |
| **任职要求·硬性** | 写在 JD「任职资格/任职要求」里、**不满足即淘汰**的项：学历、年限（含是否限「相关」）、专业、从业资格、城市 | 把硬门槛挪进「加分项」淡化 |
| **任职要求·软性** | 可议、可证明能力替代的项：沟通能力、学习能力、协作 | 把年限/学历默认为软性 |
| **任职要求·加分** | 明确写「优先」「加分」「者优先」的项 | 把加分项写成必需项，人为抬高门槛 |
| **工具栈** | 具体技术/工具名，区分「必须」与「了解即可」 | 罗列一堆名词不分主次 |
| **典型交付物** | 这个岗产出什么（系统、文档、模块、报告） | 空着不填 |
| **考核指标** | 试用期考核 / KPI / 交付节奏 | 空着不填 |
| **年限带** | `min-max` + **是否限「相关岗位年限」**（关键） | 只写「3-5 年」不写是否相关 |
| **城市分布** | 逐岗取证的实际工作地列表 | 默认「一线城市都有」 |
| **学历门槛** | 层级 + **软/硬判定** + 是否限专业 | 默认「本科够用」 |
| **薪酬带宽** | 区间 + 币种 + 来源 + 日期；无 ①/② 来源即 ⬜未取证 | 引用二手转述的海外薪资 |
| **来源 + 查证日期 + 证据等级** | 每条必填 | 只写「据招聘网站」 |

---

## 二、三级拆分：软硬怎么判

**判定规则（按顺序走，任一命中即判硬）**：

1. JD 原文用了「**须**」「**及以上**」「**要求**」「**必备**」「**须具备**」+ 具体数值（学历层级、年限数、专业名、证书名）→ **硬**
2. JD 原文用了「**优先**」「**加分**」「**者优先**」「**有…经验更佳**」「**熟悉…者优先**」→ **加分**
3. 介于两者之间、且可用作品/业绩证明替代 → **软性**
4. **判定不出 → 写 ⬜未取证**，禁止默认软性

**还要额外判「是否限相关」**：

| JD 原文 | 判定 | 对命中矩阵的影响 |
|---|---|---|
| 「3 年及以上工作经验」 | 不限相关 | `years_total` 计入 |
| 「3 年及以上**相关**工作经验」 | 限相关 | 只有 `years_relevant` 计入——**这是转岗者最常见的隐性硬门槛** |
| 「有物流行业 AI 场景落地经验者优先」 | 加分（行业限定） | 不淘汰，但影响竞争力 |

> `filters.years_of_experience.relevant_only` 这个开关就是为这条准备的。**默认 true**（保守），只有取证确认「不限相关」时才改 false。

**学历的额外判定**：
- **法定门槛**：国家职业标准里的「普通受教育程度」（①权威，通常是高中/初中毕业）
- **市场门槛**：企业 JD 里的学历要求（②专业，通常远高于法定）
- 两者都要记。**差值本身就是重要发现**（说明这个岗的实际筛选逻辑不在法定层面，而在雇主层面）

## 三、 Step 2 PROFILE 的交叉纪律

**至少 3 份 JD 交叉**，且必须覆盖不同雇主类型，否则口径单一：

| 雇主类型 | 为什么必须覆盖 |
|---|---|
| 校招 JD | 暴露**学历/专业的硬底线**（校招门槛最刚性） |
| 社招 JD（民企） | 暴露**年限与技能的市场真实要求** |
| 社招 JD（国企/央企） | 暴露**最刚性的门槛**（学历、专业、年限常白纸黑字 + 报名截止） |
| 中小公司 / 非一线城市 JD | 暴露**城市分布**与门槛弹性（一线大厂的 JD 不代表全市场） |

交叉后要显式区分：
- **这家公司特有**（如「熟悉 MES/SCM 系统」「有物流行业经验」）
- **行业通用**（如「熟悉 RAG」「掌握至少一门后端语言」）

**只有行业通用项才能进「任职要求·硬性」**；公司特有项进加分项或备注。

## 四、Step 3 DRILL 深钻：额外四块

| 块 | 怎么取 | 检索语句 |
|---|---|---|
| **典型一天 / 一个迭代** | 从业者自述、技术博客、岗位复盘 | `"<岗位名>" 一天 工作 日常 复盘` |
| **常见淘汰原因** | **搜失败报告比搜成功案例值钱** | `"<岗位名>" 面试 挂 被拒 劝退 踩坑` / `"<岗位名>" 离职 转岗 后悔` |
| **晋升路径** | 职业标准的技能等级阶梯（①）+ 从业者分享（③线索） | `"<岗位名>" 职业发展 晋升 路径 高级` |
| **可迁移入口** | 从哪些邻近岗能切进来（看岗位清单表的上下游 + JD 里的「相关职业」表述） | 国家职业标准里的「相关职业」定义（①权威） |

> 国家职业标准里通常有一段「**相关职业**是指……**相关专业**是指……」——这是**权威口径的可迁移入口清单**，别处拿不到，必取。

## 五、检索语句模板（心脏 A 专用）

```
# 职责与要求（中英文都要试，英文命中率更高）
"<岗位名>" 岗位职责 任职要求
"<岗位名>" 任职资格 学历 工作经验 工作地点 <当前年份>
"<岗位名>" job description requirements responsibilities <year>

# 校招（拿硬底线）
"<岗位名>" 校招 应届 学历要求 专业要求
# 社招（拿市场真实要求）
"<岗位名>" 社招 3-5年 任职要求 本科
# 国企（拿最刚性门槛）
site:iguopin.com "<岗位名>" 任职要求
# 官方锚点
site:osta.org.cn "<岗位名>" 国家职业标准

# 失败侧（最值钱）
"<岗位名>" 劝退 裁员 缩招 岗位消失
"<岗位名>" 面试 被拒 挂了 复盘
"<岗位名>" 离职 后悔 转行
```

**检索预算**：Step 2 PROFILE 至少占总额的一半。人会本能地先搜「这个方向前不前景」（顺手、有成就感），回避逐岗翻 JD（枯燥、要翻很多页）——**而判决几乎全部建立在 JD 上**。

## 六、反记忆冒充检查（写完自查）

- [ ] 每条任职要求后面都有来源链接吗？没有的删掉或标 ⬜未取证
- [ ] 有没有出现「众所周知」「行业通用」「一般来说」这类无源表述？有就补证或删
- [ ] 薪酬数字有 ①/② 来源吗？只有 ③二手转述的，标 ⬜未取证并**移出判决理由**
- [ ] 年限要求写清「是否限相关」了吗？
- [ ] 学历是法定门槛还是市场门槛？两者都记了吗？
- [ ] 硬门槛是抄 JD 原文判的，还是凭「应该可以放宽」判的？
