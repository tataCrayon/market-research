# 游戏立项调研——立项定生死，三道独立筛子：玩法成立 × 版号放行 × LTV≥CPI

> 本仓库其余调研 Skill 的起点是「已经决定要做了，怎么把它做对」，**游戏立项前这一段一直是空档**。
> 本 Skill 补的就是这一段：从「我想做一个 X 游戏」到「决定做 / 不做 / 先验证什么」。
>
> 它不是通用商业调研（那种一搜一堆），只做一件事：**游戏/小游戏产品立项**。
> 通用调研假设「产品做出来就能卖」，但游戏的真实世界里有三道**独立**筛子——
> **玩法成立**（用户真留得住、真觉得好玩）、**版号放行**（能合法开付费）、**LTV≥CPI**（能回本）。
> 任何一道不过都该在立项阶段给方向性结论，不能「以后再说」。v1.0 只硬方法化了后两道；**v1.1 起三道全部硬方法化**：版号与买量是心脏（上 / 下），玩法成立是第三筛子（PLAY），并补「验证阶梯（PROVE）」——最便宜的验证必须先测需求、再花钱建。

## 何时用 / 何时不用

**用**：有一个明确游戏想法、要判断要不要立项目；调研某品类游戏格局；版号与买量可行性排查；竞品深挖找玩法楔子；想用最低成本先验证需求/玩法；上线前排查硬性阻塞。

**不用**：
- 通用技术 / 想法体检 → `idea-vetting`（用户级技能，找「有没有人已经做过」）
- 已决定做，把想法框成设计目标 → `game-design-goal-framing`
- 已决定做，估**研发预算**（做出来花多少钱）→ `game-dev-budget-estimator`
- 已决定做，写设计文档 / UI → `game-design` / `game-ui-design`
- 移动端 App / 小程序（非游戏）立项 → `app-market-research`（心脏是三端平台约束，本 Skill 不覆盖）

## 硬信念（六条，违反即报告作废）

1. **判决必须落地**。禁止以「值得考虑」「看情况」收尾。必须落到五选一，且每个判决附「最值钱的一步 + 最便宜的验证 + 放弃信号」。
2. **证据分级**。①权威 = 国家新闻出版署(NPPA)/ 微信开放社区 / Steam 官方文档；②专业 = DataEye、七麦、伽马数据、游戏工委、上市公司财报、Zukowski 基准；③二手 = 版号代办机构与 SEO 博客——**只能当线索，不得当结论**。搜索版号问题时前几条几乎全是代办营销页，且互相矛盾，这是本 Skill 最常踩的坑。
3. **未取证 ≠ 没问题**。版号口径 / 分成比例 / CPI 基准 / 留存基准查不到就写「未取证」并计入风险；默认「没问题」是调研里最贵的错误。
4. **反谄媚**。「❌ 放弃」和「⏸ 卡合规」是常态判决之一，用户的热情不该影响结论——预算该听证据的。
5. **三道独立筛子**：**玩法成立 × 版号放行 × LTV≥CPI**。立项阶段必须给方向性结论，不能「以后再说」。利润 = (LTV − 买量成本) × 规模（指色网络「生死公式」）。
6. **验证从最便宜开始**（v1.1 新增）：L0 概念测试（¥0）/ L1 可玩切片（¥0）未过时，**不得跳到 L2 Demo / L3 买量烧钱**。先证伪需求再建，是立项阶段最大的省钱纪律。

## 调研循环（8 步）

```
GATE    — 先定战场：国内/出海；平台(微信/抖音小游戏/iOS/安卓国内/TapTap/Steam/主机)；品类(休闲/中重度/独立)
FRAME   — 压成 2-4 条可证伪主张(吸量/留存/LTV≥CPI/版号) + KPI + 致命风险 + 玩法成立预检(Schell build-a-toy 镜)
MARKET  — TAM/SAM/SOM(量级) + 品类饱和度(红海/新品斜率) + 趋势(品类迁移/题材热度/平台风向)
RIVAL   — 竞品分层 → 七层情报 → 对比矩阵(含"版号状态"行) → 楔子(玩法融合/经典二创/情绪革新/榜单变体)
GATEWAY — 版号与合规硬约束(心脏·上)：版号口径/IAA vs IAP/内容红线/防沉迷/实名 + 取证纪律 + 延误险
ECON    — 买量单位经济(心脏·下)：CPI×渠道/LTV×留存档位/分成/自然量 → 生死公式 → 盈亏平衡SOM
PLAY    — 玩法成立筛子(第三筛子)：Schell build-a-toy 镜 + L1 可玩切片 playtest，证"核心循环好玩吗"
PROVE   — 验证阶梯(L0→L3) + 平台 KPI 门：最便宜先上，按战场映射 soft-launch/小流量/wishlist 量化阈值 → 升级 VERDICT
VERDICT — 五选一 + 三件套
```

检索预算：**≤20 次**。其中至少 **1/3 必须投给 GATEWAY + ECON 的取证**（版号口径、渠道分成、DataEye/广大大 CPI/LTV 基准）；**至少 2 次投给 PLAY/PROVE 的玩法与验证基准**（Schell 镜、品类留存/ARPDAU、Steam wishlist 基准）。人会本能搜玩法与竞品（有成就感），回避版号、买量与"玩法到底成不成立"——后三者最容易被偷工。

### Step 0: GATE — 先定战场

搜索任何东西之前，先回答「做哪个战场」。这一步不花钱，但省掉后面 80% 的返工。

| 战场 | 合规主逻辑 | 变现主逻辑 | 买量特征 | 验证机制（PROVE 映射） |
|---|---|---|---|---|
| 微信小游戏 | 平台资质（软著+自查；含虚拟支付需版号） | IAA 广告（开发者到手 50%，创意倾斜 70%）/ IAP（安卓道具开发者到手 60%） | 社交裂变降获客，但诱导分享审核收紧 | 自查版 IAA Demo + 小流量买量测 CPI/D1/D7/eCPM |
| 抖音小游戏 | 类似微信，平台资质 | IAA / IAP，分成结构不同 | 内容种草—即点即玩—社交裂变闭环 | 同上 |
| iOS App | NPPA 版号 + App Store 审核 | 应用内购买走平台（苹果税 ~15-30%） | ASO + 投放，CPI 高 | soft-launch(CA/AU/NZ/PH) 读 KPI 门 |
| 安卓国内渠道 | 版号 + 各商店资质 + 普遍软著 | 通道自由度较高 | 买量 + 厂商预装 | soft-launch 或买量实测 |
| Steam / 独立 | 海外无版号（国内发行另论） | Steam 分成 30% | 社区 + 折扣 | 建 Steam 页 + Next Fest Demo 攒 wishlist |

**产出「战场阵」三格**：
- **主战场**：`<战场>`——一句理由（为什么需求密度/获客成本/验证机制最优）
- **副战场**：`<战场 或 无>`——触发条件
- **延后战场**：`<战场>`——为什么现在不做（明文代价）

**有罪推定（本 step 硬闸门）**：「全平台全渠道起手」视为有罪，必须过举证——给出顺序、每端增量成本、复用率。过不了就砍到单战场起手。**注意**：微信小游戏 / 抖音小游戏的版号口径与 iOS/安卓 App **不同**，战场选择直接决定合规路径与验证机制，必须先定。

> 详细取证清单与查证入口见 [references/license-compliance.md](references/license-compliance.md) 与 [references/monetization-economics.md](references/monetization-economics.md) 与 [references/validation-gate.md](references/validation-gate.md) 与 [references/practitioner-review.md](references/practitioner-review.md)（从业者审视八轴实例化，通用协议见 [docs/dual-mirror-review.md](../../docs/dual-mirror-review.md)）。

### Step 1: FRAME — 压成可证伪主张

模糊的想法无法调研。重写成 2-4 条主张，每条必须覆盖「游戏四必要条件」（GameRes《立项定生死》）：**用户清晰 / 体验优势鲜明 / 商业模型自洽 / 团队能驾驭**。落到可执行，须显式回答四件「若为假塌在哪」：

```markdown
主张 1（吸量）：<这个钩子能让目标用户 10 秒内说清"它爽在哪">
  - 若为假：<吸量失败 → 买量 CPI 失控 → 利润公式第一项崩>
主张 2（留存）：<核心循环能让 D1/D7 留存达品类基准>
  - 若为假：<留存差 → LTV 撑不起 CPI>
主张 3（单位经济）：LTV ≥ CPI 方向成立
  - 若为假：<买量越猛越亏，研发越精越死>
主张 4（合规）：<主战场版号/资质口径可过>
  - 若为假：<不能上线或不能开付费>
主张 5（玩法成立·v1.1）：<去掉目标/数值，纯核心循环让人想玩(Schell build-a-toy)>
  - 若为假：<版号能过、CPI 能回本，但没人爱玩，全白搭>
```

同时定三项：
- **KPI 三级**：Demo 期（D1/D7 留存、CPI）、上线 90 天（回本周期、付费率）、12 个月（是否跑通规模）——可度量，禁止「快速增长」。
- **致命风险 #1**：这赛道最常栽在哪（版号卡死 / 买量拖垮 / 头部固化 / 生命周期短 / **核心循环不好玩**），以及对冲动作。
- **团队能驾驭（v1.1 显式）**：列出交付 MVP 所需的关键能力（玩法设计 / 数值 / 美术 / 买量 / 合规 / **内容产能**），逐项标「有 / 缺口」。缺口是真实 kill 原因，不得用「招人就解决」糊弄——标缺口即待办。**须量化「缺口到几个 kill / 验证期上限」**：小团队最致命的不是缺口多，是验证期无限延长变长期填坑，故 FRAME 须给「缺口 ≥ N 个或验证期 > 8 周即二判」硬线（v1.2 从业者审视新增）。
- **一个澄清问**：想法太模糊时只问**一个**问题，得到回答再继续。

### Step 2: MARKET — 规模与品类饱和度

**TAM / SAM / SOM**：只要量级，禁止编高精度数字。有报告（游戏工委/伽马/QuestMobile）→ 引用 + 链接；没有 → 自底向上估。
**品类饱和度单列**（游戏专属）：该品类榜单是否红海、近 3 月新品斜率、头部 MAU 是否固化。头部固化意味着新团队入场门槛抬到原生 App 级别（2025 微信小游戏 28 款 MAU 破千万、畅销榜固化）。
**SOM 门槛**：不是看绝对值，看能不能盖住刚性成本（软著代办 / 买量 / 团队）。算「盈亏平衡 SOM」，若现实 SOM 低于它，Verdict 必须降级。

**趋势 3-5 条**，每条五要素（是什么 / 证据 / 成熟度 / 顺风逆风 / 动作）。游戏专属信号源见 references/monetization-economics.md（七麦、DataEye、微信公开课）。

### Step 3: RIVAL — 竞品深挖

**分层**（四个都列）：

| 层 | 定义 | 数量 |
|---|---|---|
| 直接 | 同一群人同一个玩法同一个题材 | 3-5，深挖前 3 |
| 间接 | 同一群人的不同解法 | 2-3 |
| 大厂/相邻玩家 | 现在不在窄赛道但随时能挤过来 | 1-2 |
| 不玩你的游戏 | 用户继续玩别的解压方式 | 永远计入 |

**七层情报**（前六层通用，第七层游戏专属）：
1. **策略与定位**：它声称解决什么、为谁、**不为谁**（缺口即机会）
2. **玩法与系统深度**：核心循环、复杂度档位、长线内容
3. **变现档位**：IAA / IAP / 混合；免费到哪、付费点卡哪
4. **买量素材打法**：创意方向（真人/AI/剧情）、投放强度（DataEye 在投数、素材量）
5. **用户评价**：每家 **20+ 条评论**，按五类归档（玩法缺口 / 体验卡顿 / 付费冤枉 / 广告太肝 / 上手太难）；归档「被夸最多的三项」= 桌赌注
6. **公司健康与动向**：融资、人数、**近 6 个月更新日志**（真实路线图）
7. **版号与平台状态**（游戏专属）：它有没有版号、在哪些端、各端功能是否等价——不等价处通常是真实缺口

**对比矩阵**：列 = 竞品 + 你方案；行 = 8-12 条决策维度。**必须含「版号状态」行**。空格不知道就留空——留空是待办检索清单，不是猜的内容。

**楔子四法**（来自指色网络实战四种立项方法论）：
- **玩法融合立项**：轻度玩法（吸量）+ 重度/长线内容（回收），如消除外壳 + 模拟经营
- **经典玩法二创**：旧玩法（连连看/打螺丝/水排序）做情绪革新，零学习成本新手感
- **情绪革新**：给旧机制新的情绪反馈
- **榜单变体**：研究榜单 2-3 名变体做了什么差异化改良
楔子公式：`唯一 [品类] 里为 [特定人群] 做到 [具体那件事] 的`。三个测试：用户一眼懂差别？最少守 6-12 月再被抄？你做得出来？

### Step 4: GATEWAY — 版号与合规硬约束（心脏·上）

对 **GATE 选定战场**逐项查。**最易偷工、最决定成败的一步**。

**取证纪律（本 Skill 最重红线）**：
- 每条政策结论必须写 `结论 | 官方链接 | 查证日期 | 状态（✅通行 / ⚠️条件满足即可 / 🔴阻塞 / ⬜未取证）`
- **版号口径冲突是常态**：搜「小游戏 IAA 要不要版号」会得到互相矛盾的代办营销页（有的说纯广告不需要、有的说 2025 起不再豁免）。**多条冲突时，取①权威（NPPA / 微信开放社区官方）；只有③时标 ⬜ 未取证，并变成「打电话/查官方确认」的待办，不得写进判决依据。**
- 查不到写「未取证」计风险；**未取证 ≠ 没问题**
- 答不出「这条在我这个战场/品类上怎么适用」的项 → 标 **🔴 阻塞项**，必须先证伪再往下走；阻塞项不清零，判决不得是「立项」
- 政策会过期：**每次调研必须现场重填**，禁止复用上次结论或记忆数字

**产出「合规快照表」**：

| 战场 | 查项 | 结论 | 出处 | 查证日期 | 状态 |
|---|---|---|---|---|---|

**同时产出「延误险」清单**：版号排队、软著代办、资质办理、账号开通——每项都是日历天数，加总写进 Verdict 的「最值钱的一步」。

### Step 5: ECON — 买量单位经济（心脏·下）

**利润 = (LTV − 买量成本) × 规模**。立项不必精算每档礼包，但必须回答 LTV 与 CPI 的方向。

- **CPI**：按渠道×品类取基准（DataEye / 广大大 / App Growing），**禁写死**，带来源日期。行业 2025：小游戏买量日耗 1.44 亿、在投 5.1 万款(+54%)、素材 5000 万+(+97%)；休闲单用户买量成本高位约 ¥98（需核验）。
- **LTV**：档位 × 留存(D1/D7/D30) × ARPU，分 IAA（eCPM×展示）与 IAP（付费率×ARPPU）算。明确标注哪些是假设（⬜）。
- **渠道分成**：微信小游戏 IAA 开发者到手 50%（创意 70%）、IAP 安卓道具 60%（创意 70%）；iOS 苹果税 ~15-30%。**现场取证**，不得用记忆。
- **自然量比例**：小游戏常靠社交裂变，须显式假设（如 30% 自然量），并说明依据。
- **有效 CPI = 展示 CPI ÷ D1 留存**（小游戏最常见的自欺：只看展示 CPI 不看留存）。

**算「盈亏平衡 SOM」（v1.2 从业者审视：必须含双成本）**：`(一次性研发沉没 + 内容产能成本 + 合规/资质 + 刚性月成本 + 买量投入) ÷ (LTV − CPI) × 规模系数`。**只算运营现金流回正（漏研发沉没）是高估可行性的头号坑**——立项口径须把 3–6 月研发、软著代办、防沉迷开发、长线内容更新产能一并 amort。与市场 SOM 比对，盖不住则 Verdict 降级（涨价 / 换窄定位 / 换战场 / 放弃）。**平台可控变量（自然量占比 / Steam 可见性 / eCPM 季节波动）须当风险加权而非定值假设**：IAA 小游戏自然量随分发权重可一夜归零、eCPM 有 Q4 高 Q1 低季节性，模型须给「自然量腰斩 / eCPM 腰斩」情景测试。

---

### Step 6: PLAY — 玩法成立筛子（第三筛子，v1.1 新增）

**这是与版号、买量并列的第三道独立筛子。版号能过、CPI 能回本，但核心循环不好玩，全白搭。**

用 Schell「Design Lenses」做轻量预检（立项阶段不必精通 100 镜，抓三镜）：
- **Lens 15 The Toy**：去掉目标、数值、进度，纯核心循环——人还愿意上手玩吗？**否 → 核心循环未成立，先改，不要进 ECON/VERDICT 自我安慰。**
- **Lens 18 Flow**：难度曲线是否在第一分钟就让人「再来一局」。
- **Lens 91 Playtesting**：你打算找谁测、问什么。

**动作（L1 可玩切片，¥0，≤1 周）**：paper 或极简可玩原型，跑 **5–10 个目标用户** playtest，观察「是否主动继续玩」「卡在哪」。记录：核心循环有趣吗 / 一眼懂吗 / 想再玩吗。

**产出「玩法成立快照」**：
| 镜 / 观察 | 结论 | 证据 |
|---|---|---|
| build-a-toy：没目标也想玩？ | ✅/⬜/🔴 | playtest N 人 |
| Flow：第一分钟「再来一局」？ | ✅/⬜/🔴 | 同上 |
| 卡点 | <描述> | 同上 |

**铁律**：PLAY 未过时不得主张「玩法成立」。若 PLAY = 🔴，Verdict 直接走 🔧 改方向 / ❌ 放弃（核心循环问题），不要靠「买量能拉来人」自我安慰。

---

### Step 6½: PROVE — 验证阶梯与平台 KPI 门（v1.1 新增）

**立项不必一次烧钱到底。按「最便宜先上」给出验证阶梯，并把 L3 的量化阈值按战场映射好，供 VERDICT「先验证」直接引用。**

**验证阶梯**：
- **L0 概念测试（¥0–几千，无需建）**：fake-door（在现有产品/落地页放「即将上线」按钮测点击率）、concept-ad（5 词卖点+素材小预算投 CTR）、社区 storyboard。验证「吸量主张」。**Zynga 用 5 词 pitch + 广告测点击决定是否建。**
- **L1 可玩切片（¥0，≤1 周）**：见 Step 6 PLAY，证「玩法成立」。
- **L2 封闭 Demo（≤2 周，小预算）**：核心循环 + 留存埋点，测 D1/D7。
- **L3 小流量 / soft-launch（按战场，见下）**：证「单位经济 + 规模」。

**平台 KPI 门（L3，方向性基准，每次重取，来源见 references/validation-gate.md）**：
- **微信/抖音小游戏**：自查版 IAA Demo + 小预算买量实测 CPI/D1/D7/eCPM；有效 CPI = 展示 CPI ÷ D1；D1<30% 停 UA，D7<品类基准（休闲 15–25%）留存不过关。
- **出海/iOS/安卓**：soft-launch 在 CA/AU/NZ/PH，读 D1(休闲40%+/中重35%)、D7(20%/15%)、D30(10%/8%)、ARPDAU($0.05–0.15/$0.10–0.30)；三留存达标 + 变现验证 + LiveOps 压测才升级全球。预算 $50k–120k（产品验证费）。
- **Steam/独立**：建 Steam 页 + Next Fest Demo 攒 wishlist；7,000 = 发布地板（Zukowski 2026）；收入 ≈ wishlist × $5；WL<5k 且弱转化 → 重做。

**量化 kill 阈值（写入 VERDICT 放弃信号）**：D1<30% 停 UA；soft-launch 三留存未达品类基准 → 迭代或砍；Steam WL<5k 且弱转化 → 重做。Supercell ~90% 砍掉率提醒：**砍是生产环节不是失败**。

**验证期 time-box 硬纪律（v1.2 从业者审视新增）**：「先验证」必须带**上限**——L0/L1(¥0) ≤ 2 周、L2 Demo ≤ 4 周、L3 小流量/soft-launch ≤ 4 周，**总验证期 ≤ 8–10 周到期必须二判**（✅立项 / 🔧改方向 / ❌放弃），不得「永远在验证」。小团队最易死在无限验证期——time-box 是退出纪律，不是建议。

---

### Step 7: VERDICT — 五选一

| 判决 | 含义 | 触发条件 |
|---|---|---|
| ✅ **立项** | 三筛子全过（玩法成立 + 版号非阻塞 + LTV≥CPI 方向）且存在可打缺口 | 阻塞项清零、PLAY=✅、盈亏平衡 SOM 可达 |
| 🔧 **改方向** | 某筛子成立但另一筛子要改 | 玩法成立但战场/变现/题材要改；或主战场被版号否但副战场可行 |
| 🧪 **先验证** | 关键主张还没验证 | 按 PROVE 阶梯从 L0 起，先 ¥0 测需求/玩法，再决定 L2/L3 |
| ⏸ **卡合规** | 与版号或内容红线冲突 | 先解除阻塞再谈其他——游戏最常见真实结局之一 |
| ❌ **放弃** | 前提不成立 / 压倒性替代 | 给理由 + 替代方案 |

每个判决必须附三件套，缺一不可：
1. **最值钱的一步**：现在就该做的**单个**具体动作（通常是「先去把版号口径问清楚」或「先做 L0 fake-door 测需求」）
2. **最便宜的验证**：**默认从 L0/L1（¥0）起**，明确验证哪条主张；确需 L2/L3 才上，且标预算
3. **放弃信号**：观察到什么就停手（须含 PROVE 的量化阈值：D1<30% / WL<5k / soft-launch 三留存未达标）

## 红线

- **版号/CPI/分成/留存基准 数字无链接禁出**——没查就写数字，等于让用户在错误地基上投钱
- **版号口径冲突时，只取①权威**——多条代办页互相矛盾，一律标 ⬜ 未取证，不得当结论
- **未取证 ≠ 没问题**——写「未取证」并计风险
- **禁止「全平台全渠道」嘴上通过**——不给顺序与增量成本，不成立
- **判决必须落地**——不许「值得考虑」收尾
- **搜不到 ≠ 没有**——换语言/同义词/榜单入口再下结论
- **反谄媚**——"❌ 放弃"和"⏸ 卡合规"是常态判决之一
- **验证不得跳级（v1.1）**——L0/L1(¥0) 未过时不得跳到 L2 Demo / L3 买量烧钱；先证伪需求再建
- **玩法成立是独立筛子（v1.1）**——版号能过、CPI 能回本，但 PLAY=🔴 时不得判「立项」，核心循环问题靠买量拉不来人

## 常见合理化借口

| 借口 | 现实 |
|---|---|
| "玩法好玩就够了，市场不重要" | 立项四必要条件里商业模型自洽独立存在；好玩≠能回本（GameRes《立项定生死》） |
| "先做出来，版号以后再说" | 版号是付费前置且周期/结果不确定；无版号=不能开内购=无法验证商业模型 |
| "版号肯定能过 / 我们内容比较安全" | 版号结果不确定是行业常识；IAA 与 IAP 口径不同，须现场取证，不得默认 |
| "搜到的代办页说纯广告不用版号，那就不用" | 前几条几乎全是代办营销页且互相矛盾；只取①权威（NPPA/微信开放社区），否则标未取证 |
| "买量以后再说，先打磨产品" | 利润=(LTV−CPI)×规模；CPI>LTV 时研发越精越亏。立项不必精算礼包，但必须回答方向 |
| "TapTap/抖音小游戏不用版号" | 口径随产品形态变，须查当前规则；混淆 IAA/IAP 是常见踩坑 |
| "市场有百亿，肯定能分到" | TAM 是分母，要 SOM 盖住刚性成本（软著代办/买量/团队） |
| "我自己玩过觉得好玩，不用测" | 自己爽≠目标用户留；用 Schell build-a-toy 镜 + 5–10 人 playtest（L1）证"玩法成立"，跳过等于把第三筛子当默认值 |
| "直接做个 Demo 测一下最实在" | Demo 是 L2，要烧钱；先用 L0 fake-door(¥0) 测需求、L1 切片测玩法，不过线不烧钱——这是立项最大的省钱纪律 |

## 与其他 Skill 的关系

| Skill | 关系 |
|---|---|
| `idea-vetting` | 通用想法体检（有没有人做过/技术成熟度）。先过它定方向，再进本 Skill 做市场+版号+买量+玩法 |
| `app-market-research` | 并行不重叠：它是移动端 App/小程序立项（心脏=三端平台约束）；游戏是体验产品，心脏是版号+买量+玩法。"游戏化 App"以本 Skill 为主，发行渠道合规参考其 PLATFORM 简化版 |

## 报告双镜自审（grill-method × practitioner-review）

> 每份 game-research 报告提交前，必须过**双镜**——只过一镜不算完整交付（通用协议见 [`docs/dual-mirror-review.md`](../../docs/dual-mirror-review.md)，本 Skill 八轴实例化见 [references/practitioner-review.md](references/practitioner-review.md)）：
> 1. **grill-method 镜**：审**方法**——流程守住没、有没有更强走法（见 `grill-method` Skill）。
> 2. **practitioner-review 镜（落地镜）**：审**真实世界 survivability**——八轴盲区（成本完整性 / 生产现实 / 团队可持续性 / 平台政治 / 上线后现实 / 机会成本 / 验证动作可行性 / 退出纪律）是否摊开（游戏领域八轴实例化见 [references/practitioner-review.md](references/practitioner-review.md)）。
>
> 实证：喵喵小馆 v1.1 与 草木集 v1.1 两份报告都过 grill-method 镜（判决落地、证据分级、验证阶梯不跳级），但都不过 practitioner-review 镜——暴露**同源软肋**（研发沉没没进 SOM、内容产能缺口未评、验证期无 time-box、平台变量风险加权不足）。本 Skill 已将这 4 处吸收进 ECON / PROVE / FRAME 步（见上方 v1.2 标注）。

## 验证清单

调研完成后自查：
- [ ] 战场阵三格齐全，「全平台全渠道」已过举证或被砍；验证机制已随战场标注
- [ ] 想法压成 2-4 条可证伪主张，覆盖吸量/留存/LTV≥CPI/版号/玩法成立 五件
- [ ] 团队能驾驭能力清单已列（有/缺口），缺口未用「招人就解决」糊弄
- [ ] TAM/SAM/SOM 有方法论 + 品类饱和度单列 + 算盈亏平衡 SOM 并比对
- [ ] 至少 3 家直接竞品做 20+ 条评论归档，有更新日志佐证
- [ ] 对比矩阵含「版号状态」行，空格已转待办检索清单
- [ ] 楔子过四法之一且通过三个测试
- [ ] 合规快照表填满（含状态 ✅/⚠️/🔴/⬜），版号口径若冲突已标 ⬜ 未取证而非当结论
- [ ] 延误险天数已列明
- [ ] CPI/LTV/分成有来源日期，未写死；有效 CPI = 展示CPI÷D1 已算；生死公式算过
- [ ] **PLAY 玩法成立快照已填（build-a-toy/Flow/playtest），未用「好玩」空判**
- [ ] **PROVE 阶梯已按战场给出（L0¥0→L3），量化 kill 阈值已写入放弃信号**
- [ ] 检索预算 1/3 以上投给版号+买量取证，≥2 次投给玩法/验证基准
- [ ] 报告区分「检索到的事实」与「我的推理」
- [ ] 判决五选一，三件套齐全；最便宜验证从 L0/L1(¥0) 起
- [ ] 认真考虑过「放弃」与「卡合规」
- [ ] **双镜自审已过**：grill-method 镜（方法守住）+ practitioner-review 镜（八轴盲区已摊开，见 references/practitioner-review.md）
- [ ] **ECON 双成本已算**：盈亏平衡 SOM 含一次性研发沉没 + 内容产能 + 合规，不止运营现金流回正；自然量/可见性/eCPM 等平台变量已风险加权（给腰斩情景）
- [ ] **FRAME 团队缺口已量化**：能力清单标「有/缺口」且给出「缺口 ≥ N 个 或 验证期 > 8 周即二判」硬线
- [ ] **PROVE 验证期已 time-box**：L0/L1≤2周、L2≤4周、L3≤4周、总 ≤8–10 周到期二判，不得「永远在验证」

## 构建实证

本 Skill 由真实 case（喵喵小馆·微信小游戏合成经营）跑通并复盘后定稿，并经 v1.1 评估优化。

**v1.0 关键教训（2026-09-21）**：
1. **版号口径是头号取证陷阱**——搜「小游戏 IAA 要不要版号」返回的全是代办营销页且互相矛盾，必须升级到①权威（NPPA/微信开放社区）才敢写进判决；否则标 ⬜ 未取证。
2. **买量单位经济是第二道筛子**——2025 小游戏买量日耗 1.44 亿、素材 +97%，CPI 高位，纯靠"玩法好"立项会死在回本。

**v1.1 评估优化（2026-09-21，grill-method 拷问后）**：
3. **原 v1.0 只硬方法化了版号+买量两道筛子，漏了「玩法成立」第三筛子**——用 Schell build-a-toy 镜 + L1 可玩切片 playtest 补上（Step 6 PLAY）。
