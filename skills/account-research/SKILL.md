# 对标账号拆解——动作可抄，数据不可编；拿不到的就写 ⬜

> **为什么存在**：民间拆解框架已经烂大街——定位三件套、选题母题、爆文率、赞粉比，框架本身不稀缺。稀缺的是**纪律**：通用调研和拆解文章都在做同一件事，用看起来专业的框架包装印象——「爆文率 5% 算高」没有出处，「这个号靠情绪价值起家」没有证据，「曝光大概是这样」直接填格。而账号决策里最贵的两个错误恰好都出在数据侧：
> ① **平台特异指标被跨平台搬运**——拿抖音的完播率判小红书是错的，两个平台的指标定义与公开可见性都不同；
> ② **后台数据被当公开结论**——曝光、点击率、粉丝画像明明拿不到，却脑补一个数字填进报告。
>
> **心脏**：**平台特异指标 × 可取证边界（心脏 A）**。
> - 心脏 A（Step 1 DATA）：每条指标必须先标注**取证口径**（公开页 / 仅作者后台 / 第三方工具 / 不可得）与**数据等级**；拿不到写 ⬜ 未取证。**这是本 Skill 的生死线**——小红书数据封闭性强于公众号 / CSDN，公开页可见数据有限，恰是这条纪律的试金石：⬜ 会大量出现，而它们必须被如实记录、计入判决，而不是被「补全」。
> - 心脏 B（诊断模式，v0.3 预留）：漏斗排除（曝光→点击→停留→互动→关注→转化），每层给可观测证据，禁止直接猜「内容不好」。v0.1 不展开。
>
> 找不到心脏就别建这个 Skill——那说明它只是通用调研的换皮。

## 何时用 / 何时不用

**用**（用用户会说的话写）：
- "拆解一下这个小红书账号，我想知道它凭什么做起来"
- "这个对标值得抄吗？抄什么、抄了会不会死？"
- "它的爆文集中在哪些选题上？给我选题母题和占比"
- "帮我建个账号库，按领域占比看清楚我关注的博主都发什么"
- "为什么我的小红书没流量？"（→ v0.1 只能做对标侧的间接诊断；**逐层漏斗诊断是 v0.3 诊断模式**，依赖专业号后台导出，v0.1 不接）

**不用**：
- App / 小程序 / 游戏该不该做 → `app-market-research` / `game-research`（他们管立项前）
- 职业方向 / 岗位选择 → `career-research`
- 内容本身怎么写（选题成文、脚本、排版）→ 不在本 Skill 范围（本 Skill 产出拆解与判决，不生产内容）
- 买哪个数据工具（新榜 / 灰豚 / 千瓜）→ 本 Skill 不卖数据、不做工具选型，只给查证入口
- 爬虫 / 批量采集 / 接口绕过方案 → 红线 R2，直接拒绝
- 对账号背后的真实自然人建档、评分、排序、人肉 → 红线 R1，直接拒绝

## 硬信念（7 条，违反即报告作废）

1. **判决必须落地**。判决集合封闭为五选一：`✅ 直接对标 / 🔧 部分对标 / 🧪 先验证 / ⏸ 只观察 / ❌ 换对标`，每个判决附三件套（最值钱的一步 / 最便宜的验证 / 放弃信号）。**⏸ 不是「再想想」**——它必须带补数据清单 + 时间预算 + 到期自动降级 ❌，否则就是变相的和稀泥。
2. **证据分级**。①权威 = 平台官方规则 / 官方创作者文档；②专业 = 用户手动记录的公开页数据（可复核）、用户自有后台导出、正规媒体调查报道；③-a = 民间拆解框架 / 运营课程 / SEO 博客 / 二手横评；③-b = 匿名社区与评论区传闻（「这个号是刷的」）。**③ 只能当线索，不得当结论**；③-b 只能生成待核验主张 + 反向指标。
3. **未取证 ≠ 没问题**。拿不到的数据写 ⬜ 未取证并计入「数据不可证」统计；⬜ 过多本身就可以触发 ⏸ 判决。默认「没问题」是账号调研里最贵的错误。
4. **反谄媚**。「⏸ 只观察」和「❌ 换对标」是常态判决之一。用户想抄的迫切程度不得影响结论。
5. **平台特异指标不可移植**（本领域专属）。拿抖音的完播率判公众号是错的，拿公众号的打开率判小红书同样错——**每个平台的指标定义、算法口径、公开可见性都不同**。指标必须按平台实例化（见 [references/xiaohongshu-metrics.md](references/xiaohongshu-metrics.md)），跨平台混用 = 报告作废。
6. **数据边界先于分析**（本领域专属）。公开可见 ≠ 后台可得。拆解开始前先逐条划边界：这条指标公开页拿得到吗？后台能导吗？工具有吗？都不行就是不可得。**先划边界再拆解，脑补数据 = 报告作废**。
7. **零爬虫**（本领域专属）。数据只来自**用户可见的公开数据 + 用户手动粘贴 / 截图补充**。小红书反爬严格，用爬虫换样本量是把合规风险转嫁给用户；本 Skill 不提供、不指导、不执行任何采集绕过。

## 模式

| 模式 | 状态 | 输入 | 产出 |
|---|---|---|---|
| **A 对标拆解**（默认，v0.1 唯一建成模式） | ✅ v0.1 | 对标账号（小红书）+ 公开数据 | 四层拆解报告 + 可抄/死亡清单 + 五选一判决 + HTML 可视化 |
| B 账号诊断 | ⏳ v0.3 规划 | 自有账号的专业号后台导出数据 | 漏斗掉点定位 + 改动优先级（**依赖后台导出，v0.1 不展开**） |

**两模式共享**：证据分级、七条硬信念、全部红线、双镜自审、未取证 ≠ 没问题。
**心脏 B 预留给模式 B**：没流量必须沿漏斗逐层排除、每层给可观测证据，禁止直接猜「内容不好」——这是 v0.3 的事，本文档不预写流程。

## 流程（9 步）

> 以下为**模式 A（对标拆解）** 的完整 9 步。

```
STEP 0 SCOPE    — 拆解委托书（输入规范化 + 用途 / 数据边界闸门）
STEP 1 DATA     — 公开数据取证【心脏 A】→ 数据底稿
STEP 2 POSITION — 定位拆解（为谁 / 解决什么 / 怎么变现）→ 定位卡
STEP 3 TOPIC    — 选题拆解（母题聚类 + 占比）→ 选题母题表（占比条数据源）
STEP 4 STRUCT   — 结构拆解（钩子 / 节奏 / 引导 / 标题句式）→ 结构模板卡
STEP 5 MONETIZE — 变现拆解（可见路径 + 成交长短）→ 变现路径图
STEP 6 LEDGER   — 可抄清单 × 死亡清单
STEP 7 VERDICT  — 五选一判决 + 三件套
STEP 8 RENDER   — markdown 报告 + HTML 可视化 + 账号库台账追加 + 双镜自审
```

检索预算：**≤10 次**（站外检索：框架、平台规则、基准区间取证），其中至少 **1/2 必须投给 Step 1**（指标口径与基准区间取证——AI 最爱凭印象写「小红书爆文率 5% 算高」这类基准数字，顺手且看起来专业）。
数据取样另受 time-box 约束：**≤24 小时 / 账号**（1 主拆 + ≤2 陪跑），不计入检索预算，但超时必须以现有样本收口并如实标注样本不足。

### Step 0: SCOPE —— 拆解委托书

**产出物**：一份《拆解委托书》，含：对标账号（名 + 链接 + 账号 ID）、陪跑账号（≤2）、四层是否全拆、样本量（默认 30–50 篇，不少于 10）、检索预算、time-box、**用途声明**（个人创作策略 / 团队内容规划 / 课程案例研究）、**数据边界声明**。

**两道闸门（先于一切数据操作）**：
1. **用途闸门**：若用途含「对真实第三方自然人建档 / 评分 / 排序 / 筛查 / 人肉」→ 立即停止并拒绝（红线 R1）。
2. **数据边界闸门**：`public_only: true` 与 `forbid_crawler: true` 为不可关闭项。任何要求「爬一下更全」的输入，回 R2。

### Step 1: DATA —— 公开数据取证【心脏 A】

**产出物**：《数据底稿》——账号基础数据 + 逐篇内容数据 + ⬜ 清单。

**取样纪律**：
- 1 个主拆账号；陪跑账号 ≤2 个，只记基础数据不逐篇拆。
- 内容样本：账号近 **30–50 篇**（不足则取全部并注明「样本不足 N 篇」），**必须含近 90 天时间窗**——否则无法判断账号处于什么阶段（起号 / 增长 / 成熟 / 衰退信号，v0.1 只如实记录时间分布，不做阶段诊断）。
- 每篇记：标题 + 发布时间 + 公开页可见互动数（以页面实际显示为准）+ 链接。
- 账号层记：粉丝数、简介、可见的合集 / 专栏结构、近期更新频率。

**五件套铁律**：每个数字必须带 **数值 × 取证口径（公开页 / 后台 / 工具 / 不可得）× 数据等级 × 来源链接 × 查证日期**。缺一即 ⬜。

**⬜ 处理流程**：拿不到 → 写 ⬜ 并转「手动补充任务」（请用户贴后台截图 / 专业号导出）→ 24 小时内补充 → 仍拿不到则保持 ⬜ 并计入「数据不可证」统计。**⬜ 不得被估算值、行业经验值、第三方横评填充**（红线 R4）。

指标字典、口径标注流程、基准区间取证规则见 [references/xiaohongshu-metrics.md](references/xiaohongshu-metrics.md)。

**数据从哪来、怎么采、什么时候才允许升级采集手段**，见 [references/data-sourcing-playbook.md](references/data-sourcing-playbook.md)——四层来源协议（公开页手动 / 自有后台导出 / 第三方工具 / 不可得）+ L0 手动采集 SOP + 防封节奏。**默认路径是 L0 公开页手动采集；升级到第三方工具的唯一触发条件是「⬜ 阻塞关键层」且 7 天补数据窗口内拿不到**，「手动太麻烦」不是升级理由。

**这一步最容易整体漏掉**：互动数记了，口径没标——于是「公开看到的赞」和「后台导出的曝光」混在一张表里，后面的拆解全部建立在流沙上。

### Step 2: POSITION —— 定位拆解

**产出物**：《定位卡》。三件套，每项必须带证据来源：
- **为谁**：人群画像（来源：简介自述 + 评论区高频身份词，如「宝妈」「考研党」——取样遵循 ③-b 纪律，≥3 条独立评论才计）
- **解决什么**：核心痛点（来源：评论区求助词 + 爆文主题聚类）
- **怎么变现**：可见路径（证据不足时写「未取证」，详见 Step 5）

**纪律**：定位是**从证据归纳**出来的，不是从账号名猜的。归纳不出就写「未取证」——一个拆不出清晰定位的账号，这件事本身就是 Step 7 判决的输入。

### Step 3: TOPIC —— 选题拆解

**产出物**：《选题母题表》——**这张表同时是 git 式领域占比条的数据源**。

**做法**：对 Step 1 的全部样本做标题 / 封面 / 首图文本聚类 → 归并为 **3–6 个母题**，母题命名尽量用账号自己的语言（不从外部框架硬套）。
每行记：母题名 | 笔记数 | 占比 | 其中爆文数（按 Step 1 数据排序的 Top 20% 锚定——**这是聚类用的内部分档，不是平台爆文定义**；报告若要引用「爆文率」指标，仍按字典 §4 先取证定义）| 代表笔记链接。

**两条纪律**：
1. **归类分歧的笔记单列「未归类」段**显示占比，不得硬塞进某个母题——硬塞会让占比条失真。
2. **「爆文集中在哪些母题」是相关性陈述，不是因果结论**（红线 R6）：只能说「爆文中 X 母题占 Y%」，不能说「做 X 母题就会爆」。

### Step 4: STRUCT —— 结构拆解

**产出物**：《结构模板卡》。

**深拆 3 篇代表笔记**：1 篇数据最好 + 1 篇中位 + 1 篇近 90 天发布。每篇逐层标注：
- **开头钩子**（前 3 秒 / 首图首句：悬念 / 痛点 / 反常识 / 结果前置）
- **中段节奏**（信息点密度、分段方式、视角切换）
- **结尾引导**（引导关注 / 评论 / 收藏 / 点击主页的话术与钩子）
- **标题句式**（句式模板 + 关键词位置 + 数字 / 情绪词使用）

**横向纪律**：对比爆款与平庸篇，找出结构差异。**若差异不存在，如实写「结构未见显著差异」**——为了报告好看而硬编差异，是反谄媚要防的典型偷工。

### Step 5: MONETIZE —— 变现拆解

**产出物**：《变现路径图》（公开可见证据）。

**可见证据类型**：蒲公英报备痕迹 / 橱窗与商品笔记 / 直播 / 课程与知识产品 / 私域引导（群聊 / 引流） / 广告合作口播痕迹 / 账号简介商务联系方式。

每条记：路径类型 | 可见证据（链接 + 查证日期）| 证据等级 | 成交路径长短（内容 → 成交几跳）。

**铁律**：报价、转化率、商单收入属于私域 / 后台数据，**对标拆解几乎必然拿不到** → 一律 ⬜ 未取证。**禁止用第三方横评价格填充**（新榜 / 灰豚的报价区间是 ③-a 且是工具口径，不等于该账号实际收入）。

### Step 6: LEDGER —— 可抄清单 × 死亡清单

**产出物**：两张清单（这是本 Skill 区别于「拆解文章」的核心交付物）。

**可抄清单**：每条 = 抄什么（具体到动作）+ 为什么有效（引 Step 1–5 的证据编号）+ **你的适配动作**（搬到你的领域 / 人设 / 产能后长什么样）+ 成本（时间 / 钱 / 技能 × 预算）+ 时间窗。

**死亡清单**：每条 = 抄了会死在哪 + **失效条件**（时间窗已过 / 依赖团队 / 依赖投放预算 / 依赖资质 / 合规风险 / 与你的产能不匹配）。

**交叉纪律**：每条可抄动作必须能过死亡清单——过不了的不进可抄清单，只进死亡清单。**「建议全抄」是报告作废的标志**：拆解的价值一半在告诉你什么不能抄。

### Step 7: VERDICT —— 判决

| 判决 | 含义 | 触发条件 |
|---|---|---|
| ✅ **直接对标** | 四层拆解均有实证支撑，可抄清单可执行，成功路径在你约束下可复制 | ⬜ 不阻塞任何一层结论；死亡清单无可抄动作的命中项 |
| 🔧 **部分对标** | 账号成功含你无法复制的层（团队 / 投放 / 货盘 / 时间窗），只抄可复制层 | 可抄清单 ≥1 条且均有适配动作；≥1 层判定不可复制 |
| 🧪 **先验证** | 打法可迁移但适配你的领域 / 能力未经证实，先小成本验证 | 可抄动作存在但有效性证据不足（如爆文集中在拿不到口径的母题） |
| ⏸ **只观察** | 公开数据撑不起结论（⬜ 阻塞关键层）或账号处衰退期 / 违规边缘——进观察区，不进对标清单 | 关键层（定位 / 选题）主要依据为 ⬜；或账号更新停滞 / 数据持续走低（如实记录，不下病因结论） |
| ❌ **换对标** | 该账号的成功因素对你不可复制，继续拆解是沉没成本 | 心脏层（如选题 / 出镜形式 / 货盘）与你约束根本冲突，且无邻近替代层可抄 |

**冲突时从严**：⏸ / ❌ > 🔧 > 🧪 > ✅。

**⏸ 的防和稀笼条款（硬性）**：⏸ 必须附——① 补数据清单（缺哪几条、去哪补）② 时间预算（默认 ≤7 天）③ 到期未补齐自动降级 ❌ 并说明换对标的方向。**缺这三样的 ⏸ = 「值得考虑」，报告作废。**

**三件套（缺一不可）**：
1. **最值钱的一步**——现在就该做的单个具体动作（优先选能一次消除最大不确定性的：往往是「拿到某条后台数据」或「按某母题发 3 篇实测」，不是「开始抄」）
2. **最便宜的验证**——默认 ≤1 天（核验类：私信问报价 / 查官方规则页）或 ≤7 天（实测类：发 N 篇看数据）；明确验证哪条主张
3. **放弃信号**——观察到什么就停手（可证伪：如「按母题发 5 篇互动量仍低于对标本底稿中位数」「7 天内补不到关键数据」）

### Step 8: RENDER —— 输出

**产出物**：① markdown 报告（见输出格式）② HTML 可视化（git 式领域占比条 + 账号库页面 + 数据图，模板与 token 见 [references/output-html-template.md](references/output-html-template.md)）③ 账号库台账追加一行（只追加，不改写历史行）。

**双输出纪律**：markdown 与 HTML 的数字必须同源——HTML 里禁止出现 markdown 报告中没有的数字。两版不一致 = 交付未完成。

## 红线

- **判决必须落地**——不许「值得考虑」「看个人情况」收尾；⏸ 不带补数据清单 + 时间预算 + 到期降级 = 作废
- **外部结论必须带真实出处 + 查证日期**——只引用实际检索 / 实际记录的链接；没拿到就写「未取证」
- **未取证 ≠ 没问题**——写 ⬜ 未取证并计入统计与风险
- **禁止用记忆冒充检索**——没有来源的基准区间、报价、比例一律删掉或标 ⬜
- **反谄媚**——「⏸ 只观察」「❌ 换对标」是合法且常常正确的判决
- **R1 隐私红线**：只分析公开内容。禁止收集 / 输出账号背后真实自然人的姓名、联系方式、证件号、住址、雇主可识别信息；禁止对自然人建档、评分、排序、人肉、关联身份。账号是内容策略分析对象，不是人
- **R2 零爬虫**：不提供、不指导、不执行任何爬虫 / 批量采集 / 接口绕过 / 验证码绕过方案。数据只来自用户可见公开数据 + 用户手动粘贴 / 截图补充——小红书反爬严格，采集的合规风险由设计规避，不由用户承担。**操作层（四层来源协议 + 手动采集 SOP + 防封节奏 + 升级路径）见 [references/data-sourcing-playbook.md](references/data-sourcing-playbook.md)**：默认 L0 公开页手动；L1 自有后台导出；L2 第三方工具仅当「⬜ 阻塞关键层」且 7 天补数据窗口内拿不到才启用；账号密码 / Cookie 绝不交给任何第三方
- **R3 指标口径必标**：每条指标必须带取证口径（公开页 / 仅作者后台 / 第三方工具 / 不可得）+ 数据等级；**禁止跨平台移植指标**（拿抖音完播率判小红书 = 作废）
- **R4 基准禁写死**：「多少算正常 / 异常」一律现场取证（① 官方创作者文档 → ② 专业数据工具公开报告 → ③-a 民间框架），附链接 + 查证日期；取不到写 ⬜ 且判决不得依赖
- **R5 第三方工具数据须标口径**：工具显示的数字是工具口径 ≠ 平台口径，引用必须标工具名 + 日期 + 等级；工具横评价格（③-a）不得当账号收入证据
- **R6 相关 ≠ 因果**：对标模式不下病因判决——「爆文集中在 X 母题」是相关性陈述，「数据差 = 内容不行」是 v0.3 诊断模式的事，v0.1 禁止

## 常见合理化借口

| 借口 | 现实 |
|---|---|
| "爆文率超过 5% 就是爆文，行业公认标准" | 没有官方口径，且定义分歧（绝对阈值 / 相对账号中位数 / 分位数）会给出不同结论。基准区间必须现场取证并附链接日期，取不到写 ⬜——凭印象写的基准是报告作废级错误 |
| "曝光 / 点击率后台才有，我按经验估一个填上" | 拿不到就写 ⬜。估值冒充数据比留空更贵：它会让后面四层拆解全部建立在流沙上，还以为自己有证据 |
| "用抖音的完播率模型分析小红书" | 平台特异指标不可移植（R3）。指标定义、算法口径、公开可见性都不同，先查字典再动手 |
| "这个号是 MCN / 团队做的，拆了也没法抄，不用拆了" | 可复制性是**判决输入**，不是**拆解豁免**。照样拆，但可抄清单必须剔除不可复制层，判决落 🔧 / ❌——跳过拆解等于放弃了「知道它为什么行」的机会 |
| "评论区都说这个号是刷的，基本实锤了" | ③-b 传闻只能生成待核验主张 + 反向指标（传闻越密集越要查平台官方处置记录），不得当结论。单帖不算，≥3 帖交叉且跨 ≥1 个月 |
| "爬虫批量跑一遍，样本更大更全" | R2 零爬虫。小红书反爬严格，用爬虫换样本量是把合规风险转嫁给用户。样本不够就如实标注样本不足，那是数据，不是缺陷 |
| "先拆 50 个账号建库再分析" | 1 主拆 + ≤2 陪跑，账号库存的是「已拆解过的账号」速览。穷举是检索预算的黑洞，且每个新账号都该是一份新委托书 |
| "数据工具显示的粉丝画像 / 报价，直接引用" | 工具口径 ≠ 平台口径（R5）。引用必须标工具名 + 日期 + 等级；横评价格是 ③-a，不得当账号收入证据 |
| "这篇笔记数据差 = 内容不行" | 相关 ≠ 因果（R6）。对标模式只记录相关性（爆文集中在哪），病因判决是 v0.3 诊断模式的事 |
| "对标在做的先抄了再说" | 每条可抄动作必须过死亡清单（失效条件：时间窗 / 团队 / 投放 / 资质 / 合规 / 产能）。过不了的不进可抄清单——「建议全抄」是报告作废的标志 |
| "拆解报告越全越好，每篇都拆" | 代表抽样（1 爆款 + 1 中位 + 1 近期）+ 母题聚类即够。全拆是预算黑洞，且会把噪音当信号 |
| "简介写得很清楚，定位不用归纳了" | 简介是账号的自我声明（③-a），定位要从证据归纳（评论区 + 爆文主题）。两者冲突时如实记录冲突——那恰恰是定位卡最有信息量的一行 |
