## 一、一页结论

**一句话定位**：把「对标账号为什么能做起来 / 我的账号为什么没流量」从玄学变成**有证据、有判决**的报告——一个加入 market-research 仓库的新 Skill：`account-research`（账号调研）。

**立项判决：✅ 做，但形态必须修正。**

| 维度 | 结论 |
|---|---|
| 原构想最脆弱的假设 | 「爬取并拆解」——第三方数据 API 约 ¥300–5000/月（③-a 横评线索，2026-10-16 检索，需现场取证），平台反爬与 ToS 合规风险高，**数据供给线不成立** |
| 修正后的形态 | **Skill**（不是爬虫工具、不是 Agent）：公开页数据 + 用户自有后台导出数据 → 判决驱动 |
| 第一用户 | 用户自己——创作发布工作台有「生产管线」（选题→写作→发布），缺「增长拆解」这一环 |
| 心脏（候选） | **平台特异指标 × 可取证边界**：指标跨平台不可移植；拿不到的数据 ≠ 没问题 |
| MVP | 单平台（**小红书**）+ 对标拆解先行 + HTML 可视化（领域占比条 + 账号库）第一版即有 |
| 最大风险 | 数据获取 → 设计上零爬虫即可规避 |

## 二、目标：把三个混合层拆开

原构想混了三层东西，立项时逐一处置：

| 层 | 原说法 | 诊断 | 处置 |
|---|---|---|---|
| 工具层 | 可视化页面、账号库、git 式领域占比条 | 是**产品形态**，依赖持续数据供给，而供给线不成立 | 降级为先 markdown 表格；账号库以「HTML 渲染 + 台账文件」形态保留（v0.1 即有，不建数据库） |
| 能力层 | 拆解、诊断 | 这是真正的核心 | 升格为 Skill 的两个模式 |
| 教学层 | 差异化分析与教学 | 不是独立功能，是**输出的消费形式** | 并入报告结构：「什么可抄 / 抄了会死在哪」 |

### 2.1 sharpen 后的目标陈述

> **对标账号做对了什么，你的账号卡在哪一环——拆解必须给出可照抄的动作和可证伪的放弃信号。**

| # | 子目标 | 输入 | 产出 |
|---|---|---|---|
| G1 拆解 | 看懂一个账号凭什么能做起来 | 对标账号公开数据 | 五层拆解报告 + 「可抄清单 / 死亡清单」 |
| G2 诊断 | 定位自己账号没流量的原因 | 自有账号后台导出数据 | 漏斗掉点定位 + 改动优先级（v0.3） |
| G3 演化 | 看懂账号在不同阶段怎么做的 | 纵向内容数据 | 阶段识别 + 阶段策略对照（v2） |

### 2.2 边界（不做什么）

- 不做爬虫、不做数据采集基础设施（合规 + 成本双重不成立）
- 不生产内容本身（写作归创作发布工作台）
- 不碰产品立项（app / game-research 的职责）
- 不对真实第三方自然人做建档 / 评分 / 排序（对齐 career-research 红线）

## 三、价值评估：值不值得做

### 3.1 对谁有价值

| 用户 | 场景 | 强度 |
|---|---|---|
| **用户自己（第一用户）** | 拆解领域对标账号（第一站：小红书），诊断自己账号的增长瓶颈 | **高**——直接补上生产管线之后的缺口 |
| 准备入场自媒体的人 | 立项前拆赛道头部，判断「现在入场怎么打」 | 中高 |
| 有账号没流量的人 | 诊断掉点 | 高（痛点最痛，也最容易被割韭菜） |

### 3.2 市场现状：两侧红海，中间有空位

- **数据侧红海**：新榜（六平台）、灰豚 / 千瓜（小红书）、蝉妈妈 / 飞瓜（抖音快手）——都在卖「数据」，不卖「判决」；价格 ¥199–5000/月（③-a 横评线索，2026-10-16 检索，需现场取证）
- **内容侧红海**：拆解方法论文章已趋同——定位三件套、选题母题、爆款率、赞粉比……框架本身不稀缺
- **空位**：把这套框架按 market-research 的方法论（封闭判决 + 三件套 + 证据分级 + 双镜自审）做成 **AI 原生 Skill**——与「卖数据的工具」「卖课的博主」都不同构
- 附带价值：拆解报告本身就是内容选题（「我拆解了 XX 账号」是成熟内容格式），可反哺创作发布工作台

### 3.3 与现有 Skill 的关系

| Skill | 管什么 | 边界 |
|---|---|---|
| app / game / career-research | **立项前**：做不做 | 到「启动」为止 |
| account-research（本） | **启动后**：账号怎么拆、为什么没流量、怎么改 | 不碰立项、不生产内容 |

### 3.4 价值判决与放弃信号

- **判决：✅ 做**（Skill 形态，MVP 单平台起步）
- **放弃信号**（出现任一即停手，立项时写入）：
  1. 真实 case 跑完发现「公开数据 + 用户提供数据」撑不起任何一层结论 → 领域只能靠买数据，Skill 形态不成立
  2. 拆解结论与成熟民间框架零差异 → 只是换皮，按仓库铁律不该建
  3. 3 个月内用户自己没有真实使用场景 → 第一用户不成立，降级为纯方法论归档

## 四、能力地图：实现目标需要什么

五层能力栈（③ = 只能当线索）：

| 层 | 能力项 | 知识 / 数据来源 | MVP |
|---|---|---|---|

| L2 指标 | **平台特异性指标字典**：公众号（打开率 / 分享率 / 完读率）、抖音（完播 / 赞粉比）、小红书（赞藏比 / 爆文率）、B站（三连 / 完播）、视频号（转发率） | 平台官方创作者文档优先；民间框架仅 ③-a | ✅ 先小红书（references/xiaohongshu-metrics.md） |

| L3 拆解 | 定位拆解（为谁 / 解决什么 / 怎么变现） | 民间成熟框架实例化 | ✅ |
| L3 拆解 | 选题拆解（近 30–50 条主题聚类 → 选题母题） | 同上 | ✅ |
| L3 拆解 | 结构拆解（开头钩子 / 中段节奏 / 结尾引导 / 标题句式模板） | 同上 | ✅ |
| L3 拆解 | 变现拆解（广告 / 橱窗 / 直播 / 课程 / 私域 + 成交路径） | 同上 | ✅ |
| L3 诊断 | **漏斗排除决策树**：曝光 → 点击 → 停留 → 互动 → 关注 → 转化，每层可观测证据 + 常见病因 | 平台公开算法逻辑 + 实证纪律 | ✅（v0.3） |
| L3 演化 | 阶段识别（起号 / 增长 / 成熟 / 衰退信号） | 待调研 | ⏳ v2 |
| L4 输出 | 结构化 markdown 报告（沿用仓库输出骨架） | — | ✅ |
| L4 输出 | **可视化 HTML（git 式领域占比条 / 拆解数据图 / 诊断漏斗图）** | 自有前端规范 | ✅ 第一版即有 |
| L5 管理 | 账号库（领域归属 / 内容占比 / 更新追踪；HTML 页面渲染 + 台账文件持久化，不建数据库） | — | ✅ 第一版即有（页面形态） |

## 五、形态：Skill，不是 Agent，也不是产品

| 候选形态 | 判断 | 理由 |
|---|---|---|
| 可视化爬虫工具 | ❌ | 数据供给线不成立（见 §一）；且与数据工具商正面竞争 |
| Agent | ❌ | 瓶颈是**方法论**不是执行循环；没有「定期自动跑」的硬需求 |
| **Skill → market-research 仓库** | ✅ | 与仓库使命同构（说不清 → 有判决）；证据分级 / 三件套 / 双镜 / 真实 case 验收全部现成；单技能分发路径已通 |

命名：`account-research`（遵循仓库 `<领域>-research` 约定）。

## 六、心脏、MVP 与路线图

### 6.1 心脏：这个 Skill 的生死线

> 判据：哪一步最容易被偷工、又一旦漏掉就否定整个结论？

- **心脏 A（主）· 平台特异指标 × 可取证边界**：拿抖音的完播率判公众号是错的；把「后台才有的数据」当「公开可得的结论」是更贵的错。**每条指标必须标注取证口径与数据等级，拿不到写 ⬜ 未取证。**（v0.1 实例化：Step 1 DATA 五件套 + xiaohongshu-metrics.md）
- **心脏 B（诊断模式）· 漏斗排除**：没流量必须沿漏斗逐层排除、每层给可观测证据，禁止直接猜「内容不好」。（v0.3 实例化，v0.1 不预写）

### 6.2 MVP 范围

- **平台：小红书（已定盘）**——注意小红书数据封闭性强于公众号 / CSDN，公开页可见数据有限，这恰是心脏 A 的最佳试金石（⬜ 未取证纪律会被真实数据撞出来）
- **模式：对标拆解先行**，自有诊断随后（诊断依赖专业号后台导出，作为 case 2）
- **输出：markdown + HTML 双格式，第一版即含 git 式领域占比条与账号库页面**（账号库存续 = HTML 渲染 + 台账文件，不建数据库）
- **数据：零爬虫**——小红书反爬严格，只用用户可见的公开数据 + 手动粘贴补充
- **真实 case**：一个真实关注的小红书对标账号跑完整流程 → `examples/`（v0.2）
- **验收**：静态验证清单 + 动态重跑（换数据源撞结论）

### 6.3 路线图

| 版本 | 内容 | 毕业标准 |
|---|---|---|
| **v0.1（已完成，2026-10-16）** | SKILL.md 骨架 + 小红书指标字典 reference + HTML 输出模板（占比条 / 账号库页） | 纸面自洽 ✅ |
| v0.2 | 拆解模式 + 真实 case 1（小红书对标账号） | 静态清单全过 + 双镜 |
| v0.3 | 诊断模式 + 真实 case 2 | 动态重跑不改判 |
| v1.0 | 双 case 复盘回写 + 提交仓库 | 按 AGENTS.md §6 自检全过 |
| v2+ | 演化模式、其他平台指标字典、付费数据接口 | 产品化另立项 |

## 七、风险与红线

| 风险 | 严重度 | 缓解 |
|---|---|---|
| 平台数据反爬 / ToS 合规 | 高 | 设计上零爬虫；只用公开可见数据 + 官方导出 |
| 指标基准写死过时 | 高 | 仓库铁律：禁写死，只给查证入口 + 现场取证 |
| 诊断变伪科学（相关当因果） | 高 | 漏斗每层要可观测证据；报告分「检索事实 / 我的推理」两区 |
| 第三方自然人隐私 | 中 | 只分析公开内容；不做自然人建档评分 |
| 小红书数据封闭性强 | 高 | 对标拆解只用公开可见数据；缺口标 ⬜ 未取证转手动补充，不爬虫 |
| 与数据工具商竞争 | 低 | 不卖数据，卖判决 |

## 附录：立项时外部调研发现（2026-10-16，③-a 线索级，实例化时逐条取证）

**B1 民间拆解框架（③-a）**：
- 四层拆解：定位（三件套：为谁 / 解决什么 / 怎么变现）→ 内容（选题母题 + 结构逐秒拆 + 标题模板）→ 数据（粉丝量级 / 更新频率 / 赞评比 / 爆款率 / 评论区热评 = 需求清单）→ 变现（卖什么 / 怎么卖 / 路径长短）
- 对标账号选择三标准：同领域 / 体量适中（几万到几十万粉，百万大号复制不了）/ 近半年快速起号
- 五维度挖掘：基础层 / 内容策略层 / 用户互动层 / 商业变现层 / 发布节奏

**B2 数据源（③-a 横评线索，价格需现场取证）**：
新榜（六平台最全，约 ¥399/月起）、灰豚（小红书最强，¥199–599/月）、千瓜（小红书）、蝉妈妈（抖音 / TikTok，¥299–1999/月）、飞瓜（¥999–3999/月）、B站官方开放平台（免费）。
→ 结论：个人自用买 API 不划算；Skill 的数据策略 = 公开数据 + 用户后台导出。

**B3 对原构想的直接影响**：
- 「爬取并拆解」→ 改为「公开数据取证」
- 「可视化页面 / 账号库」→ 降级 v2（后经 §6 定盘回调为 v0.1 即有：HTML 渲染 + 台账文件，不建数据库）
- 「拆解指标需要研究」→ 已有民间答案（B1），SKILL 内仍需按平台实例化 + 现场取证
- 「诊断标准」空白 → 候选方案为漏斗排除决策树（曝光→点击→停留→互动→关注→转化）

> **v0.1 落地后对方针的两处修正（须回记）**：① 「可视化降级 v2」被 §6 定盘**回调**——台账 + HTML 渲染=data 供给线成立的部分，占比条数据来自报告自身母题表而非持续采集；② 诊断的候选方案「漏斗排除」确立为**心脏 B** 并整体推迟到 v0.3（依赖专业号后台导出，且与对标拆解共享同一套数据边界纪律）。
