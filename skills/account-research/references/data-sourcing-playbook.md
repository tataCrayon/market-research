# 账号数据获取操作手册（account-research · 零爬虫协议 v0.1）

> **本文件是红线 R2（零爬虫）的操作层**：SKILL.md 规定「数据只来自用户可见的公开数据 + 用户手动粘贴 / 截图补充」，本文件回答那个必然被追问的问题——**不爬的话，数据到底从哪来、怎么采、采多少、什么时候才允许升级手段**。
>
> **使用铁律**：
> 1. **先选层再动手**——任何数据操作前，先在本手册 §1 四层协议里定位这条数据属于哪层；层级决定手段与纪律，不决定结论的敢下多重。
> 2. **L0 是默认层**——对标拆解的全部数据默认走 L0（公开页手动）；升级到 L2 必须满足 §4 的触发条件，不是「嫌手动麻烦」就能升级。
> 3. **节奏先于样本量**——采集节奏（分天、限量、遇阻即停）比采集手段更重要：爬虫的风险不只是合规，是它逼出来的高频行为特征本身就会触发风控（§3）。
> 4. **口径标注不受采集层影响**——哪层来的数据，就按 `xiaohongshu-metrics.md` §1 的流程标哪层口径；手动抄的公开页数字 = ② 专业（附链接 + 查证日期），工具截图 = ②/③-a（附工具名 + 日期）。
> 5. **采集记录是证据的一部分**——HTML 存档（默认）/ 原始表格 / 截图、采集日期必须留存（§6）；丢了它们，报告里的数字就退化为「据说」，② 等级不成立。

## 1. 四层数据来源协议

| 层 | 是什么 | 能拿到什么 | 封号风险 | 纪律 | 何时用 |
|---|---|---|---|---|---|
| **L0 公开页手动层** | 用户用自己的小红书账号（或未登录）手动浏览，复制粘贴 + 截图 | 对标账号的标题 / 发布时间 / 赞 / 藏 / 评 / 分享 / 粉丝数 / 简介 / 正文 / 封面文本 / 评论区 | **无**（正常用户行为） | 建表先行、分天取样、遇验证码即停、不翻历史到底（SOP 见 §2） | **默认层**。对标拆解（v0.1 模式 A）的全部数据 |
| **L1 自有后台导出层** | 平台官方创作者服务中心（专业号后台）的数据导出 / 截图 | 曝光 / 点击 / 完播 / 粉丝画像 / 流量来源 / 单篇数据明细 | **无**（官方口径） | 仅限**用户自有或有明确授权的账号**；导出文件注明导出日期；这是第一方自证数据，等级 ② | 自有账号的数据补齐；**v0.3 诊断模式的主场** |
| **L2 第三方工具层** | 新红 / 灰豚 / 千瓜等数据工具的公开查询结果（用户自购账号） | 历史趋势 / 粉丝画像估算 / 对标横向对比 / 部分后台口径的估算 | **中**（风险不在工具本身，在把账号授权交出去） | **只读不授权**：用户自己登录查询、只贴截图/导出件；账号密码 / Cookie 绝不交给任何第三方工具或他人（§3）；引用必须标工具名 + 查询日期 + 等级，工具口径 ≠ 平台口径（R5） | 仅当 §4 触发条件满足 |
| **L3 不可得层** | 以上都拿不到 | —— | —— | 写 ⬜ 未取证，计入「数据不可证」统计；⬜ 阻塞关键层可触发 ⏸ 判决 | 报价 / 转化率 / 对标账号后台数据——对标拆解里这是**常态**，不是失败 |

**层级与结论强度的关系**：L0/L1 数据可直接支撑结论；L2 数据只能支撑到「疑似」（③-a 横评价格禁作收入证据）；L3 的 ⬜ 不得被任何层的估值填充（R4 / R5）。

## 2. L0 手动采集 SOP（对标拆解默认路径）

**适用**：模式 A 对标拆解，样本 = 主拆账号近 30–50 篇（不足 10 篇须声明样本不足），必须含近 90 天时间窗。

**采集方式分级**（人力从高到低，数据质量从低到高——**推荐保存 HTML**）：

| 方式 | 一次动作覆盖 | 50 篇净耗时 | 数据质量 | 定位 |
|---|---|---|---|---|
| **保存网页 HTML**（Ctrl+S，选「仅 HTML」） | 整页 30–50 篇 | ≈2 分钟 | 字段全、零转录误差、自带链接 | **推荐** |
| 截图 | 1 屏 | ≈4 分钟 | 数字靠 AI 读图，有识别误差 | 兜底 |
| 复制粘贴 | 1–3 篇 | ≈8 分钟 | 格式靠后处理 | 兜底 |
| 手动抄数字 | 1 篇 | ≈25 分钟 | 有转录误差风险 | 最后手段 |

> 小红书网页版列表页的 HTML 通常内嵌当页结构化数据（标题 / 互动数 / 发布时间 / 链接），**一次保存即完成几十条的「建表 + 记录」**。保存网页是浏览器原生存存功能——属于人的动作，不触碰 R2；越界的是用开发者工具 / 脚本代存（那已经是程序化采集）。

**SOP 六步**：

1. **选方式并当场存档**：默认「保存网页，仅 HTML」（单文件、AI 解析最友好；「完整」模式带的资源文件夹不留）。铁律：**存档必须当时当地产生**——在浏览的当下按 Ctrl+S，禁止事后补存（事后补 = 记忆补数的变体）。滚动加载是正常浏览行为，可分段进行，每段一次保存。
2. **账号层**：主页存档 1 份起（粉丝数 / 简介 / 合集结构 / 列表首页数据）。分段滚动保存时自然覆盖更多篇目。
3. **逐篇覆盖**：主页滚动分段保存 2–3 次（每滚一至两屏保存一次），合计覆盖近 30–50 篇。**不翻历史到底、不进无关推荐流**——滚动深度按正常用户习惯，别把一个号的历史翻空（风控信号，见 §3）。
4. **深拆 3 篇才进详情页**（1 篇数据最好 + 1 篇中位 + 1 篇近 90 天发布）：各存 1 个详情页 HTML（正文与评论区数据在内），供 Step 2 定位归纳（评论区身份词，≥3 条独立评论才计）与 Step 4 结构拆解。其余样本靠主页存档覆盖，不逐篇进。
5. **分 2–3 天完成**：每天 10–15 篇的量，中途正常刷别的内容（真人不会连刷 20 篇同领域笔记）。遇到滑块 / 验证码：**当天停手**，隔天再继续；连续两天遇阻，该账号本期样本就此收口并如实标注。
6. **打包回传**：全部 HTML 存档 + 采集日期一起交回，命名规范 `<账号名>_<主页|详情>_<YYYYMMDD>_<序号>.html`。采集日期 = 五件套里「查证日期」的来源；HTML 存档 = ② 等级「可复核」的前提（§6）。

**成本校准**：HTML 路径下 30–50 篇 ≈ 2–5 分钟净操作 + 分天节奏。**省人力不省纪律**——保存键必须是人按的；边界不变（§4）。

**AI 侧（数据进表之后，全自动）**：解析 HTML → 提取字段 → 结构化底稿 → 指标计算 → 台账累计 → 异动告警 → 报告生成，管线见 §4.3。解析脚本照真实存档结构写，v0.2 前不预写（§4.3 脚本落点纪律）。

## 3. 防封节奏（比选工具更重要）

**原则：真人行为模型 + 低频 + 可中断。**

| 规则 | 为什么 |
|---|---|
| 分天取样，单日单账号浏览量 ≤ 正常用户量级 | 高频访问是最容易被行为识别特征化的模式——不需要爬虫字样，访问曲线就已经不像人 |
| 用自己的账号登录浏览（未登录亦可，遇阻即停） | 登录态是正常用户的主形态；**禁止为采集新建小号 / 借他人号**——多账号矩阵是平台重点打击形态，且把封号风险转嫁给别人 |
| 遇滑块 / 验证码：当天停手，隔天再试；连续两天遇阻就收口 | 验证码是平台的明确减速带，硬闯 = 把风险等级主动升上去 |
| 禁：爬虫 / RPA / 模拟器 / 群控 / 「一键导出」工具 / 接口绕过 | 这些手段全部把账号置于封号射程内；用它们换样本量，是把合规风险转嫁给用户（R2 原文） |
| 禁：把账号密码 / Cookie / 授权交给任何第三方工具或个人 | Cookie 外借是灰产标准手法，出事时平台追责的是账号主人；L2 层只接受「用户自己登录查询、只回传截图」 |
| 样本不足就如实标注 | 样本量不足是**数据**，不是缺陷；用风险换来的样本量， reports 里的每个数字都带着账号安全的成本 |

> **一条判据**：任何采集动作，如果它要求「比真人更快、比真人更多、比真人更不挑」，它就在封号边缘——不管它叫爬虫、叫工具、还是叫「批量整理」。

## 4. 自动化边界：数据进表前后

> **总则：采集端只能是人，处理端可以全自动。分界线 = 「数据进表」这一刻。** 这一节回答 v0.1.1 之后被追问最多的问题：「手动太麻烦，能不能交给 AI 或脚本，慢一点、模拟真实用户？」

### 4.1 为什么「慢速拟人化脚本」不能进本 Skill

「每天只采几条、速率压到像人」不改变性质，四层理由：

| 层 | 理由 |
|---|---|
| ToS | 平台协议禁止未经授权的自动化采集，**看性质不看速率**——低速只降低被发现概率，不等于合规 |
| 法律定性 | 风控检测的就是「是不是真人」，**「模拟真实用户」是加重情节而非减责**：它书面证明了绕过技术措施的主观故意。快速爬虫还能辩不知情，拟人化脚本没得辩；国内已有非法获取计算机信息系统数据罪的判例 |
| 技术脆弱 | 风控是多维的（设备指纹 / 行为序列 / 账号信誉），无头浏览器本身就在检测名单上；今天能跑的配置，一次平台更新就变成封号器——**Skill 是长期复用资产，不能建在流沙上** |
| 责任归属 | 账号是用户的，脚本是设计者的。跑挂了封的是用户的号——这正是 R2「合规风险不由用户承担」的原意 |

**一个常见混淆点**：「让 AI 去抓公开页」并不比「让脚本去抓」更干净——平台侧看到的都是程序化请求。分界不在执行者是碳基还是硅基，在**请求是否由真实浏览行为产生**。

### 4.2 三条路径的合规分级

| 路径 | 做法 | 分级 | 说明 |
|---|---|---|---|
| **A · 人采 + AI 整**（推荐） | 人每天 5–10 分钟手动采集；AI/脚本负责进表之后的一切 | ✅ | **L0 的日常化形态**，设计见 §4.3 |
| **B · L2 付费工具订阅** | 用户自购新红/灰豚等，自己登录查询、只回传截图 | ⚠️ | **持续追踪的正路**：合规风险由工具商承担（商业实体），用户是查数据的人；引用须标工具口径（R5）。见 §5 升级路径 |
| **C · 拟人化慢采脚本** | 低速率 + 模拟真人行为的自动化采集 | ❌ | **不提供、不指导、不执行**（R2）。「嫌麻烦」「每天只采几条」都不是例外理由 |

### 4.3 日采 + 自动累计管线（路径 A）

把一次性「30–50 篇重采集」拆成日常节奏——这正是 §2 SOP 第 5 步「分天取样」的延伸形态，且更可持续：

```
每天（人，5–10 分钟）          每周/随时（全自动）
├ 正常刷对标账号               ├ 结构化入表（合并多日、去重、按发布时间排序）
├ 新笔记：复制粘贴或截图贴给 AI ├ 指标计算（赞藏比 / 篇均互动 / 近 90 天覆盖检查）
└ 不做任何「加速」动作          ├ 台账只追加累计（账号库）
                               ├ 异动告警 → 列入深拆候选
                               └ 报告 / HTML / 占比条生成
```

**人力感知从「一下午」变成「每天几分钟」，自动化的部分一点没少**——只是全部放在数据进表之后。该部分为纯本地处理，零合规风险，可以按需加厚（异动检测、母题辅助归类、月报生成）。

**异动告警判据（示例，可调）**：某篇互动量 > 当期底稿中位数 × 3 → 列入深拆候选（1 爆款 + 1 中位 + 1 近期的「爆款」位由此自动补位）。倍数为民间框架口径（③-a），阈值随账号体量现场调整，不写死。

**脚本落点纪律**：自动化脚本只处理「数据进表之后」——即用户贴进来的文本/截图。**允许写**：解析粘贴内容、合并表格、算指标、台账更新、告警。**不允许写**：任何直接访问平台域名、模拟点击、接管浏览器会话的代码。v0.2 之前不预写脚本——等真实数据流跑起来，照实际格式写，不纸面造脚本。

## 5. 升级路径：什么时候才从 L0 升到 L2

**默认答案：不升。** L0 + L1 覆盖模式 A 的全部设计场景。升级是例外，且必须走完这条链：

```
L0 采集完成 → ⬜ 清单出现 → 判定「是否阻塞关键层（定位 / 选题）」
  ├─ 不阻塞 → 结案，⬜ 计入统计即可
  └─ 阻塞 → 先走 7 天补数据窗口（⏸ 防和稀泥条款的组成部分）
       ├─ 窗口内靠 L1（自有 / 授权账号后台）或询问号主补齐 → 结案
       └─ 7 天仍缺 → 才评估 L2：买哪个工具、只查哪几个指标、预算多少
            └─ 买了也拿不到 → 保持 ⬜，⏸ 到期降级 ❌ 换对标
```

**三个防漂移规则**：
1. 「手动太麻烦」不是升级理由——触发条件只有「⬜ 阻塞关键层」一个；
2. L2 每买一个工具，报告里必须有一次它的实际引用记录，否则下期不再续（防「买了放着」）；
3. L2 截图按 §5 留存，标工具名 + 查询日期；引用上限是「疑似」，横评价格禁作收入证据（R5）。

**v0.3 诊断模式的天然层**：诊断（漏斗排除）的数据源就是 L1——自有账号的专业号后台导出。这不是升级，是模式 B 的默认入口。

## 6. 采集记录与留存规范

| 项 | 要求 | 为什么 |
|---|---|---|
| HTML 存档（一等证据） | 主页分段存档 + 深拆 3 篇详情页原件，命名含账号 + 日期 + 序号 | 比截图更硬：文本可解析、字段全、零 OCR 误差、自带链接；**报告引用的每个数字必须能在某个存档里找到** |
| 原始表格 | 若走了粘贴路径，保留采集时的 Excel / CSV 原件，不做美化、不删「异常行」 | 异常行常常是报告里最有信息量的行（刷量嫌疑、时间断档） |
| 截图 | 兜底路径使用；命名含账号 + 日期 | 「可复核」是 ② 等级的定义性要求；复核不了就只是听说 |
| 采集日期 | 每条数据带查证日期 | 平台展示项会变——「当期公开页展示什么」须按当期标注，沿用旧口径视为未取证（xiaohongshu-metrics.md §1） |
| 报告与留存的对应 | 报告引用数字必须能在 HTML 存档 / 原始表格 / 截图里找到 | 找不到的数字 = 没有来源，按 R 线删除或标 ⬜ |
