## 一、八轴在账号拆解领域的实例化

| 轴 | 通用质问 | **账号拆解领域的从业者问法** | 判据 |
|---|---|---|---|
| **A. 成本完整性** | 一次性成本算了吗 | 「可抄清单上的动作，成本算全了吗——出镜时间、拍摄剪辑、设备、投流预算、技能学习？还是只抄了一份动作清单，产能账一分没算？」 | 可抄清单每条是否带**成本 × 预算**；只列动作不算成本 → ⚠️ |
| **B. 生产现实** | 长线产能扛得住吗 | 「对标日更 / 周更的 cadence，你蜜月期后扛得住吗？一个人又出镜又剪辑又回评论，第 90 天呢？」 | 是否评估 **cadence vs 实际产能**（把对标频率折算成自己的周工时）；只拆内容不评估产能 → ⚠️ |
| **C. 团队可持续性** | 缺口到几个 kill | 「对标的团队配置（编导 / 拍摄 / 剪辑 / 商务）你几个人？哪些层没有团队根本复制不了？」 | 团队 / 单人缺口是否量化到 **kill 线**（如「出镜 + 剪辑双缺口且 4 周内补不上 → 该层不可复制」）；只列不判 → 🔴 |
| **D. 平台政治** | 平台可控变量风险加权了吗 | 「对标的量有没有吃平台扶持（新类目流量 / 活动加权）？有没有走违规边缘（标题党 / 擦边 / 夸大）？算法与规则一夜变天，它的打法还在吗？」 | 是否把**平台可控变量**（流量扶持 / 规则变天 / 类目兴衰）当风险加权而非定值假设；对标的生存依赖违规边缘 → 🔴 |
| **E. 上线后现实** | 首月好 ≠ 长期好 | 「你拆的是它三个月前的爆文——它**近 90 天**的数据在涨还是在跌？红利期打法在红利退了之后还成立吗？」 | 是否含**近期时间窗数据**（样本必须覆盖近 90 天，见 SKILL.md Step 1）；只拆历史爆文 → ⚠️ |
| **F. 机会成本** | 比过其他选项吗 | 「抄对标的这 3 个月，投你自己的差异化方向上，期望回报谁高？还是只有『抄』这一个选项被评估了？」 | 判决是否比过**「抄对标」vs「做自己的差异点」vs「先不动作」**；只评估抄 → ⚠️ |
| **G. 验证动作真实可行性** | 小团队真做得到吗 | 「说『先发 5 篇测数据』——不出镜的人能抄出镜类对标吗？每天只有 1 小时的人，5 篇要几周？验证动作是不是另一个白日梦？」 | 最便宜的验证是否评估**执行条件**（出镜意愿 / 每日可用时间 / 设备 / 技能门槛）；默认有无限时间 → ⚠️ |
| **H. 退出纪律** | 验证期 time-box 了吗 | 「拆解报告写完，然后呢？没有 deadline 的『开始对标』，标准结局是收藏夹吃灰——报告很厚，号一个没动。」 | 可抄清单是否有**执行窗 time-box（默认 ≤4 周）+ 到期二判**；只给清单不给期限 → ⚠️ |

> **不要求全过。** 八轴是盲区扫描器，每条必须显式标「过 / ⚠️缺口 / 🔴硬缺口 / 不适用」+ 理由，不留空白。

## 二、账号拆解领域的两个补充轴（通用八轴没覆盖）

| 轴 | 从业者问法 | 判据 |
|---|---|---|
| **I. 数据可证性** | 「这份拆解的地基本证吗？四层结论挂在几个 ⬜ 上？公开页只给得到互动计数——曝光、点击率、报价全没有，那你说的『它做对了什么』，多少是证据、多少是猜的？」 | 是否逐层统计 ⬜ 并判定是否阻塞关键层；⬜ 阻塞关键层仍下强结论 → 🔴（正确结局是 ⏸ 只观察 + 补数据清单） |
| **J. 红利时间窗** | 「它是**怎么**做起来的——内容做得好，还是品类早期 + 平台扶持 + 先发占位？同样的动作今天做，还有那个流量池吗？」 | 是否区分**内容能力**与**时间窗红利**，并把红利假设标为可衰减项；把红利当能力抄 → ⚠️ |

> **I / J 两轴是账号拆解领域专属**：I 是心脏 A（平台特异指标 × 可取证边界）的落地镜形态——方法镜看「口径标了没」，落地镜看「⬜ 上的结论你敢不敢执行」；J 是「拆解报告最常见的系统性偏差」：**人们只想抄动作，不想承认成功里有自己复制不了的时间成分**。

## 三、账号拆解领域真实 kill 案例（写报告时要想到这些）

| 现实 | 从业者视角的解释 |
|---|---|
| **违规边缘起量被处置** | 标题党 / 软色情 / 夸大医疗效果的「成功路径」，平台治理一轮就没了。抄它的动作 = 连带风险；识别信号：数据曲线陡但评论区有质疑、内容打擦边球——此信号本身只作 ⬜ 记录「是否存在违规不可证」，不得凭感觉下判（R6） |
| **扶持期红利消退** | 平台捧新类目 / 新形式时给的流量扶持是**短期加权**。红利期账号的数据是「内容 × 扶持」的乘积，拆解只看到内容。红利退潮后同款动作数据腰斩是常态 |
| **MCN 矩阵号被当个人号抄** | 团队号（编导 + 出镜 + 剪辑 + 商务投流）的产能是个人号的 N 倍。拆得再细，抄不动就是抄不动——正确处置是 🔧 部分对标（只抄个人可执行层），不是硬上 |
| **刷量号被当成功号拆** | 互动曲线异常平滑 / 评论水化 / 赞藏结构违背内容性质——数据可证性存疑的账号，拆得越认真错得越远。处置：⏸ 观察 + 按 §5 优先级的核验动作，不是直接引用它的数据 |
| **日更 cadence burnout** | 「先日更 90 天」是最常见的自杀式计划。个人创作者真实可持续 cadence 是周更 2–3 篇；低估产能的代价是断更，而断更比低产更伤账号 |
| **收藏夹吃灰** | 报告写得很厚，动作一个没执行。没有 time-box 和验收阈值的「可抄清单」，结局是在收藏夹里吃灰——H 轴杀的正是这种死法 |

## 四、使用方法

```
STATE   — 一句话说清判决（如「🔧 部分对标」）+ 它依赖的真实世界前提（哪些前提在真实生态里最脆）
ATTACK  — 沿八轴 + I / J 两轴发问；每条攻击必须附「从业者会怎么处理」（推荐动作）
VERDICT — 逐项判：守住 / 补强 / 推翻
COMMIT  — 写下报告要补的章节或字段（回写 SKILL.md 的，进构建实证）
```

**铁律：批评必附货。** 只拆不建等于噪音。每条 ⚠️/🔴 必须同时给替代处理（如「把对标 cadence 折算成自己的周工时再进可抄清单」「给可抄清单加 4 周执行窗 + 到期二判」），否则禁止出口。

**不死磕完美**：个人创作者本就带着产能与资源缺口。目标是「把盲区摊开、把最脆前提标红」，不是逼出零风险报告——尤其是 I 轴：**带着 ⬜ 交付是诚实的，把 ⬜ 填成想象才是事故**。
