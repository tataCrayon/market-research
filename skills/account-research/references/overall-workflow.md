# account-research 整体流程设计（E2E）

> 本文是 account-research 的**端到端流程总装图**：从一个用户提问，到一份带判决的交付物，中间每一步谁来做、做什么、守什么闸门。
> 与 SKILL.md 的分工：SKILL.md 是**纪律与 9 步拆解主干**（方法），本文是**产品级流程**（方法之外，还有采集、回传、解析、交付、持续追踪的管线）。
> 状态：v0.1 纸面设计（2026-10-21），待 v0.2 真实 case 撞。

## 0. 一句话

**人按 6 次 Ctrl+S，其余全自动。**

## 1. 流程全景

```
用户提问          采集（人）            回传              处理（AI 全自动）                交付
"这个号为什么    登录小红书 → 滚动     打包 HTML +        解析 → 结构化 → 口径五件套        报告 + HTML
 能做起来"   →    主页 → Ctrl+S    →   表格/截图    →     → 四层拆解 → 判决 → 双镜    →    + 台账追加
   │                （分 2-3 天）        带采集日期            （本地处理，零平台请求）          │
   ▼                                                                            ▼
 STEP 0 委托书                                                          STEP 8 交付 + 复盘
 （用途/边界闸门）                                                        （⬜ 密度 → v0.2 毕业 or ⏸）
```

七个阶段，两道质量闸门在数据操作之前：

| # | 阶段 | 执行者 | 输入 | 输出 | 闸门 / 纪律 |
|---|---|---|---|---|---|
| P0 | 委托 | 人 + AI | 用户的一句话需求 | 《拆解委托书》 | 用途闸门（R1）+ 数据边界闸门（public_only / forbid_crawler 不可关闭） |
| P1 | 采集 | **人（不可外包给机器）** | 委托书 + 账号链接 | 列表页 HTML × 2-3 + 详情页 HTML × 3 + 采集日期 | playbook §2 SOP：真人行为模型，遇验证码当天停 |
| P2 | 回传 | 人 | HTML 包 + 原始表格 | 本地工作目录的存档（命名含账号 + 日期） | 存档 = ② 等级「可复核」的前提 |
| P3 | 解析 | **AI（本地脚本/读取，零平台请求）** | HTML 存档 | 结构化数据表（发布时间/标题/赞/藏/评/分享/链接） | 只解析已存档文件；禁访问平台域名 |
| P4 | 拆解 | AI | 数据表 + 深拆 3 篇全文 | 数据底稿（五件套）+ 四层拆解（定位/选题/结构/变现） | 心脏 A：口径 × 等级 × 链接 × 日期；⬜ 不得被填充 |
| P5 | 判决 + 双镜 | AI | 四层结论 | 五选一判决 + 三件套 + 方法镜/落地镜 | ⏸ 防和稀泥三件（补数据清单 + 时间预算 + 到期降级） |
| P6 | 交付 | AI | 全部中间产物 | markdown 报告 + HTML 可视化 + 台账追加 | 双输出同源；台账只追加 |
| P7 | 持续追踪（可选） | 人（每天 5-10 分钟）+ AI | 新增笔记 HTML | 台账累计更新 + 异动告警 | 日采管线：互动量 > 中位数 ×3 → 自动列深拆候选 |

## 2. 人机分工总表（自动化的分界线 = 数据进表）

| 环节 | 人 | AI / 脚本 | 为什么这样分 |
|---|---|---|---|
| 登录、浏览、滚动、Ctrl+S | ✅ 只能是人 | ❌ 禁止 | 保存键由真实浏览行为触发才合规；脚本代存 = 程序化采集（R2） |
| HTML → 结构化数据 | ❌ | ✅ 全自动 | 纯本地文件处理，零平台请求 |
| 指标计算（赞藏比/篇均/90 天覆盖） | ❌ | ✅ 全自动 | 同上 |
| 口径标注 / 五件套 | ❌ | ✅ 全自动（按页面实际显示项标公开页口径） | 存档自带来源链接与抓取时点 |
| 四层拆解、母题聚类 | ❌ | ✅ | 方法论主体 |
| 判决、双镜 | ❌ | ✅ | 封闭集合 + 反谄媚纪律 |
| 报告 / HTML 生成 | ❌ | ✅ | 双输出同源由脚本保证 |
| 台账追加、异动检测 | ❌ | ✅ | 只追加，本地文件 |

**人力的总量**：一次性拆解一个账号 ≈ 6 次 Ctrl+S + 打包，净操作 2-5 分钟（对比手抄约 25 分钟）。持续追踪模式 ≈ 每天 5-10 分钟。

## 3. P1 采集端详规（人做的全部事情）

1. 登录小红书网页版 → 进对标主页
2. 向下滚一至两屏 → Ctrl+S（「仅 HTML」）→ 再滚一至两屏 → 再存。**重复 2-3 次**，覆盖近 30-50 篇
3. 深拆 3 篇（数据最好 / 中位 / 近 90 天）进详情页各存 1 个
4. 分 2-3 天做完；遇滑块/验证码当天停手，隔天继续
5. 打包回传（HTML 按 `账号名-页面类型-YYYYMMDD.html` 命名）

**采集方式分级**（人力从低到高的备选，HTML 是默认）：

| 方式 | 单账号耗时 | 数据质量 | 地位 |
|---|---|---|---|
| 保存网页 HTML | 约 2 分钟 | 文本结构化，零 OCR 误差，自带链接 | **默认 / 推荐** |
| 粘贴 + 截图补充 | 约 10 分钟 | 截图需 AI 读图，有误差 | 备选（HTML 存不了的页面） |
| 手抄表格 | 约 25 分钟 | 转录误差 | 最后备选 |

## 4. P3-P6 处理端管线（AI 做的全部事情）

```
HTML 存档 ──▶ 解析器 ──▶ 结构化 CSV ──▶ 指标层 ──▶ 拆解层 ──▶ 判决层 ──▶ 渲染层 ──▶ 台账
              │              │             │            │            │            │
         只读本地文件   五件套补齐    赞藏比/篇均/   四层证据链   五选一+     md/HTML     只追加
         零平台请求      口径=公开页   90天覆盖检查   母题聚类     三件套      同源校验    累计累计
```

**P3 前提验证（v0.2 第一个动作，先于一切解析器开发）**：小红书网页版是重 JS 渲染的 SPA，「列表页 HTML 内嵌可解析数据」是**未验证前提**。验证方式 = 5 分钟探针：登录网页版 → 打开对标主页 → 滚一屏 → Ctrl+S 存「仅 HTML」→ 文本编辑器搜账号名/笔记标题。命中 → 前提成立，照真实格式写解析器；不命中 → 走 §3 降级路径（粘贴 + 截图，约 10 分钟/账号，仍合规）。**探针通过前不写一行解析器代码。**

**脚本落点纪律**（v0.2 前不预写，照真实粘贴/存档格式写）：
- ✅ 允许：解析已存档 HTML、合并表格、算指标、台账更新、异动告警、报告渲染
- ❌ 禁止：访问任何平台域名、模拟点击、接管浏览器会话、批量存档

## 5. 质量闸门清单（流程内置，不靠人记）

| 闸门 | 位置 | 不过的后果 |
|---|---|---|
| 用途闸门（R1 隐私） | P0 | 直接拒绝，不进流程 |
| 数据边界闸门 | P0 | public_only / forbid_crawler 不可关闭 |
| 存档完整性 | P2 | 缺采集日期 = ② 等级不成立，相关数字降 ⬜ |
| 五件套完整性 | P4 | 缺一项即 ⬜ |
| ⬜ 密度检查 | P4→P5 | ⬜ 阻塞关键层 → 判决不得为 ✅/🔧 |
| 死亡清单交叉 | P5 | 过不了死亡清单的动作不进可抄清单 |
| ⏸ 防和稀泥 | P5 | 缺补数据清单/时间预算/降级方向 = 报告作废 |
| 双输出同源 | P6 | md 与 HTML 数字不一致 = 交付未完成 |
| 双镜 | P5-P6 | 只过一镜不算完整交付 |

## 6. 异常与降级路径

| 异常 | 处置 |
|---|---|
| 采集遇滑块/验证码 | 当天停手，隔天继续；连续两天遇阻 → 本期样本收口，如实标注 |
| 样本 < 10 篇 | 声明「样本不足 N 篇」，判决降权 |
| 缺近 90 天时间窗 | 不做阶段判断，只记录时间分布 |
| ⬜ 阻塞关键层（定位/选题） | ⏸ + 7 天补数据窗口；到期未补齐自动降 ❌ |
| 手动补充也拿不到（报价/转化率） | 保持 ⬜，计入「数据不可证」统计，禁第三方横评填充 |
| 想升级采集手段 | 唯一触发条件 = ⬜ 阻塞关键层且 7 天窗口内拿不到 → 才评估 L2 付费工具（用户自购、只读不授权） |

## 7. 持续追踪模式（周采管线，P7）

对标拆解是**一次性深拆**；周采管线是**轻量持续**，两者共用同一台账：

- 人：**每周一次** 20-30 分钟（默认档；日采 5-10 分钟为可选加强档），正常刷对标，本周新出的笔记存 HTML / 粘贴。周频依据：小红书笔记生命周期以天/周计，周频对异动告警的时效损失可忽略，坚持成本约为日采的 1/5
- AI：解析入表 → 台账只追加 → 指标滚动更新 → **异动告警**（互动量 > 该号中位数 ×3 自动列深拆候选）→ 月报（母题占比变化）
- **断流检测**：台账超过 10 天无追加且无告警记录 → 月报显式写「追踪中断，本期数据截至 X 日」——让管线死亡可见，不许静默断流（静默断流比没有管线更坏：用户以为还在追踪）
- 30-50 篇的完整拆解样本 = 周采积累到阈值后自动触发，无需专门采集

## 7b. 判决交付物构成（防 ⏸ 流失）

封闭判决 + ⬜ 纪律的必然结果是相当一部分账号判 ⏸。方法论上正确，产品上「问了半天说再观察」是流失机器。处置：**不改判决纪律，改交付物构成**——三件套（最值钱的一步 / 最便宜的验证 / 放弃信号）在报告中升为**一级区块**，放在结论旁而非附录；⏸ 用户拿到的是「一个 ≤1 天可完成的小实验 + 7 天补数据清单」，不是「等」。

## 8. 产品化路线（流程不变，载体变）

| 阶段 | 载体 | 人的操作 | 自动化的部分 |
|---|---|---|---|
| 现在（v0.1-v0.2） | Skill（AI 对话驱动） | 存 HTML + 打包发给 AI | 解析→拆解→判决→渲染全自动 |
| v0.3 | Skill + 诊断模式 | 同左 + 后台导出 CSV | + 漏斗排除 |
| v1.0+（产品化另立项） | 工具/服务 | 上传 HTML 包 | 同左 + 多账号管理 + 定时报告 |

**第一个产品化组件已经明确**：P3 解析器（HTML → 结构化表）。它是整条管线上唯一「纯工程、零合规风险、输入输出都明确」的环节——v0.2 真实 case 的存档格式就是它的需求文档。

## 9. 本流程的未验证假设与验证顺序（grill-method 2026-10-21 拷问产出）

按「便宜的先行」排序，v0.2 按此顺序撞：

1. ~~列表页 HTML 内嵌数据足以复现全字段~~ → **升级为 v0.2 第一个动作：5 分钟探针**（§4）；不命中则 §3 降级路径自动顶上，前提失败不致命
2. ⬜ 的真实密度不阻塞定位/选题两层（v0.2 毕业判据）
3. 保存 HTML 的 UX 成本（约 2 分钟）用户可接受（P1 的前提）
4. 解析器对真实存档格式足够鲁棒（探针命中后才写，不纸面造）
5. 周采节奏下用户能坚持 ≥1 个月（P7 存活率，断流检测给信号）
