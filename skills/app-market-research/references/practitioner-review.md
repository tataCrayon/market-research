# 从业者审视 · App/小程序实例化（Practitioner Review for App Research）

> **本文件是通用协议 [`docs/dual-mirror-review.md`](../docs/dual-mirror-review.md) 在 App/小程序立项领域的八轴实例化。**
> 通用轴、4 步循环、红线、判定标记一律见共享协议，**本文件只写 App 领域的专属提示与真实 kill 案例**，避免重复。
>
> **视角定位**：一个真把 App/小程序做上线、踩过应用商店拒审、扛过合规复查、见过独立开发散伙的**产品人 / 独立开发者**，
> 拿着你的立项报告问的不是「方法对不对」，而是「**这东西在真实移动生态里能不能活**」。

---

## 八轴 · App/小程序专属提示

| 轴 | App 领域的具体盲区 | 报告里要显式回答的问题 |
|---|---|---|
| **A. 成本完整性** | app 的盈亏平衡 SOM 通常只算**运营年成本**（服务器/SDK/代账），漏：①一次性研发沉没（尤其跨端复用率归零时，第二端要重写）；②合规代办+上架延误的**时间成本**（与研发串行）；③资质硬条件的隐性人力（如药械备案需 2 名药学人员） | SOM 含研发沉没 + 合规时间成本了吗？还是只算「上线后每月花多少」？ |
| **B. 生产现实** | 工具类 App 内容军备竞赛弱，但有两个真实陷阱：①**端能力边界**——小程序受限容器（后台/推送/系统权限）导致上线后核心功能缩水，用户预期落空；②**工程核心难点真实工期**（如 OCR/AI 识别），降级方案（Wizard-of-Oz）验证的是需求不是技术 | 主端容器是否真能跑通核心链路？最脆的工程环节有没有降级验证？ |
| **C. 团队可持续性** | 合规硬条件本身就是团队能力缺口（如「法人+2 名药学人员」对单人开发者 = 不可解）；独立开发者的关键人风险极高 | 能力清单量化「缺这个即不可解」了吗？单人开发的可行性标红了吗？ |
| **D. 平台政治** | 微信类目口径 / 苹果审核准则 / 安卓各商店政策**按季度变**且**各端不等价**；搜索权重、榜单排名是平台可控变量，可一夜变天 | 政策结论带查证日期了吗？自然量/搜索权重当定值假设还是风险加权？ |
| **E. 上线后现实** | 工具类无 eCPM 季节性，但有人均 ARPU 波动、ASO 排名算法调整、竞品降价或巨头下场；「首月好 ≠ 长期好」 | 给了上线后竞争/算法变天的应对动作吗？还是只给静态假设？ |
| **F. 机会成本** | 「三端全做」的隐性机会成本；V1/V2 路径选择（先做无资质版 vs 等资质版）的真实时间差 | 端阵 / V1-V2 路径比过选项间机会成本了吗？还是只定单战场？ |
| **G. 验证动作真实可行性** | Wizard-of-Oz / 小程序 Demo / 落地表单这类 ≤1 天实验，小团队能否真找到 8–10 个目标用户做？没用户池的独立开发者常卡在这 | 最便宜验证的「找用户」动作，团队真做得到吗？ |
| **H. 退出纪律** | app-market-research 已有「最便宜验证 ≤1 天」硬纪律，但缺**总验证期上限 + 到期二判**——独立开发者易陷「永远在调合规 / 永远在找人」 | 验证期有总上限吗？到期必须二判（立项/改/放弃）吗？ |

## App 领域的真实 kill 案例（审报告时对照）

1. **研发沉没没进 SOM**：工具类 App 算「首年需 1000 付费用户打平」，但漏了 3–6 月研发 + 跨端重写成本；一旦主端被平台规则否掉要换端，沉没直接归零。
2. **合规硬条件 = 团队不可解缺口**：药械/医疗/金融类目要求法人主体 + 持证人员，单人独立开发者判「立项」等于骗自己。
3. **端能力边界缩水**：小程序做了「后台定时提醒」，上线发现小程序后台保活受限，核心功能变残次品，差评如潮。
4. **验证期无限延长**：「先打电话确认合规」「先找齐 2 名人员」——这些动作没有 deadline，独立开发者 18 个月还在准备，产品从未上线。
5. **巨头下场**：验证期内京东健康/阿里健康上线同类功能，小团队局部优势被碾压。

## 用法

app-market-research 产出的每份报告，提交前做**双镜自审**——
1. 用 `grill-method` 验方法（流程是否守住、有没有更强走法）；
2. 用本文件（落地镜）验 survivability（八轴盲区是否摊开）。
两份都过，才算完整交付。详见 [`docs/dual-mirror-review.md`](../../docs/dual-mirror-review.md)。
