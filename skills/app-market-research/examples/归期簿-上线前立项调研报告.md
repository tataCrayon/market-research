## 1. 想法拆解（FRAME）

### 核心主张（可证伪）

| # | 主张 | 若为假，塌在哪一层 |
|---|---|---|
| 1 | 中文用户存在「从 DDL 倒推排期 + 随执行进度动态重算」的真实需求，且现有工具没人做好 | **需求不存在** → 塌在需求层 |
| 2 | 倒推算出来的「最晚开始日」，能被**通知临门一脚**兑现，而不是被用户忽略 | **交付不成立** → 塌在交付层（算得准也没人看）。这是本项目工程量最大的部分 |
| 3 | 「不接日历、不往日历写一个字」的节奏线哲学能构成区隔，而非被当成「残缺版滴答清单」 | **定位不成立** → 塌在定位层 |
| 4 | **（本报告新增）AI 功能对首发的价值 < 它的合规成本** | 若为假（AI 是核心卖点）→ 必须走算法备案 + 安全评估，首发推迟 3–5 个月。**项目自身设定 AI 为 L2-lite 默认关闭、BYO key，此条大概率为真** |

### KPI 三级（可度量，禁止「快速增长」）

- **30 天**：至少一家国内安卓商店通过审核并上架；无投放前提下自然下载 ≥ 100
- **90 天**：D7 留存 ≥ 20%；买断付费转化 ≥ 1%（对标 BackDate 中国区 Lifetime ¥38）
- **12 个月**：付费用户 ≥ 300，或明确降级为自用 + 作品（见放弃信号）

### 致命风险 #1 + 对冲

**AI 功能的合规定性**。商店明文要求与「用户自带 API Key」的模糊地带之间存在缺口，最坏情况不是上架被拒，而是**上架后巡检被下架**（此时下载与口碑已投入）。
**对冲**：首发版本关闭 AI 入口 + 商店元数据零 AI 表述 + 隐私政策不提模型服务商。零研发成本，因为 AI 本就是默认关闭的可选层。

| **现金流口径小计** | **≈ ¥4,000** | |
| **研发沉没（v1.1 必计）** | ≈ ¥30,000 | 约 2 个月全职当量，按 ¥15,000/月 保守折算 |
| **含沉没合计** | **≈ ¥34,000** | |

**到手单价**：买断 ¥38（对标 BackDate）。国内安卓商店分成口径 **⬜ 未取证**（见阻塞项 B4）；iOS 侧 2026-03-15 起标准 25%、Small Business Program 12%（Apple 官方①）。保守按到手 **¥25/份** 计。

- **现金流打平**：4,000 ÷ 25 ≈ **160 份**
- **含研发沉没打平**：34,000 ÷ 25 ≈ **1,360 份**
- **现实首年 SOM（100–300 份）对比结论**：

> **现金流可打平，研发沉没打不平。** 按纯商业口径，这个项目收不回研发投入。
> 这与「倒推赛道至今没有一家做出 PMF」的证据是一致的（见趋势 4）。
> **它的合理目标是：自用 + 作品 + 软著 + 可能的小体量口碑，不是生意。**
> 这一条直接决定后面「要不要为商业化注册公司主体」——见 VERDICT 的放弃信号。

### 三类产出

- **桌赌注**（不做就没资格被考虑）：农历支持、提前 N 天提醒、桌面小组件、免费可用、提醒可靠
- **共性缺口**（所有人都在躲或做得糟）：①**不告诉你「最晚什么时候必须开始」**；②**不随执行进度重算**；③要么绑死日历（Motion 系），要么纯倒数（Days Matter 系）——**中间地带是空的**
- **被忽略人群**：中文 + 不信任全自动排期 + 想要「今天该动哪一步」而不是一张填满的日程表的人

### 楔子与三测试

> **唯一一个「不往日历写一个字」、却告诉你「今天该动哪一步」的中文倒推排期 App。**

| 测试 | 结论 |
|---|---|
| 目标用户一眼能懂差别？ | ✅ 「不写日历」与「今天做什么」都是具体可感的 |

## 5. 判决（VERDICT）

# ⏸ 卡合规

**一句话理由**：不是想法不行，而是**首发形态与商店明文规则冲突**——AI 功能（BYO key 且可指向未备案境外模型）落在 vivo / 小米的「AI 生成合成类 / 人工智能」资质要求里，其合规成本（安全评估 ~30 工作日 + 算法备案 1–3 个月）是首发最大的一笔延误险，且一旦带病上架，后续「清朗」巡检的下架风险比不上架更贵。

### 三件套

**1. 最值钱的一步（今天就该做的单个动作）**

> **定下首发形态：提交商店的版本关闭 AI 入口，商店元数据（标题 / 简介 / 截图 / 关键词）零 AI 表述，隐私政策不提模型服务商。**

理由：项目自身 AI 本就是 **L2-lite 默认关闭、BYO key**（README / PROJECT_STATUS 明文），这一刀**零研发成本**，却同时——
① 清零 🔴B1；② 让「单机 App 免备案」路径可用（内蒙古通管局①明确「单机不联网无需备案」，华为文档①提供勾选入口）。

同日并行启动两件事：
- **办电子版权认证**（3–10 工作日，可当天）换上架资格——传统软著 40–60 工作日，时间差一个数量级；正式软著继续办（它对职称 / 作品价值独立于销量）。
- **核对名称三处一致**：软著登记名 / 备案名 / 商店名是否同为「归期簿」。包名 `dev.knowulife.know_u_time` 已锁定 ✅，别在最容易的一项上被驳回。

**2. 最便宜的验证（≤ 1 天，验证主张 4）**

验证的是「BYO key 是否能免责」这条主张。**两个免费动作，任选其一即可出结论**：

- 在**小米开放平台 / 华为 AGC 提一个资质咨询工单**，原文问：「一个默认关闭、由用户自行填入 API Key 调用大模型、数据本地存储不上传的中文效率工具，是否需要提交安全评估报告与算法备案？」
- 或致电**属地省通信管理局 + 属地网信办**，同一问法。

**拿到书面 / 工单答复之前，一律按「需要」来准备（即首发去 AI）。**

**3. 放弃信号（观察到就停手）**

- 若工单 / 电话答复为「凡有 AI 入口即需安全评估」→ **不要等**，直接去 AI 首发，AI 放 V1.1。**绝不因为 AI 推迟上架超过 8 周**。
- Android 上架后 **90 天**：自然下载 < 500 且付费转化 < 1% → **停止商业化投入**（不注册公司主体、不注册商标、不买量、不做 iOS），转为「自用 + 作品集」；软著照办。
- 若安全评估 / 算法备案排期确认 > 2 个月 → AI 永久降级为「本地规则引擎 + 模板匹配」（项目已有 `breakdown_templates` 表与 v4.2 模板匹配，**本就可不依赖大模型跑通拆解**）。

### 验证期 time-box（v1.1 硬纪律）

**总验证期 ≤ 8 周，到 2026-11-19 到期必须二判**（✅ 立项 / 🔧 改方向 / ❌ 放弃）。
不得陷入「永远在调合规 / 永远在找人」——这是独立开发者最常见的死法。
