## 0. 端阵决策（GATE）——这里没有"三端"，只有"四形态"

本产品不是 App/小程序，`GATE` 的自变量不是"微信/iOS/安卓"，而是**交付形态**。形态决定分发、变现、合规与能力边界，比技术选型重要一个量级。

| 形态 | 分发逻辑 | 变现 | 门槛 | 能力边界 | 判决 |
|---|---|---|---|---|---|
| **A. Windows 桌面工具**（Python + 草稿库 + GUI） | 自建下载页、社群、内容导流 | 买断/订阅 | 代码签名、杀软误报、版本适配 | 能读写本地草稿、能碰剪映 GUI；但受协议与版本漂移直接冲击 | **主形态候选** |
| **B. CLI / Agent Skill**（无 UI，命令或 Skill 调用） | GitHub、Claude Code 生态 | 免费引流 / 教学附带 | 无签名、无商店、无支付 | 只出文件（报告/草稿包），零安装成本 | **先验证形态（推荐先跑）** |
| **C. Web SaaS**（上传→云端拆解→下载草稿包） | SEO/内容 | 订阅/按条 | ICP 备案、上传带宽与存储、内容安全义务、参考视频版权 | 摆脱本地 GPU 依赖，但把"版权+内容安全"从用户手上搬到自己头上 | **延后，现在不做** |
| **D. 剪映插件/官方开放能力** | — | — | — | **未检索到剪映面向第三方开放"草稿生成"官方 API 或插件市场** | ⬜ 未取证，按"不存在"处理 |

**端阵决策三格**

- **主形态**：`B 先跑 → A 承接`——先用无分发的 CLI/Skill 验证"拉片报告有人买"，再决定是否为它付 GUI、签名、支付、版本适配的成本。
- **副形态**：`A 桌面工具`——触发条件：**B 形态下 ≥10 份付费报告成交，且 ≥3 位用户明确要求"直接给我草稿"**。在此之前做 GUI 就是把钱烧在没人验证过的壳上。
- **延后形态**：`C Web SaaS`——明文代价：ICP 备案日历时间（⬜未取证，通常按周计）+ 每 GB 上传/存储成本 + 用户上传他人视频带来的著作权与内容安全责任（⬜未取证）。**在单机版跑通付费之前，SaaS 只会把风险放大、把验证变慢。**

> **有罪推定**：若有人主张"桌面 + Skill + Web 三形态一起做"，需先给出顺序、每形态增量成本、以及 B→A 的复用率。本报告给出的复用率判断：**B→A 的 L1/L2 逻辑可复用约 70%，L3/L4 与 UI 需重写；A→C 的复用率低于 40%（推理，非事实）**。过不了这道举证，砍到单形态。

## 1. 想法拆解（FRAME）——四条可证伪主张

| # | 主张（要为真的那句话） | 若为假，塌在哪一层 |
|---|---|---|
| **C1 需求** | 存在一群人，愿意为"看懂参考视频的节奏与手法"付费，且剪映自带模板/一键成片满足不了他们。 | **需求层**：付费意愿为零，模板免费且更快，"迁移节奏"是伪需求。 |
| **C2 精度与成本** | "参考视频 → 剪映合法操作清单"能做到用户认可的准确度（转场/卡点/景别），且单条成本 ≤¥1。 | **产品层**：拆解不准 → 报告不可信 → 用户回到人工拉片，产品无价值。 |
| **C3 地基稳定** | 剪映草稿格式在未来 6 个月内仍可由第三方稳定生成，且不违反剪映用户协议。 | **交付层**：只能交报告不能交草稿；或被迫停售（合规）。 |
| **C4 获客** | 无投放条件下，首年能做到 200–350 单付费（覆盖研发沉没）。 | **商业层**：单位经济不成立，做出来也是自娱自乐。 |

**KPI 三级（可度量，禁止"快速增长"这种词）**

| 周期 | KPI |
|---|---|
| 30 天 | ① 3 份人工拉片样张交付 ② 触达 30 位目标用户 ③ 预付 ≥3 份（¥49/份） ④ L1 原型在 5 条参考视频上与人工标注的转场区间重叠率 ≥70% |
| 90 天 | ① 10 份付费报告交付 ② 单份人工耗时 ≤2h（决定能否规模化） ③ ≥2 位剪辑老师愿意试点 ④ 单条自动拆解成本 ≤¥1 |
| 12 个月 | ① 付费 ≥230 单，或 3 家教学机构年框 ② 剪映版本适配造成的停摆 ≤1 次/季 |

**致命风险 #1 + 对冲**

> **风险**：**地基不属于你**——草稿格式是剪映的私有协议，随版本漂移；用户协议是否允许第三方生成草稿/自动化 GUI 尚未取证（见 §4 阻塞项）。
> **对冲**：把产品价值锚在**报告**（纯文件、零依赖、不可被平台封）而不是草稿（依赖私有协议）；草稿作为"增值附件"，允许它在某个版本上失效而不致命。**这条对冲直接决定了 §5 的判决方向。**

**收入侧与打平点**

| 定价假设 | 净收/单 | 打平所需首年单量 |
|---|---|---|
| 买断 ¥299 | ≈¥254（扣渠道/税费 ~15%） | **≈228 单** |

### 3.1 分层

| 层 | 竞品 | 一句话 |

| **直接**（同一群人、同一问题、同一解法） | ① 剪映自带模板 / 营销成片 ② 剪映自带"智能镜头分割" ③ `capcut-mate` + 通用大模型拼装 ④ `jianying-autocut` 类 Agent | 都在回答"我想让我的片子像那条一样" |

### 3.3 桌赌注 / 共性缺口 / 被忽略人群

- **桌赌注（不做就没资格上桌）**：草稿能在当前剪映版本打开；卡点对齐到帧；转场时长可调；竖屏 1080×1920 模板；有 GUI 或至少一条命令能跑完。
- **共性缺口（所有人都在躲）**：**没有任何产品把"参考视频 → 可核对的剪映操作清单"做成结构化、可交付、可教学的产物**。模板给结果不给解释；拉片课给解释但不可规模化；草稿库给能力但不给判断。三者之间是空的。
- **被忽略人群**：① **剪辑教学者/训练营**——需要批量产出"带截图的案例"，且愿意为省时间付费；② **中级剪辑者**——会剪但不会"读片"，卡在"看不出别人怎么做到的"。

### 3.4 楔子

> **"唯一把任意参考视频拆成『逐秒手法清单 + 剪映里怎么点 + 截图证据』的拉片工具，为剪辑教学者和中级剪辑者服务。"**

| 测试 | 结论 |
|---|---|
| 目标用户一眼能懂差别吗 | ✅ 能。"拉片"是他们的行话，"带截图的逐秒清单"是可感知的交付物 |
| 最少能守 6–12 个月吗 | 🟡 功能守不住（剪映一次更新就可能内置），**但案例库 + 教学渠道 + 版本适配服务能守** |
| 你做得出来吗 | ✅ 只要 L1（拆解）+ L3（核对）就能出报告，**不必先解决 L4 的草稿地基** |

> **关键判断**：楔子成立，但成立的对象**不是 PRD 写的"所有想仿剪的用户"，而是"教学者 + 中级学习者"**。这是 §5 判"改方向"而不是"放弃"的依据。

## 5. 判决（VERDICT）

### 🔧 **改方向**——想法成立，但不能按 PRD 现在的定位和形态做

**理由（三句话）**

1. **需求端被免费替代品压制**：剪映内置模板/营销成片/智能镜头分割已经覆盖了大多数"我想像那条一样"的诉求，PRD 的差异化只剩"解释为什么"——**而"解释"是教学场景，不是大众剪辑场景**。
2. **交付端地基不属于自己**：草稿协议随版本漂移已被三次实证（改名、改键、隐藏控件），把产品价值压在草稿上，等于把生死交给字节的发布节奏。
3. **PRD 的技术假设有一处硬错**：`GET_EFFECTS` 不是"当前版本剪映的合法列表"，而是库里的静态枚举快照；照原案开发，会在用户升级剪映后出现"报告说合法、剪映里没有"的信任崩塌。

**改方向的具体内容**

| 维度 | 原案 | 改为 |
|---|---|---|
| 目标人群 | 所有想仿剪的用户 | **剪辑教学者/训练营 + 中级剪辑者** |
| 核心交付 | 剪映草稿 | **逐秒拉片报告**（手法清单 + 剪映操作路径 + 截图证据）；草稿列为可选增值，后置到第 4 阶段 |
| 形态 | 桌面工具 | **CLI/Skill 先行**，桌面 GUI 在 ≥10 份付费后再说 |
| 变现 | 未定（买断） | **报告按份/按包**（先 ¥49 试水）→ 机构年框 → 软件订阅（含版本适配） |
| 版本策略 | "实时拉取合法列表" | **锁版本 + 自建特效快照 + 漂移监控**，把"持续适配"当卖点 |
| L3 GUI 核对 | 硬性门禁的关键子流程 | **可选增强**（用户点了才跑），不阻塞主链路 |

**三件套（缺一不可）**

1. **最值钱的一步**：**先卖，不先写代码。** 用 3 天人工产出 3 份拉片样张（口播/旅拍/Vlog 各一），按 ¥49/份向 5 位剪辑学习者 + 1 位剪辑课老师预售 10 份。成交与否，直接回答 C1。
2. **最便宜的验证（≤1 天）**：拿 1 条 60s 参考视频，手工标 20 个镜头 + 8 个转场 + 卡点，做成一份"样张报告"，发到 1 个剪辑学习社群，测"阅读→留资→预付"三步转化。**它验证的是"报告有人要"（C1），不是"AI 能做"（C2）**——后者是工程问题，钱能买时间；前者是生死问题，钱买不到。
3. **放弃信号（任一命中即停）**：
   - 触达 30 位目标用户，预付 **<3 份**；
   - 3 位剪辑老师都说"我们要成品，不要报告"；
   - B2 取证结果为"协议禁止第三方生成草稿/自动化"，且无本地纯报告形态可退；
   - 单条拆解云成本 **>¥5** 且用户不接受涨价。

**验证期 time-box**：**总上限 8 周**，到期必须二判（✅ 立项 / 🔧 再改 / ❌ 放弃），**不允许"永远在调精度、永远在找用户"**。

## 9. 追加：双功能拆分 + "自用降级"（2026-10-26 第二轮，产品方决策）

产品方提出两点修正，本报告据此追加，**§5 的判决主结论不变，但适用前提变了**。

### 9.1 新方案：一条流水线，两个出口

| | 功能一：拉片教学 | 功能二：复刻（特效/节奏层） |
|---|---|---|
| 输入 | 参考视频 | 参考视频 + 用户素材 |
| 出口 | `report.md`（逐秒手法清单 + 剪映操作路径 + 截图） | 剪映草稿（**占位片段** + 转场 + 特效 + 卡点标记） |
| 是否依赖草稿格式 | ❌ 不依赖 | ✅ 依赖（受 B1 制约） |
| 何时做 | **先做**（2 周可出第一版） | 功能一跑通后（+1 个 `export_draft`） |
| 风险 | 低 | 中（版本漂移） |

**关键收益**：功能二**砍掉了原 PRD 最不可控的 B3「素材映射策略」**——不再需要判断"哪个用户素材放哪个槽位"，这个语义判断交给人在剪映里做。原案 §6.1 承认"不承诺第 2.10 秒必须切"，本质就是这块解决不了；现在直接把它划出产品边界。

### 9.2 但有一条技术硬约束，会改变"只放特效"的形态

**剪映草稿里，转场必须挂在相邻的两个视频片段上**，不能独立存在。证据（② 平台官方/库官方）：

> `demo.py`：`video_segment.add_transition(TransitionType.信号故障)` —— 注释明确"**注意转场添加在'前一个'视频片段上**"。
> 来源：https://github.com/GuanYixuan/pyJianYingDraft/blob/main/demo.py

**所以"只建特效轨、不建素材轨"的草稿做不出来。** 可行解只有一个：**占位片段**（按参考节奏生成等长的黑场/纯色/彩条片段），人再把自己的素材替换上去。这不是妥协，反而正是产品方想要的"槽位"：

- 生成：`add_videos`(占位) → 每个片段 `add_transition` → `add_effects` → 打标卡点；
- 替换：库已提供 `replace_material_by_seg(track, index, new_material, source_timerange=..., handle_shrink=..., handle_extend=...)`，**专门处理"新素材比占位长/短"的伸缩**——这比原案"按比例映射"诚实得多，因为它把"素材不够"显式暴露给人，而不是悄悄缩放。
- 工程后果：功能二**不需要** add_videos 的素材映射逻辑，工程量约为原 L4 的一半。

### 9.3 必须点破的一处价值折损（反谄媚）

**去掉"素材拼接"之后，"节奏"这半个价值也基本没了。** 节奏的定义就是"哪个镜头落在哪个点上"——那正是拼接。剩下的"特效 + 转场"层，是剪映模板免费提供的，也是用户在特效面板 20 秒能点出来的。所以：

> 功能二的差异化**很薄**。薄不是问题，**前提是它是自用工具**；若按商业产品投 4 个月，薄就是致命伤。

### 9.4 "自用降级"是对战略的合法降级，但要接受三个后果

| 后果 | 说明 |
|---|---|
| **判据换了** | 从"有人付费吗"变成"每周帮我省 X 小时 / 产出 Y 条"。本报告 §2 的 SOM、§5 的获客验证**整套不再适用**——这是合法的，不是逃避。 |
| **形态该跟着换** | 自用就不该做 GUI、代码签名、支付、SaaS。**Skill + CLI，2 周出第一版**，比桌面产品快 5 倍。 |
| **不该背版本适配的债** | **锁死本机剪映版本（如 11.x），不追新。** 追新是商业产品为留存必须付的承诺；自用产品付它是纯浪费，能省掉约 60% 的长期维护。 |

### 9.5 "自己用 token 比官方便宜"——方向对，但别用"便宜"给自己发许可证

省的是**订阅费**，不是**总成本**。按机会成本 ¥12k/月折算，一周 5 小时调试 ≈ ¥700，远超 token 差价（10 条/周的分析成本约 ¥5–30）。**自建的真实收益是：能力可定制、数据不出本地、不排队、可批量**——这三条才是理由，"便宜"不是。

### 9.6 关于"抄开源竞品"

- **许可证层面可行**：`capcut-mate` 是 Apache-2.0（含 `NOTICE`），可商用、可改，**保留 LICENSE 与 NOTICE 即可**；它内部 vendored 的 `pyJianYingDraft` 同为 Apache-2.0。
- **真正的风险不是许可证，是没有 SLA**：你抄的不只是代码，还有它的维护节奏——而它自己正在跟剪映私有格式赛跑（见 §4.3）。
- **正确姿势**：`fork + 锁 commit + 自己维护关键路径`，不要 `pip install` 跟最新版。升级由你决定，不由上游决定。

### 9.7 "持续追踪官方能力"的操作化定义

不要停留在"我们可以持续追踪"。写成可执行的三件事：

1. `effect_registry_{剪映版本}.json` 记录**快照版本号 + 采集日期**（承接 §4.3 对 `GET_EFFECTS` 的修正）；
2. 维护**5 条回归样本**（口播/旅拍/Vlog/剧情/带货），每次剪映更新后跑一遍，检查：草稿能否打开、转场是否还在、特效名是否失效；
3. 官方新增能力（如"参考节奏分析"）出现时，**先把它当上游、把自己降级为"补充层"**——即产品方说的"能力补充助手"，落地形态就是：官方给结果，你给**解释与可核对证据**。这恰好是功能一的位置，也是唯一不会被官方更新抹掉的位置。

### 9.8 追加后的判决

**仍为 🔧 改方向，但改法更具体**：功能一（拉片报告）**立即做、零依赖**；功能二（占位草稿）**降级为可选插件**，且必须先接受"锁版本、不追新"。若产品方确定走**纯自用**，则 §2/§5 的商业验证与 8 周 time-box 一并作废，改用"两周能跑通一条视频"作为唯一验收标准。
