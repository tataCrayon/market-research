# 拉片报告｜30 分钟手工产出指南

> **这份指南解决一个问题**：在产品还没写一行代码之前，你能不能先卖出一份报告。
> 全程只用**剪映专业版 + 截图工具**，不装 Python、不跑模型。目标是**一条视频 30–40 分钟**，产出可直接交付的 `拉片报告.md`。
>
> 配套交付物：[拉片报告-模板.md](拉片报告-模板.md)（填这个）

---

## 0. 为什么手工版值得先做

| 理由 | 说明 |
|---|---|
| **验证需求，不验证技术** | 你卖的是"看懂 + 解释"，不是"全自动"。手工版能卖出去，才证明有人要；卖不出去，写再多代码也没用。 |
| **它是自动版的 ground truth** | 手工标的镜头/转场/卡点，就是将来 M1「重叠率 ≥70%」的**人工标注基准**——先做 5 条，后面省一次标注外包。 |
| **它逼你把"路径"写清楚** | 手工做一遍，你就知道哪些手法根本写不出剪映路径——那些不该进映射库（见 PRD 的 L2 硬依赖）。 |

---

## 1. 开工前（5 分钟）

- [ ] 参考视频已下载到本地（在线看会卡帧，且截图会带进度条）
- [ ] 剪映专业版版本号记下来：`帮助 > 关于`（报告里必须写，特效名随版本变）
- [ ] 新建项目，分辨率按参考视频（竖屏 1080×1920 / 横屏 1920×1080）
- [ ] 导入视频 → 拖到时间轴 → **右键「分离音频」**（下一步要用）
- [ ] 打开模板 `拉片报告-模板.md`，先把 front-matter 里 `source` 段填掉

> 小技巧：把时间轴缩放到"能看到整条片"的档位，后面读切点会快很多。

---

## 2. 拿切点（5 分钟，剪映自带）

**用「智能镜头分割」**，不要一帧帧看：

1. 选中时间轴上的视频片段
2. 右键 → 找「智能镜头分割」/「场景分割」（**不同版本叫法不同，以你本机为准**）
3. 等它跑完，时间轴会被自动切成 N 段 —— **这 N 段就是 §3 逐秒表的行数**

**找不到这个功能时的手动兜底**：把播放速度调到 2×，看到画面跳变就 `Ctrl+B`，一轮下来 3–5 分钟也能切完（准确性够用，因为你要的是"镜头边界"，不是逐帧精确）。

**产出**：每段的入点/出点（剪映时间轴直接读数，记到小数点后两位）。

---

## 3. 拿拍点（5 分钟，剪映自带）

**用「自动踩点」**，不要手数 BPM：

1. 选中分离出来的音频片段
2. 右键 → 「自动踩点」/「踩节拍」（通常有"踩节拍 I / II"两档，I 更密）
3. 时间轴上会出现一排节拍标记 —— **这就是 §2 的拍点网格**
4. 随便读两个相邻标记的时间差，算 BPM：`BPM = 60 ÷ 间隔秒数`

**产出**：BPM + 拍点网格 + 每个切点是否落在拍点上（`卡点 ✅/—`）。

> 注意：有些片子是**自由节奏**（无鼓点、旁白驱动），自动踩点会给出无意义的结果。这种情况 **BPM 写"无稳定节拍"**，§2 换成"叙事节点表"，别硬凑。

---

## 4. 判转场（10 分钟，最费眼的一步）

对每个切点，**放大到能看到前后各 3 帧**，用这张表判：

| 你看到的 | 判为 | 剪映里的名字 |
|---|---|---|
| 画面直接跳变，无过渡帧 | **硬切** | （无需添加） |
| 前后两个画面同时可见、逐渐交替 | **叠化** | 转场 > 基础 > 叠化 |
| 中间 1–2 帧整屏发白/过曝 | **闪白** | 转场 > 基础 > 闪白（或白场） |
| 有方向性拖影/模糊，像镜头被甩过去 | **甩入/甩出** | 转场 > 运镜 > 甩入 |
| 画面被推向/拉远后切换 | **缩放** | 转场 > 运镜 > 缩放 |
| 出现明显几何边界扫过 | **擦除** | 转场 > 基础 > 各种擦除 |

**记多长？** 叠化的时长 = "两画面同时可见"的帧数 ÷ 帧率。0.3s 和 0.5s 在观感上差很多，值得记。

**产出**：§3 表的「入转场（类型/时长）」列。**硬切也要写"硬切"，不许留空。**

---

## 5. 截图（5 分钟）

每行至少一张，命名照模板 §7.1：

```
shots/01-0.00.png      ← 第 1 镜首帧
shots/02-2.10.png      ← 第 2 镜首帧
shots/T01-a.png        ← 卡点对齐处的**时间轴**截图（证明"切在拍点上"）
shots/T01-b.png        ← 该手法的**成片效果**帧
```

**两个纪律**：
- **时间轴截图不可省**——它是"我真的对齐了"的证据，也是买家最看重的那张（他一眼能看出你是不是在瞎写）。
- **不要用原片截图冒充"效果图"**。你要证明的是"剪映里怎么点"，不是"原片长什么样"。

---

## 6. 写手法卡（5 分钟，报告的价值所在）

从 §3 里挑**出现次数最多的 3–5 个手法**，一个一张卡。写不出来的不要写：

- 写不出「剪映路径」的 → **删掉**（说明它可能不是剪映能做的，或者你没搞懂）
- 写不出「不可迁移情形」的 → **删掉**（说明你只看到了"能用"，没看到"什么时候不能用"，那买家自己也能看）

**死亡清单至少 2 条**——这是模板给不了、只有你能给的东西，也是这份报告最容易卖出去的部分。

---

## 7. 交付前自检（2 分钟，5 条）

- [ ] §3 的行数 = 实际镜头数（随机抽 3 个切点回放核对）
- [ ] 「硬切」列**无空值**
- [ ] ≥3 张手法卡，每张都有 **路径 + 参数 + 截图 + 不可迁移情形**
- [ ] 死亡清单 ≥2 条，每条写明"为什么别抄"
- [ ] 把 §1 念给一个不懂剪辑的人听，他能在 30 秒内说出"这片子大概怎么剪的"

**五条全过 = 可交付。有一条不过 = 是草稿，别卖。**

## 8. 时间预算表（目标：单条 ≤40 分钟）

| 步骤 | 预算 | 实际（第 1 次） | 实际（第 5 次） |
|---|---|---|---|
| 0 开工 | 5 min | | |
| 1 切点 | 5 min | | |
| 2 拍点 | 5 min | | |
| 3 转场 | 10 min | | |
| 4 截图 | 5 min | | |
| 5 手法卡 | 5 min | | |
| 6 自检 | 2 min | | |
| **合计** | **37 min** | | |

> 第一次做大概率超过 60 分钟——**这不是问题**，记下来，第五次再看。这个曲线决定了你未来能不能按 ¥49 卖（¥49 / 37 分钟 ≈ 时薪 ¥79，勉强；¥49 / 20 分钟 ≈ 时薪 ¥147，可做）。

## 9. 拿它去验证需求（这一步比做报告重要）

产出 3 份样张（口播 / 旅拍 / Vlog 各一），然后做这件事：

1. 找 **5 位剪辑学习者 + 1 位剪辑课老师**（社群、训练营、B 站评论区都行）；
2. 把样张发过去，**不要问"你觉得怎么样"**（那只会得到"挺好的"），问三个具体的：
   - **"这份报告，你愿意花 ¥49 买吗？"**（愿不愿意，不要问"值不值"）
   - **"你愿意为它付钱的那个点，具体是哪一段？"**（定位真实价值）
   - **"如果你不买，你会用什么替代？"**（暴露免费替代品）
3. 记录**预付**（真收钱，哪怕 ¥9.9），不接受"下次一定"。

**判据（写死在验证前，别事后改）**：
- ≥3 人预付 → C1 成立，继续；
- 1–2 人 → 改定位（换人群或换交付物），别加功能；
- 0 人 → 停，别写代码。

## 10. 这套流程 → 将来 CLI 的规格

手工每一步，对应产品的一个自动化点。做的时候顺手记下"这步最烦的是什么"，那就是优先级：

| 手工步骤 | 将来由谁做 | PRD 对应 |
|---|---|---|
| 智能镜头分割 | PySceneDetect（更可控、可批量） | L1 视觉切点 |
| 自动踩点 | librosa（BPM/onset，不必依赖剪映） | L1 音频 |
| 判转场 | TransVLM / VLM（最容易翻车，人工兜底） | L1 转场区间 |
| 写剪映路径 | 映射库 + `effect_registry_{version}.json` | L2 |
| 截图（时间轴） | 不需要自动化——**这是人工价值** | L3 核对 |

> 注意最后一行：**"时间轴截图"这一步恰恰不该自动化**。它是买家信任的来源，也是官方 AI 最难替代的部分（官方给你结果，不给你"我为什么这么判断"）。
