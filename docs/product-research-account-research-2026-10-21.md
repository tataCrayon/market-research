# 📱 产品立项调研报告：把 account-research 产品化（合规优先的 AI 对标拆解）

> 调研对象：`account-research`（小红书对标账号拆解，仓库 v0.1.4）产品化——「人保存网页 HTML（约 2 分钟/账号）→ AI 全自动处理（解析 → 四层拆解 → 封闭判决 → 双镜）→ 报告交付」。
> 方法论：app-market-research v1.1（6 步循环 + 双镜自审）。检索 12 次（预算 ≤15），其中 8 次投 PLATFORM 政策取证（≥1/3 达标）。
> 上游输入：整体流程设计（references/overall-workflow.md）、方法拷问记录（docs/grill-overall-workflow-2026-10-21.md）、可行性调研（docs/feasibility-research-2026-10-21.md）。

## 0. 端阵决策（GATE）

- **主端（先行）：Skill（AI 助手市场，如 YouMind / WorkBuddy skill 生态）**——一句理由：采集行为的产物是 HTML 文件，Skill 形态下用户「把 HTML 贴给 AI」与「保存 HTML」是同一动作的自然延伸；零基建、零备案、平台自带流量与付费体系，且**生成式 AI 服务提供者是宿主平台，备案义务不由我们承担**
- **副端（放大）：PC Web 工具**——触发条件：Skill 版验证「有人愿意为纪律付费」后（≥50 次自然安装且 ≥3 次付费）再建站；纯客户端解析（HTML 在浏览器本地解析，数据不出用户浏览器）+ 静态托管 + 大模型 API
- **延后端：微信小程序 / iOS / Android**——明文代价：采集动作（PC 浏览器保存 HTML）在移动端不成立，硬做要么违反「采集端只能是人 + 原生保存」的合规设计，要么重做一套截图/分享链接的完全不同交互（= 第二个产品）；iOS 虚拟支付抽成对工具类是重税；小程序需重新备案 + 类目审核。**「三端全做」不成立，砍到 Skill 单端起手**

## 1. 想法拆解（FRAME）

**主张 1**：有足够多的个人创作者 / 小团队愿意为「带判决的对标拆解」付费
- 若为假：需求侧塌方——最大竞争对手是「什么都不做」：把内容手动粘贴给通用 AI（人人都是产品经理方法 1，免费）已能满足约 60% 需求

**主张 2**：「人保存 HTML」的 UX（约 2 分钟/账号）目标用户能接受
- 若为假：核心流程断裂，产品只能退回人工服务形态

**主张 3**：交付物显著优于「通用 AI + 民间框架」组合
- 若为假：只是换皮（立项.md 放弃信号 ②），按仓库铁律不该产品化

**主张 4**：合规优先（零爬虫）在监管趋严下是卖点而非累赘
- 若为假：被爬虫形态竞品（Fellou / xhs-account-teardown）以省力碾压；2025 年百万级判例后此概率低，但平台规则变动是长期变量

**KPI 三级**：
- 30 天：v0.2 真实 case 跑通（真实账号 + 真实 HTML 存档 + 完整报告 + 双镜）；HTML 探针通过
- 90 天：Skill 版 ≥10 个真实用户完成一次拆解，或 ≥3 次付费安装
- 12 个月：Skill 版月收入 ≥¥3,000，或 Web 版 ≥100 份/月付费报告

**致命风险 #1 + 对冲**：免费通用 AI 替代（最大对手是「什么都不做」）。对冲：交付必须在那 40% 上做到通用 AI 做不到——封闭判决、⬜ 纪律、证据分级五件套、HTML 解析自动化（通用 AI 读不了存档结构）、双镜自审、账号库台账。

## 2. 市场（MARKET）

**TAM**：小红书月活突破 4 亿（2026 Q1 行业测算 4.2 亿，②/③-a 多源交叉）；**累计创作者超 1 亿、活跃创作者 4200 万**（2026 上海网络视听创作者大会披露，②）；2025 全年笔记发布量 120 亿篇（③-a）。自媒体从业者总盘子更大。

**SAM**（⬜ 精确比例未取证，只给量级与方法论）：以「对标拆解」为高频动作的认真运营者 = 活跃创作者 × 有拆解意识比例。参照系 sanity check：数据工具个人档（新红 200-400/月、灰豚 199-599/月）存在且存活 → 该人群真实存在且已证明愿意为数据付费（③-a）。

**SOM**：首年现实可达 500-2000 次使用。参照：YouMind 生态早期（赚美金机制 2026-05 上线），头部 Skill「讲稿转 Slides」432 次付费安装（② 平台官方博客）；普通创作者 87 天 34 个 Skill 收益 $1002（② 个人复盘，非承诺）。

**盈亏平衡 SOM**（含研发沉没，v1.1 口径）：
- 刚性成本：域名 + 静态托管 ¥100-300/年；ICP 备案免费但占日历 3-22 工作日；AI 调用约 ¥0.5-3/份；微信支付费率 0.6-1%（需个体户主体）
- 研发沉没：解析器 + 前端 + prompt 工程 ≈ 80-150 小时（一人）
- 按 ARPU ¥50/份、毛利约 70% 计，盈亏平衡 ≈ 300-600 份/年
- **结论：Skill 形态下固定成本近零，盈亏平衡轻易可达；独立 Web 站的瓶颈是获客不是成本**——这正是「Skill 先行」的量化依据

**共性缺口**（多家共有、有评论/产品证据、我们能解、非桌赌注）：① **封闭判决**（无人给「该不该抄、抄了会不会死」的结论）② **⬜ 纪律**（无人标注哪些数是编的）③ **结构化数据自动化**（都在让用户手动粘贴，没人解析 HTML 存档）④ **合规采集路径**（竞品要么爬虫要么手抄）。

**楔子**：`唯一把「对标账号拆解」做成有封闭判决、有证据分级、有 ⬜ 纪律、有双镜自审的 AI 产品`

- 测试 ③ 做得出来吗——方法论已在仓库（v0.1.4 + 整体流程 + 数据手册），缺的只是产品化工程（解析器）与 case

## 5. 判决（VERDICT）

### 🔧 改方向

**一句话理由**：想法成立（需求真实、合规站得住、缺口明确），但「独立 Web 产品先行」是用最高成本验证最不确定的主张——**先以 Skill 形态完成 v0.2 验证，Web 站作为放大路径**。端从「PC Web 先行」改为「Skill 先行、Web 放大」。

**三件套**：

1. **最值钱的一步**：跑 v0.2 真实 case——5 分钟 HTML 探针（验证「列表页 HTML 内嵌数据」前提）+ 一个真实关注的小红书对标账号完整 9 步 + 双镜。它一次撞掉主张 2（UX 可接受）与主张 3（优于通用 AI），是全局最大不确定性的消除点
2. **最便宜的验证（≤1 天）**：把 v0.2 case 报告脱敏后发 3-5 个目标用户聚集处（小红书运营社群 / 即刻），直接问「这份报告你愿意付多少钱」——验证主张 1（付费意愿）。回复数即答案，不需要灰度不需要 AB
3. **放弃信号**（任一出现即停手，**总验证期 ≤8-10 周，到期必须二判**）：
   - v0.2 case 的 ⬜ 密度阻塞定位/选题关键层（立项放弃信号 ①：公开数据撑不起结论）
   - 拆解结论与「通用 AI + 民间框架」零差异（放弃信号 ②：只是换皮）
   - Skill 版自然安装 <50 次且 0 付费 → 降级为纯方法论归档，不再产品化
